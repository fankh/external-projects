# SEEKERSLAB ITAM — AI 기반 IT 자산관리 플랫폼

`AI기반_IT자산관리시스템_제품안내서.pdf`(v1.0, 2026.07)를 구현 스코프로 한 웹 플랫폼.
자산 수명주기 관리 · Shadow IT Discovery · AI 자산 인텔리전스를 단일 플랫폼에서 다룬다 —
"발견되지 않은 자산을 찾아 대장에 편입시키는 것까지"가 관리 범위.

제품안내서가 정의한 **8대 업무 도메인의 명시 화면 30종**이 모두 구현되어 있다.

## 실행

```powershell
cd itam-web
npm install
npm run dev        # http://localhost:3000
```

로그인 화면에서 권한그룹별 목업 계정(SSO 대체) 4종 중 선택:
**사용자**(김민준) · **자산담당**(박자산) · **보안담당**(윤보안) · **Admin**(시스템관리자).
권한그룹에 따라 메뉴바·좌측 내비와 화면 내 기능(편입·격리·결재·정책 변경)이 다르게 노출되며,
모든 제한 화면은 `lib/authz.ts`의 서버사이드 가드로 직접 URL 진입도 차단한다.

## 테스트

```powershell
npm run build
npm run smoke      # 프로덕션 서버 기동 → 231개 검증 → 종료
```

배포 후에는 **같은 스위트를 배포본에 한 번 더** 돌린다 — 로컬에서 통과해도 배포본에서만
틀리는 결함이 실재한다(컨테이너 TZ 가 UTC 라 KST 00~09시에 날짜가 하루 뒤처지던 건).

```powershell
ssh -f -N -L 3390:127.0.0.1:3390 <host>
$env:SMOKE_BASE="http://localhost:3390"; node scripts/smoke.mjs
```

원격 대상일 때는 로컬 서버를 띄우지 않고, 문서 정합성 검사(로컬 소스 기준)는 건너뛴다.

`scripts/smoke.mjs`가 인증 리다이렉트, 라우트 × 권한그룹 접근 매트릭스(30 라우트 × 4 권한),
자산 대장 데이터 스코핑(사용자=본인 자산만), 주요 화면 콘텐츠 렌더를 검증한다.
**라우트(화면) 권한**을 바꿀 때는 **세 곳**을 함께 갱신해야 한다 — `lib/authz.ts`의 `requireRole`,
`components/chrome/menus.ts`의 `roles`, `scripts/smoke.mjs`의 `ROUTES`.
**기능(버튼) 권한**은 코드가 아니라 스토어의 권한 매트릭스가 원천이며, 환경설정 › 권한·정책에서
편집하면 서버가 즉시 강제한다 (`lib/perm.ts`).

## 아키텍처

edim-ai-blueprint(`edim-web-next`)의 구조를 계승하되 현대화:

```
Next.js 15 App Router + React 19 + TS (UI 라이브러리 없음, qrcode 만 사용)
├─ app/globals.css            디자인 시스템 — 제품안내서 비주얼 랭귀지의 모던-덴스판
│                             (다크 네이비 · 로열 블루 · 자간 넓은 키커 · KPI 스탯 · 인쇄/모바일)
├─ app/login                  SSO 목업 — 권한그룹별 계정 선택
├─ app/(app)/layout.tsx       셸(AppShell) — edim AppChrome 계승: 타이틀바 · 모듈 메뉴바(LV1)
│                             · MDI 탭(방문 화면, localStorage 유지) · 모듈 좌측 내비(LV2) · 상태바
├─ app/(app)/<domain>/<screen>/
│    page.tsx                 서버 컴포넌트 — 스토어 조회 + 권한 가드/스코핑
│    actions.ts               서버 액션 — 편입·격리·결재·스캔·정책 변경 등 상태 변경
│    *View.tsx                클라이언트 컴포넌트 — 그리드·필터·상세 패널
├─ app/api/reports/[id]       결재 첨부용 리포트 다운로드 (CSV · Markdown, 권한 가드 포함)
├─ app/api/export/[kind]      엑셀(.xlsx) 내보내기 — 권한 매트릭스의 '엑셀' 기능 단위 통제
├─ components/chrome          AppShell(메뉴바·MDI 탭·모듈 내비) · menus(권한 매핑)
├─ components/ui.tsx          ScreenHeader · Card · Stat · Chip
└─ lib/                       types(도메인 모델) · store(인메모리 시드) · session(쿠키)
```

실서비스에서는 자산 대장 RDB(CMDB)와 발견 저장소 분리 구조(제품안내서 §02)로 대체.

## 동작하는 폐쇄 루프

화면이 서로 연결되어 있어, 한 화면의 판정이 다른 화면의 상태를 실제로 바꾼다.

1. **발견 → 편입** — Discovery 발견 자산 편입 요청 → 결재 승인 → 자산 대장 등록
   (최초 발견 채널·일시가 자산 이력에 승계, 메뉴 뱃지 감소)
2. **발견 → 격리** — 격리 요청 → 보안담당 결재 → NAC 격리 조치 상태 반영
3. **입고 → 대장** — 검수 체크리스트 완료 → 자산번호 채번 → 대장 검수중 등록 + 라벨 발행
4. **실사 → 대장 보정** — 스캔 차이(위치·상태·미등록) → 조정 결재 → 대장 자동 보정 + 이력 기록
5. **폐기 → 증적** — 대상 선정 → 결재 → 데이터 소거 방식 기록 → 확인서 번호가 자산 이력에 영구 보존
6. **정책 → 운영** — SaaS 카탈로그(또는 Shadow SaaS 화면)에서 인가/차단 판정 → Shadow SaaS
   미인가 집계에서 제외 (두 화면이 같은 카탈로그를 본다) / 탐지 채널 중지 → 상태바 커넥터 수(6/6→5/6) 즉시 반영
7. **문의 → 답변** — 사용자 QnA 등록 → 담당자 답변 → 상태 전환 + 감사 로그
8. **대사 미확인 → 재물조사** — CMDB 대사에서 **미확인(유령 자산)** 판정 → 수시 조사 회차로
   자동 편성(기한 +14일) → 조사 개시 → 실사 화면에서 실물 확인. 이미 편성된 자산은 재편성되지 않는다
9. **신청 → 결재 → 불출** — 사용자가 자산 신청 상신 → 결재 승인 → 자산담당이 유휴 재고를 배정해
   불출 처리 → 대장의 소유자·부서·위치가 갱신되고 `불출` 이력이 남는다. **승인만으로는 실물이 움직이지 않는다**
10. **반납 → 점검 → 유휴 풀** — 반납 결재 승인 시 `반납대기` → 회수·상태 점검(정상/수리 필요/폐기 권고) →
    정상·수리는 유휴 풀로, 폐기 권고는 유휴를 건너뛰고 `폐기예정`으로. 유휴 풀은 다시 불출 처리의 배정 재고가 된다
11. **AI 제안 → 판정 → 조치 → 환류** — 제안을 승인하면 조치로 이어지고(이상탐지 승인 → 격리 요청 자동 상신),
    반려는 **사유 입력이 필수**라 오탐 유형이 재학습 신호로 남는다. 판정 누적이 기능별 채택률로 집계된다
12. **소유자 확인 → 응답 → 에스컬레이션** — 확인 요청 시 부서 앞 메일 발송(발송 이력 적재) →
    해당 부서 사용자가 직접 응답 → 기한(7일) 무응답 건은 격리 요청으로 자동 에스컬레이션
13. **만료 임박 → 알림 발송** — 계약·라이선스·보증(부서 단위 묶음)을 한 번에 훑어 주관부서 앞으로
    통지하고 발송 이력을 남긴다. 같은 날 같은 대상에는 재발송하지 않는다 (알림 피로가 알림을 무력화한다)
14. **라이선스 검출 → 조치** — 초과 사용은 추가 구매 품의, 미사용 보유는 회수로 이어지며 둘 다
    결재를 거친다 (컴플라이언스 4단계의 마지막 — 그동안 검출까지만 있었다)
15. **스캔 실행 → 관측 → 발견** — 채널을 골라 스캔하면 관측이 쌓이고, 아는 장비는 재관측으로
    생존 확인(미확인 상태는 되돌아감), 모르는 장비는 신규 발견으로 드러난다. 능동 스캔은 정책 시간대
    밖이면 사유가 필요하고 강도 **높음**은 아예 차단된다 — 실행 사유는 이력·감사 로그에 남는다
16. **외부 재탐지 → 노출 확인** — 도메인별 주기로 재탐지하며, **수동 수집**은 대상 무접촉으로 후보만 넓히고
    생존·서비스·CVE 는 **능동 확인**에서만 채워진다. 능동 탐지는 사전 협의된 도메인에서만 실행된다
17. **스케줄 → 리포트 자동 생성 → 배포** — 주간/월간 스케줄의 기한이 도래하면 예약 실행으로
    리포트를 만들고 수신자에게 배포한다. 중지된 스케줄은 기한이 지나도 돌지 않고, 밀린 스케줄은
    **기한 도래**로 드러난다. 배포 사실은 발송 이력에 남아 그 자체가 증적이 된다
18. **원시 관측 → 지문 병합** — 6채널이 각자 본 관측을 지문(MAC→호스트명→IP)으로 합쳐 발견 목록을
    만든다. 병합 자산은 어느 채널로 필터해도 잡히고, 지문이 갈린 중복 후보는 수동 병합으로 관측을 승계한다
19. **권한그룹 배정 → 결재선 거버넌스** — 사용자·그룹(STEP 4)에서 사용자의 권한그룹을 바꾸면 STEP 3
    매트릭스가 그 그룹 단위로 적용된다. 본인·마지막 관리자는 강등이 막혀 관리 화면이 잠기지 않고,
    폐기·격리·편입·차이 조정 결재선은 필수로 고정돼 선택으로 내릴 수 없다. 모든 변경은 감사 로그에 남는다
20. **공통코드 등록 → 전 화면 반영** — 공통코드에 값을 추가하면(위치·자산 유형 등) 그 값을 참조하는
    전 화면 드롭다운(재물조사 대상 범위·이동 목적지 등)에 즉시 선택지로 나타난다. 코드 삭제는 없고
    미사용 전환만 있어 기존 자산·이력이 참조하는 코드의 무결성이 보존된다
21. **구성변경 기록 → 대장·이력 반영** — 자산 대장 상세에서 사양 변경(메모리 증설·OS 재설치 등)을
    기록하면 대장의 해당 사양 필드가 갱신되고 변경 이력 타임라인에 `구성변경` 이벤트가 남는다.
    코드 자체는 참조 무결성 때문에 불변이며, 등록·이동·구성변경·점검·폐기가 한 화면에서 추적된다
22. **커넥터 연결 테스트 → 상태·감사 반영** — 연동·인프라에서 지연·오류·미연동 커넥터를 재연동하면
    상태가 정상으로, 최근 수집 시각이 현재로 갱신되고 그 사실이 같은 화면의 감사 로그에 남는다.
    커넥터 관리는 보안담당·Admin 만 가능하고 자산담당은 조회만 한다

라벨(QR·Code128)로 발행한 코드는 재물조사 스캔 실사에서 그대로 인식되어 3↔4가 연결된다.

## 권한 모델

**화면 단위**는 코드(`lib/authz.ts`)가, **기능 단위**는 스토어의 권한 매트릭스가 통제한다.
매트릭스는 환경설정 › 권한·정책에서 칸을 클릭해 편집하며, 서버가 즉시 강제한다.

- 서버가 직접 강제하는 칸(화면에 밑줄): 자산 대장·재고·계약·발견 자산·결재의 **엑셀**,
  발견 자산의 **편입 / 격리요청**, 신청·결재의 **결재**
- 매트릭스는 **필요조건**이다 — 권한을 켜도 코드 규칙(결재 종류별 담당자, 본인 자산 범위)을
  넘지 못한다. 편집으로 권한이 상승하는 경로를 만들지 않기 위한 제약
- Admin 의 `권한 · 정책 × 조회/저장`은 잠겨 있어 스스로를 화면 밖으로 밀어낼 수 없다
- 모든 변경은 감사 로그에 남는다

## 엑셀 내보내기

권한 매트릭스의 **엑셀** 기능이 있는 화면에서 `.xlsx`로 내려받는다 (`/api/export/<kind>`).

| 대상 | 시트 | 허용 권한그룹 |
|---|---|---|
| `assets` 자산 대장 | 자산 대장 (18열) | 자산담당 · 보안담당 · Admin |
| `stock` 재고 현황 | 유형별 · 부서별 · 위치별 | 자산담당 · Admin |
| `discovered` 발견 자산 | 발견 자산 · 채널별 관측 | 자산담당 · 보안담당 · Admin |
| `contracts` 계약·라이선스 | 계약 · SW 라이선스 | 자산담당 · 보안담당 · Admin |
| `approvals` 결재 이력 | 결재 이력 | 자산담당 · 보안담당 · Admin |

버튼 숨김은 UI 정리일 뿐이며, **서버 라우트가 같은 규칙으로 403을 반환**한다.
내보내기 데이터는 화면과 동일한 권한 필터를 통과하고, 반출 사실은 감사 로그에 남는다.
`.xlsx` 는 의존성 없이 `lib/xlsx.ts`가 직접 생성한다(ZIP 저장 + OOXML 4파트) — CSV 로 열 때
생기는 선행 0 손실·MAC 주소의 날짜 변환·지수 표기를 피하기 위해 식별자는 문자열 셀로 넣는다.

## 데모 시나리오

1. **자산담당(박자산)** — Discovery › 발견 자산에서 미등록 자산 **편입 요청** →
   워크플로에서 **승인** → 자산 대장에 신규 자산 편입 확인
2. **자산담당** — 도입·검수에서 체크리스트 완료 → **채번** → 라벨 발행(인쇄) →
   재물조사 수행에서 그 자산번호를 스캔해 **일치** 확인
3. **자산담당** — 재물조사에서 다른 위치로 스캔 → 차이 발생 → **조정 결재 상신** →
   **Admin** 승인 → 자산 대장 위치가 실사값으로 보정됨
4. **Admin** — 환경설정 › SaaS 카탈로그에서 Notion **인가** → Discovery › Shadow SaaS에서
   미인가 집계가 줄어드는 것 확인
5. **사용자(김민준)** — QnA 질문 등록(답변창 없음) → **자산담당**이 답변 → 사용자 화면에서 답변 확인
6. **자산담당** — 재물조사 계획에서 범위·담당자·기한을 지정해 회차 등록(대상 모수는 대장에서 자동 산출) →
   **조사 개시** → 실사 화면으로 이동. Discovery › CMDB 대사의 **미확인**행에서 **조사 편성**으로도 진입 가능

## 배포

```powershell
docker build -t itam-web .
docker run -d --name itam-web --restart unless-stopped -p 127.0.0.1:3390:3390 \
  --env-file ~/.itam.env itam-web:latest
```

로컬호스트 바인딩이므로 접속은 SSH 터널을 사용한다 (`ssh -L 3390:localhost:3390 <host>`).
`--env-file`은 컨테이너 재생성 시에만 다시 읽히므로, 키를 바꾸면 `docker restart`가 아니라
`docker rm -f` 후 `docker run`으로 재기동해야 한다.
