## 3. 설계에서 지킨 원칙

**승인 ≠ 집행.** 반납 결재는 `반납대기` 까지만 간다. 실물 회수·상태 점검을 거쳐야 유휴가 된다.
불출·이동도 승인 후 별도 집행 단계를 둬 *"승인은 났는데 실물이 안 움직인 상태"* 가 대기열로
드러나게 했다. 시드에 실제로 그런 건이 있었고(`APR-2607-101`, 07-16 승인·미집행), 그것이 나중에
재물조사에서 위치 불일치로 잡히는 자산이다.

**권한 편집은 회수만 가능하게.** 매트릭스는 **필요조건**이다. 끄면 실제로 막히고(API 직접 호출도
403), 켜도 코드 규칙(결재 종류별 담당자, 본인 자산 범위)을 넘지 못한다. 편집으로 권한이 상승하는
경로 자체를 만들지 않았다. Admin 의 권한 화면 접근은 잠가 자기 잠금을 불가능하게 했다.

**수동 우선, 능동 확인을 데이터로 강제.** 외부 재탐지에서 수동 수집은 후보만 넓히고 `alive=false`
로 남긴다. 생존·서비스·CVE 는 능동 확인에서만 채워진다 — 대상에 접속하지 않고 알 수 없는 것을
아는 척하지 않는다. 능동 탐지는 사전 협의된 도메인에서만 실행된다.

**검출에서 끝내지 않기.** 라이선스 컴플라이언스가 3단계(검출)에서 멈춰 있었고, AI 제안이 판정 없이
쌓이기만 했고, 대사 `미확인` 이 문구로만 존재했다. 각각 결재·조치·재물조사 편성으로 연결했다.

**알림은 묶어서, 중복 없이.** 보증 만료는 자산마다 보내면 아무도 읽지 않으므로 부서 단위로 묶고,
같은 날 같은 대상에는 재발송하지 않는다. 알림 피로가 알림을 무력화한다.

**의존성 없이.** `.xlsx` 는 `lib/xlsx.ts` 가 직접 생성한다(ZIP 저장 + OOXML 4파트). `lib/label.ts`
가 Code128 을 직접 인코딩하는 방침과 같다. CSV 로 열면 `SN-000112` 의 선행 0 이 날아가고 MAC 이
날짜로 바뀌므로 식별자는 문자열 셀로 넣는다.

## 4. 테스트가 잡아낸 결함

실제 UI 를 브라우저로 조작했기에 나온 것들이다.

- **병합 성공 메시지가 사라짐** — 후보 카드 안에 렌더링해서, 마지막 후보를 병합하면 카드와 함께
  확인 메시지도 증발했다
- **채널별 마지막 수집 시각이 거짓** — 자산당 관측 1건만 대표 채널에 기록해, 방금 돈 DNS 채널이
  `07-28` 로 표시됐다. 채널별 수집 현황 화면의 존재 이유를 무너뜨리는 버그
- **리포트 유형 부제 합 불일치** — 중지된 스케줄이 어디에도 계상되지 않았다
- **시드 정합성 3건** — 소유자 확인 결재만 있고 발견 자산 상태는 비어 있음 / 승인 상태인데 판정자
  없음 / 이동 결재가 공통코드에 없는 `9F` 를 문자열로만 참조

### 테스트 자체의 버그 — 단정을 약화시키지 않고 테스트를 고쳤다

- React SSR 이 `{n}일` 을 `7<!-- -->일` 로 쪼갬 (3회 반복) → `text()` 헬퍼 추가
- 결재 목록 기본 탭이 `대기` 라 승인된 건이 빠짐 → 탭 전환 후 검증
- 방치된 테스트 서버가 3378 을 잡고 있어 스모크가 오염된 스토어에 접속 (2회) → 매번 선점 종료
