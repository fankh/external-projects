# 배포·운영 가이드

고객사 온프레미스에 포털을 배포·운영하는 운영자용 런북이다. 어댑터 구현·프로필 작성 같은
개발 작업은 [`docs/어댑터_연동_가이드.md`](어댑터_연동_가이드.md)를, 코드 구조는
[`docs/구축_요약.md`](구축_요약.md)를 본다.

배포 형상은 단일 애플리케이션 컨테이너(내부 3400 포트) 앞에 nginx 리버스 프록시를 두는
구성이다(`deploy/docker-compose.yml`). 데이터는 `/data` 볼륨에 파일로 영속화한다.

---

## 1. 사전 준비

1. **세션 서명 키 생성** — 세션 쿠키 위조를 막는 필수 비밀값. 배포마다 랜덤으로 새로 만든다.
   ```bash
   openssl rand -base64 32
   ```
   미설정·빈값이면 소스의 개발용 기본 키로 동작해 세션 위조가 가능하다. 기동 훅
   (`instrumentation.ts`)이 프로덕션에서 미설정을 감지하면 경고를 남긴다.
2. **고객사 프로필 결정** — `default`(데모)·`manufacturer`·`public` 또는 신규 프로필 중 하나.
   신규 고객사는 [`docs/어댑터_연동_가이드.md`](어댑터_연동_가이드.md) 절차로 프로필·어댑터를 먼저 붙인다.
3. **HTTPS 종단 여부 결정** — 실서비스는 nginx에 TLS를 얹고 `PORTAL_COOKIE_SECURE=1`을 켠다(6절).

---

## 2. 환경변수

| 변수 | 필수 | 용도 | 기본 |
|------|:---:|------|------|
| `SESSION_SECRET` | ● | 세션 쿠키 HMAC 서명 키 | 개발키(경고) |
| `PORTAL_PROFILE` | | 고객사 프로필 선택 | `default` |
| `PORTAL_DATA_FILE` | | 파일 영속화 경로 | Docker=`/data/portal-data.json` |
| `PORTAL_COOKIE_SECURE` | | HTTPS 종단이면 `1` | `0` |
| `PORTAL_NOTIFY_INTERVAL_MS` | | 알림 배치 주기(ms) | Docker=`86400000`(24h) |
| `PORTAL_ADAPTER_TIMEOUT_MS` | | 어댑터 호출 상한(ms) | `10000` |

전체 설명은 [`.env.example`](../.env.example)에 있다. 컨테이너 기본값(데이터 경로·배치 주기)은
`Dockerfile`이 이미 설정하므로, 운영자는 보통 `SESSION_SECRET`과 `PORTAL_PROFILE`,
HTTPS면 `PORTAL_COOKIE_SECURE`만 주입한다.

---

## 3. 배포

`deploy/docker-compose.yml`은 포털 + nginx를 함께 띄운다. `SESSION_SECRET`은 필수라 미설정 시
기동이 거부된다.

```bash
export SESSION_SECRET=$(openssl rand -base64 32)
export PORTAL_PROFILE=manufacturer          # 고객사 프로필
export PORTAL_COOKIE_SECURE=1               # HTTPS 종단일 때
cd portal-web && docker compose -f deploy/docker-compose.yml up -d --build
```

포털은 비루트(`node`)로 실행되고, 쓰기 경로(`/data`·`.next`)만 소유한다(최소 권한). 외부
노출은 nginx(80)만 담당하고 포털 3400 포트는 컨테이너 내부에만 열린다.

---

## 4. HTTPS·TLS

기본 `deploy/nginx.conf`는 HTTP 프록시 예시다. 실서비스는 nginx에 인증서를 얹어 443을
종단하고, 포털에 `PORTAL_COOKIE_SECURE=1`을 준다 — 세션 쿠키에 `Secure` 속성이 붙어
평문 구간으로 전송되지 않는다. 쿠키는 이미 `HttpOnly`·`SameSite=Lax`다.

---

## 5. 데이터 영속화·백업·복구

- **영속화** — 스토어는 `/data/portal-data.json`에 저장돼 재시작·재생성 후에도 유지된다.
  `/data`를 도커 볼륨(`portal-data`)으로 마운트하는 것이 compose 기본값이다. 저장은
  임시파일→rename으로 부분 쓰기를 막고, 손상된 파일은 기동 시 시드로 폴백해 화면이 깨지지
  않는다(타입 안전 머지).
- **백업** — 알림 스케줄러 틱마다 일자별 스냅샷(`portal-data.json.YYYY-MM-DD.bak`, 보존 7개)이
  같은 볼륨에 남는다. `tmp→rename`이 못 막는 논리적 손상(잘못된 상태가 그대로 저장된 경우)의
  복구 지점이다.
- **복구** — 컨테이너를 멈추고 원하는 일자의 스냅샷을 원본 자리에 복사한 뒤 재기동한다
  (기동 시 파일을 다시 읽는다).
  ```powershell
  docker stop ngv-portal
  docker run --rm -v portal-data:/data alpine `
    cp /data/portal-data.json.2026-08-03.bak /data/portal-data.json
  docker start ngv-portal
  ```

---

## 6. 헬스체크·모니터링

- **컨테이너 헬스체크** — `Dockerfile`의 `HEALTHCHECK`가 30초 간격으로 로그인 화면(`/login`)을
  프로브한다. 오케스트레이터(docker·compose)가 기동 실패·행업을 자동 감지한다.
- **배포 준비 상태 카드** — 연동·인프라 화면(ADMIN)에서 세션 키·영속화·스케줄러·HTTPS 쿠키·
  프로필 상태를 한눈에 확인한다. 세션 키가 개발키면 여기서 경고로 드러난다.
- **어댑터 계약 자가진단** — 같은 화면에서 전 프로필·채널의 바인딩·계약 적합성을 표시한다.
  고객사 어댑터 투입 후 위반이 0인지 확인한다.

---

## 7. 배포 전 검증

이미지 빌드 전 저장소에서 게이트 스위트를 통과시킨다. 6단계(빌드·스모크·접근성·데이터
견고성·세션 격리·헬스·e2e)가 회귀를 막는다.

```bash
npm run gates
```

새 고객사 프로필로 배포하면 그 프로필로도 돌린다.

```bash
PORTAL_PROFILE=<고객사> npm run gates
```

---

## 8. 업그레이드·롤백

- **업그레이드** — 새 이미지를 빌드해 재기동한다. 데이터 볼륨(`portal-data`)은 그대로 유지되어
  상태가 보존된다.
  ```bash
  cd portal-web && docker compose -f deploy/docker-compose.yml up -d --build
  ```
- **롤백** — 애플리케이션은 이전 이미지 태그로 되돌리고, 데이터에 문제가 있으면 5절의 백업
  스냅샷으로 되돌린다. 데이터 볼륨과 애플리케이션 이미지는 독립적이라 각각 롤백할 수 있다.
