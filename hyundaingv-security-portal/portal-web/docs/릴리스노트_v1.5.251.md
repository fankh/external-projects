# 릴리스 노트 — portal-web v1.5.251

계획대비실적(투자·비용) 표의 **집행률 초과(err) 톤**을 반올림 집행률이 아닌 **원값(집행액>계획액)**으로
판정하도록 바로잡았다. 반올림 경계에서 실제 초과인 과제가 초과색(빨강)을 놓치던 오분류를 없앤다.

## 배경 — 발견 경위

방어적 계산 계층 감사(반올림 경계 오분류 클래스, itam-web pass5 와 동형)에서 발견. 계획대비실적 표의 집행률
칩은 `tone={rate > 100 ? 'err' : rate >= 90 ? 'warn' : 'neutral'}` 로, 여기서 `rate = Math.round((집행/계획)*100)`
이다. 집행액이 계획액을 0.5% 미만 초과하면(예: 집행 1,004 / 계획 1,000 = 100.4%) rate 가 100 으로 내려앉아
`100 > 100` 이 거짓 → 실제 초과인데 초과(err) 톤 대신 접근경고(warn) 톤으로 표기됐다. 계획대비실적 표에는
계약 섹션과 달리 별도 '초과' 칩이 없어 **이 집행률 칩 색이 유일한 초과 시각신호**라 오분류가 그대로 드러났다.

반올림 비율을 원값 비교의 대용으로 쓴 안티패턴으로, fankh 가 itam-web pass5 에서 고친 부류
(`Math.round(rate) < 임계` → 원값 비교)와 동일하다. 포털의 다른 초과 판정(KPI '계획 대비 집행률' 톤은
`fin.paidConfirmed > fin.planTotal`, 계약 초과칩은 합계 원값)은 이미 원값 비교라, 이 표만 반올림 비율을
써 불일치했다.

## 주요 변경
- `app/(app)/finance/invest/page.tsx`·`app/(app)/finance/expense/page.tsx`: 계획대비실적 집행률 칩의
  초과(err) 판정을 `rate > 100` → `paid > p.amount`(원값)로 교체. 표시 %(반올림)와 `>=90` 접근경고(warn)는
  표시용 소프트 임계라 반올림 유지 — 톤의 **초과 경계만** 원값으로 정밀화(KPI·계약 초과칩과 동일 산식).

## 호환성·영향
- 무회귀: 표시되는 집행률 %와 `>=90` warn 은 불변. 달라지는 것은 집행액이 계획액을 실제 초과하는데 반올림으로
  100 이하로 보이던 경계 과제의 톤(warn→err)뿐 — 이는 교정이다. 정확히 100.0%(집행==계획)는 초과 아님 →
  기존대로 warn.
- 두 화면(투자·비용) 동형 처리로 일관성 유지.

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt · keycheck · health · **e2e 96**(신규 시나리오 sc_exec_over_budget_tone).
- `sc_exec_over_budget_tone`: 격리 픽스처(집행 1,004 / 계획 1,000 = 100.4%)로 계획대비실적 집행률 칩이
  초과(err) 톤임을 단언(class 검사). 초과 판정을 `rate > 100` 로 되돌리고 재빌드 시 칩이 warn 으로 내려앉아
  단언 실패함을 실측 대조(fails-without-fix).
