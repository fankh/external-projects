# 릴리스 노트 — portal-web v1.5.219

SR 상태 라벨 표시의 단일 원천 정합 결함을 수정했다. 데이터·계정/권한 SR은 개발 단계가 없어 '개발중' 상태를
'처리중'으로 표기해야 하는데(단일 원천 헬퍼 `srStatusLabel`), CI SR 관리의 '배정 완료' 카드와 지연내역
화면이 이 헬퍼를 거치지 않고 raw 상태('개발중')를 그대로 노출하고 있었다.

## 배경 — 발견 경위

계정/권한 SR(요구사항: 권한 부여·삭제, 계정 초기화·잠금해제)의 e2e 커버리지 부재를 정찰하던 중 발견했다.
`app/(app)/sr/chips.ts`의 `srStatusLabel`은 "데이터·계정/권한 SR은 개발 단계가 없다 — '개발중'을 '처리중'으로
표기한다"는 규칙의 단일 원천이고, 대시보드·검색·SR관리·신청내역 화면은 이를 쓴다. 그러나:
- `sr/ci` '배정 완료 — 진행중' 카드(page.tsx:228)와
- `sr/delayed` 지연내역 표(page.tsx:57)

두 곳이 `{r.status}`(raw)를 렌더해, 배정된 데이터·계정권한 SR이 이 화면들에서만 '개발중'으로 표기됐다 —
같은 SR이 SR관리 화면에선 '처리중', 이 두 화면에선 '개발중'으로 보이는 화면 간 불일치(개발 단계 없는
유형에 '개발중' 라벨은 오표기).

## 주요 변경
- `sr/ci/page.tsx`·`sr/delayed/page.tsx`: 상태 칩을 `{r.status}` → `{srStatusLabel(r)}`로 교체(import 추가).
  이제 전 SR 표시 화면(대시보드·검색·관리·신청내역·배정완료·지연내역)이 상태 라벨을 단일 원천으로 공유한다.

## 호환성·영향
- 무회귀: 표시 라벨만 정합. 시스템개발 SR은 '개발중' 그대로(srStatusLabel 이 kind로 분기), 상태 저장·전이
  로직 불변. 칩 색(SR_CHIP)도 raw 상태 기준 유지.

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt · keycheck · health · **e2e 87**.
- e2e `sc_sr_status_label`: 격리 데이터의 계정/권한 SR(개발중·CI배정·기한경과)이 배정완료(sr/ci)·지연내역
  (sr/delayed)에서 '처리중'으로 표기되고 '개발중'이 아님을 검증. 두 화면 모두 수정 전(raw 상태)엔 '개발중'
  노출로 실패함을 대조 확인(테스트 유효성). 이 시나리오는 그간 무커버리지였던 계정/권한 SR 유형과
  srStatusLabel 표시 로직을 함께 처음으로 검증한다.
