# 릴리스 노트 — portal-web v1.5.202

이 릴리스는 월별 장애 통계의 **무효월 중복 집계 결함**을 막는다(손상 데이터 내성 강화). 손상·누락된
`occurredAt`(빈 문자열)이 있으면 `slice(0,7)`가 `''`가 되고, `startsWith('')`가 모든 장애에 참이라 `''`
라벨의 월 행이 **전체 장애를 통째로 중복 집계**했다. 4차 정찰이 지목한, v1.5.10의 월별 통계(feature)에 남아
있던 잠재 취약점이다.

## 주요 변경

### 월별 장애 통계 무효월 방어
`lib/infra.ts` `monthlyIncidentStats` 가 월 버킷을 만들 때 유효한 `YYYY-MM` 형식만 남긴다
(`/^\d{4}-\d{2}$/` 필터). `''`(빈 occurredAt)·부분값(`'2026'`) 같은 무효월을 버킷에서 제외해,
`startsWith` 전건/과대 매칭으로 무날짜 장애가 통계를 부풀리는 것을 차단한다. 유효 날짜의 장애는 그대로
해당 월에 집계되고, 날짜가 손상된 장애만 어느 월에도 산입되지 않는다(무효 데이터는 제외가 정답).

**결함 경로.** `occurredAt=''` 인 장애 → 월 집합에 `''` 포함 → `incidents.filter(i => String(i.occurredAt).startsWith(''))`
는 전건 참 → `''` 월 행의 계가 전체 장애 수와 같아져, 화면 통계표·`incident-stats` export 가 이중 집계로 왜곡됐다.

## 호환성·영향
- 무회귀: 정상(유효 날짜) 장애 집계는 불변. 손상/누락 날짜 장애만 통계에서 제외한다. 저장 스키마 변경 없음.
- 손상 파일 내성 강화: 코드베이스의 corruptfile 방어(빈/손상 스토어 38/38 무크래시) 규율과 정합 — 크래시는
  안 났으나 무날짜 데이터가 통계를 왜곡하던 사각을 닫는다.

## 검증
- 게이트 전량 그린: build · smoke 586 · a11y 698 · emptystate/corrupt 38 · keycheck 3 · health 48 · e2e 79.
- e2e `sc_incident_stats_empty_month`: 8월 2건 + 무날짜(`occurredAt ''`) 1건을 주입한 데이터 파일로 기동 →
  `incident-stats` export 에 빈-발생월 행이 없고 `2026-08` 계=2(무날짜 건 제외)임을 검증. 수정 전 코드에선
  이 시나리오가 **실패**함을 대조 확인(빈 월 행이 3건을 중복 집계)해 테스트 유효성을 보증했다.
