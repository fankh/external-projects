# 릴리스 노트 — portal-web v1.5.186

이 릴리스는 QnA 를 **폐쇄 루프**로 만든다. 지금까지 QnA 는 포털의 모든 상호작용 워크플로 중 유일하게 닫힌
루프가 없었다 — 담당을 지정해도 할일이 생기지 않았고, 미답변 문의를 알리는 일배치도 없었다. 담당자가 게시판을
다시 열어보지 않으면 잊힌 문의는 아무 곳에도 드러나지 않았다. 이제 SR·서약·교육·재택처럼 담당 지정→할일→
답변→마감으로 이어지고, 미답변은 일배치가 안내한다. 전 게이트가 그린이다.

## 주요 변경

### QnA 폐쇄 루프 (할일)
- **담당 지정 시** 담당자의 나의 할일에 `QA-.. 답변` 할일을 생성한다(재지정이면 이전 담당 할일을 닫고 새로
  발급). 나의 할일 '바로가기'는 문의 화면(`/board/qna`)으로 연결된다(KIND_HREF `답변하기`).
- **답변 완료 시** 해당 문의의 QnA 할일을 닫는다. 제목의 문의 id 선두 고정으로, 담당이 아닌 다른 관리자가
  답변해도 할일이 정확히 닫힌다(SR 적용요청서·묶음 재상신과 동일 앵커드-클로즈 규약).

### 미답변 QnA 일배치 안내
`runDailyNotify` 에 미답변 QnA 안내를 더했다. 담당이 지정된 미답변 문의의 담당자에게 안내메일을 보내되,
담당이 퇴사해 재직 명단(`s.people`)에서 빠지면 제외한다(타 배치 유형과 동일한 재직 교집합 — 유령 독촉 방지).

## 호환성·영향
- 무회귀: 신규 할일 종류(`TodoKind` 에 `'QnA'`)와 배치 유형 추가. 기존 워크플로·집계 불변. 저장 스키마는
  기존 todos·qna 컬렉션을 사용한다.
- 컴파일 강제: `TodoKind` 확장으로 `KIND_HREF: Record<TodoItem['kind'],…>`(나의 할일)에 `QnA` 항목을
  더했다 — 누락 시 빌드가 막히는 안전장치.
