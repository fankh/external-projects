# 릴리스 노트 — portal-web v1.5.287

**실동작 REST 메시징 어댑터 — 목업을 넘어선 첫 실 구현.** 안내메일·문자 발송 채널을 목업이 아닌 실제
HTTP POST 로 발송하는 REST 어댑터로 구현하고, 샘플 고객사 프로필(제조·공공·금융)의 메일·문자에
바인딩한다. 데모 기본 프로필은 오프라인 시연을 위해 목업을 유지한다.

## 배경 — 발견 경위

연동 어댑터 계층은 계약(인터페이스)·레지스트리·자가진단(conformance)까지 갖췄으나, 모든 채널이 목업
구현에 매핑돼 있었다(`mock-*`). 요구사항 '기타작업'은 메일=그룹웨어(Knox) REST API, 문자=홈페이지
서버 REST API 로 발송하도록 규정한다. 그 실 전송 방식을 목업을 넘어 실제 구현으로 채운다.

## 주요 변경
- `lib/integrations/rest.ts`(신규): `restMail`·`restSms` — 설정된 엔드포인트로 실제 `fetch` POST
  (`{to, subject, from}` JSON, 선택적 Bearer 인증). 응답을 SendResult 로 매핑:
  - 수신자 0명 → 네트워크 호출 없이 `ok:true`(무발송) — 자가진단 `send([])` 경로가 엔드포인트 없이 통과.
  - 엔드포인트 미설정 → 네트워크 없이 `ok:false`(소프트 실패, throw 아님).
  - 비 2xx → `ok:false, HTTP <status>`. 네트워크·인증 예외 → throw(sendVia 가 실패 이력으로 흡수).
  - 응답의 `accepted`/`sent` 건수 반영. 자체 타임아웃 없음(registry.withTimeout 이 감쌈).
- `lib/integrations/registry.ts`: MESSAGING 맵에 `rest-mail`·`rest-sms` 추가, 샘플 프로필 별칭
  (`fin-mail`·`fin-sms`·`gov-mail`·`gov-sms`·`hanbit-gw-mail`)을 목업 → 실 REST 어댑터로 재바인딩.
  데모 기본(`mock-mail`·`mock-sms`)은 유지.
- 엔드포인트·인증·발신자는 배포 환경변수 주입: `PORTAL_MAIL_API_URL`·`PORTAL_MAIL_API_TOKEN`·
  `PORTAL_MAIL_FROM`(문자는 `PORTAL_SMS_*`). 하드코딩 없음 — 재빌드 없이 고객사 전환.

## 호환성·영향
- 무회귀: 데모 기본 프로필은 목업 유지(오프라인 시연·기존 발송 e2e 불변). 자가진단은 `send([])`
  단락으로 계약 통과(모든 프로필 그린). 샘플 고객사 프로필은 실 배포 시 엔드포인트를 설정하면 동작하고,
  미설정 시 발송 이력에 소프트 실패로 남는다(가시성 유지).

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt(41/41) · keycheck · health(51) · **e2e 108**.
- 신규 `sc_rest_mail`(금융 프로필·로컬 캡처 서버): 알림 배치 실행 → restMail 이 실제 HTTP POST 로 발송,
  캡처 서버 수신 바디에 수신자 목록·제목·발신자(env 주입 `PORTAL_MAIL_FROM`) 포함 확인. POST 를
  제거하면 캡처 0건으로 실패 대조(fails-without-fix 실측).
