# 릴리스 노트 — portal-web v1.5.221

v1.5.219의 SR 상태 라벨 정합을 export 계층까지 확장하고, 라벨 규칙(`srStatusLabel`)을 SR 도메인 단일
원천(`lib/sr`)으로 이관했다. 화면(v1.5.219)은 고쳤으나 SR 신청내역 export가 여전히 raw 상태('개발중')를
내보내, 데이터·계정/권한 SR이 화면에선 '처리중'인데 ISMS 감사 산출물(CSV)에선 '개발중'으로 어긋나던
잔여 drift를 닫는다.

## 배경 — 발견 경위

v1.5.219 직후 같은 drift 클래스(단일원천 헬퍼의 미적용 소비처)를 export 계층에 적용해 점검한 결과,
`app/api/export/route.ts`의 SR 신청내역 export(sr-requests)가 `srStatusLabel`을 거치지 않고 raw `r.status`를
렌더하고 있었다. 화면 6곳(대시보드·검색·관리·신청내역·배정완료·지연내역)은 헬퍼를 쓰는데 export만
누락 — 화면-export 불일치(개발 단계 없는 데이터·계정권한 SR에 '개발중' 오표기).

## 주요 변경

### `srStatusLabel`을 SR 도메인 단일 원천으로 이관 (`lib/sr.ts`)
라벨 규칙을 page-dir `app/(app)/sr/chips.ts`에서 `lib/sr.ts`(delayedSrs 등 SR 도메인 단일원천이 있는 곳)로
옮겼다. `chips.ts`는 기존 소비처(../chips import 6곳)를 위해 재수출한다 — 무중단. 이제 화면과 export가
같은 파일에서 라벨 규칙을 가져온다.

### export 라벨 정합 (`app/api/export/route.ts`)
SR 신청내역 export의 상태 열을 `r.status` → `srStatusLabel(r)`로 교체. 화면과 동일 라벨.

## 호환성·영향
- 무회귀: 표시 라벨만 정합(export 상태 열). 시스템개발 SR '개발중' 불변(kind 분기), 저장·전이 로직·기존
  화면 소비처 무변경(chips 재수출).

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt · keycheck · health · **e2e 87**(기존
  sc_sr_status_label 시나리오에 export 단언 추가 — 시나리오 수 불변).
- `sc_sr_status_label` 확장: 격리 데이터의 계정/권한 SR(개발중·CI배정·기한경과)이 화면(sr/ci·sr/delayed)에
  이어 sr-requests export CSV에서도 '처리중'(개발중 아님)으로 나옴을 검증. export를 raw 상태로 되돌리면
  단언이 실패함을 대조 확인(테스트 유효성 — CSV 행에 '개발중' 노출).
