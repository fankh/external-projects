# 로드맵 — v1.0 이후

v1.0(태그 `portal-web-v1.0`)은 데모·제안 범위의 봉인 지점이다. 요구사항 3개 시트가
소진됐고 게이트 3종이 녹색이므로, **신규 기능**은 아래 실고객 접점에서만 시작한다.
각 항목은 착수 조건(외부 입력)과 완료 기준을 함께 적는다.

예외로 **v1.0.x 패치 트랙**은 봉인과 무관하게 허용된다 — 결함 수정, 기존 폐쇄 루프의
공백 보강, 게이트(스모크·e2e) 검증 추가, 문서 정합. 새 화면·새 요구사항은 여기에
속하지 않는다. (v1.0.2~v1.0.12: 묶음 채번 결함, 반려→재상신 할일 일원화·방치 알림·
이전 회차 이력, 감사 '결재 상신', 영속화 구버전 머지·채널 토글, 세션 Secure 옵션,
접근 통제·CSV 부정 검증, 교육 완료 가드 — 상세는 README 단계 표.)

**강화·검증 트랙 (v1.1~v1.5, 봉인 예외):** v1.1.x 요구 복원(§4), v1.2 권한 아키텍처·보안선,

## 2. SAML SSO 연동

- **착수 조건**: 고객사 IdP 메타데이터(엔드포인트·인증서) 접수.
- **작업**: 로그인 화면의 목업 계정 선택을 SAML 어설션 처리로 교체. 세션 발급은
  기존 `signSession()` 을 그대로 쓰고, 어설션의 사번·권한그룹을 `Session` 으로 매핑한다.
  목업 로그인은 `PORTAL_PROFILE` 과 같은 방식의 환경 스위치로 개발용으로 보존한다.
- **완료 기준**: IdP 로그인 → 권한그룹별 메뉴 노출 확인 + 스모크의 세션 부정 검증
  (변조·만료) 4건이 SAML 세션에서도 통과.

- 새 화면·권한은 `components/chrome/menus.ts` 한 곳에서 시작한다(내비·가드·매트릭스·
  스모크가 따라온다). 새 결재 유형은 `ApprovalDocType` 추가 → `draftApproval` 상신 →
  `work/approvals/actions.ts` 전파 순서다.
- 결함을 고치면 같은 커밋에 재발 방지 체크(스모크 니들 또는 e2e 시나리오)를 함께 넣는다.
- 주기적으로 `npm audit` 를 확인한다 — 전이 의존성 취약점은 프레임워크 다운그레이드
  대신 `overrides` 로 패치 버전을 강제하고, 의존성이 바뀌면 게이트 전체와 Docker
  빌드·기동을 재검증한다 (선례: v1.0.20).
- 실배포 환경변수: `SESSION_SECRET`(랜덤 키 필수), HTTPS 종단이면 `PORTAL_COOKIE_SECURE=1`,
  영속화는 `PORTAL_DATA_FILE`, 알림 배치 주기는 `PORTAL_NOTIFY_INTERVAL_MS`.
- 병렬 세션과 같은 저장소를 쓸 때 테스트 포트는 3500번대(이 프로젝트) 를 유지한다.
