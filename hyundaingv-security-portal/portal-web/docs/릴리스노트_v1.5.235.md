# 릴리스 노트 — portal-web v1.5.235

정산품의 상신(requestSettlement)에 결재대기 이중 상신 방지 가드를 더했다. 같은 계약·항목·금액의 정산품의가
이미 결재중인데 다시 상신하면(더블클릭·재전송) 두 건이 각각 결재→지급완료로 승인될 수 있어, 집행액이
겹계상되어 집행률·계획대비실적·비용 속보 기준금액이 부풀던 결함을 닫는다(협력업체 서약·인프라 변경 징구
dedup 과 동일 정책).

## 배경 — 발견 경위

관리 액션 상태전이 가드 스윕(v1.0.30 장애 조치완료 가드 계열)에서 발견. 앱 전역 `'use server'` 액션은 상태전이·
컬렉션 삽입·카운터 증가 모두 선행 가드가 촘촘했으나(상태 한정 find, 등록/징구 dedup, 증가 게이팅), 정산품의
상신만 dedup 이 없었다. requestSettlement 는 비-임시저장 시 정산(결재중)을 만들고 결재선(draftApproval)에
올리는데, 더블클릭으로 동일 (계약·항목·금액) 결재중 정산 2건이 서면 결재자가 둘 다 승인할 경우 지급완료가
두 번 반영돼 집행액이 이중 계상된다. 이는 이미 도입한 addCompanyPledge(v1.5.225)·addInfraChange(v1.5.223)의
'대기 상태 중복 방지'와 같은 클래스이며, 결재를 생성하는(재무 집계에 전파되는) 가장 고위험 create 다.

## 주요 변경
- `app/(app)/finance/invest/page.tsx` `requestSettlement`: 비-임시저장 상신 시 같은 `(contractId, item, amount)`
  정산이 이미 `결재중`이면 무시. 결재가 끝나(지급완료·반려) 대기 건이 없으면 새 정산은 정상 진행.
- `app/(app)/finance/expense/page.tsx` `requestSettlement`: 동일 가드(비용 계약).

## 호환성·영향
- 무회귀: 임시저장(작성중)은 결재 전파가 없어 가드 대상 아님 — 초안 중복은 그대로 허용. 결재대기 중복만 차단.
- 정상 흐름 무변경: 서로 다른 항목·금액, 또는 앞 정산이 지급완료·반려로 종결된 뒤의 신규 정산은 정상 상신된다
  (착수금·중도금·잔금 순차 정산, 월정산 반복 등 정당 다건 정산에 영향 없음).
