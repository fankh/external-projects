# 릴리스 노트 — portal-web v1.5.291

**실동작 REST 자산 어댑터 — 조회 + 등록번호 취득 쓰기 폐쇄루프.** 자산관리시스템 연동을 목업이 아닌
실제 HTTP 조회(GET)와 신규 자산등록번호 취득(POST 쓰기)으로 구현한다. 메시징(v1.5.287)·HR(v1.5.289)에
이은 세 번째 실 어댑터이자, 포털이 외부 시스템에 **쓰기**를 수행하는 첫 실 폐쇄루프.

## 배경 — 발견 경위

요구사항 자산등록: "자산관리시스템 API 통해 자산정보 조회 및 신규자산 등록을 위한 자료 전송하여
자산등록번호 취득". 조회(읽기)와 등록번호 취득(쓰기)의 양방향 폐쇄루프다. 계약(`AssetAdapter`)은
있었으나 구현이 목업뿐이었다. 실 조회·취득 경로를 채운다.

## 주요 변경
- `lib/integrations/rest.ts`: `restAsset` 추가.
  - `searchAssets(query)`: `PORTAL_ASSET_API_URL` GET(`?q=`), 응답을 `ExternalAsset` 로 매핑(통용 필드명:
    serial·sn / model / category·type / holder·owner / assetNo?), 응답 봉투 배열·`{assets|data|items}` 지원,
    유효 행만 수집. 미설정 시 빈 배열(자가진단은 빈 배열도 계약 통과).
  - `acquireAssetNo(serial)`: `PORTAL_ASSET_REGISTER_URL` POST(`{serial}` → `{assetNo}`), 취득번호 반환.
    미설정·응답 누락은 throw — acquire 액션의 try/catch 가 흡수(빈 번호 저장·재시도 영구차단 방지).
  - 인증은 `PORTAL_ASSET_API_TOKEN`(Bearer). 조회 실패는 화면 `.catch(()=>[])`, 취득 실패는 액션이 흡수.
- `lib/integrations/registry.ts`: `rest-asset` 등록 + 샘플 고객사 자산 별칭(`fin-asset`·`gov-asset`·`erp-asset`)을
  목업 → 실 REST 재바인딩. 데모 기본(`mock-asset`)은 유지(오프라인·결함주입 테스트 불변).

## 호환성·영향
- 무회귀: 데모 기본 프로필은 목업 자산 유지(계약위반 내성 e2e 불변). 자가진단은 미설정 시 빈 조회로 통과
  (자산 계약은 빈 배열 허용). 샘플 고객사 프로필은 실 배포에서 엔드포인트 설정 시 실 조회·취득.

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt(41/41) · keycheck · health(51) · **e2e 110**.
- 신규 `sc_rest_asset`(금융 프로필·로컬 자산 픽스처 GET+POST): 자산등록 화면 조회 → 실 GET(픽스처 히트)·
  목록 표시 → '등록번호 취득' → 실 POST(픽스처 히트)로 취득번호(AST-FIN-9001) 이력 기록. 실 GET 제거 시
  조회 0건·취득 버튼 부재로 실패 대조(fails-without-fix 실측).
