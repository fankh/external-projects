# 릴리스 노트 — portal-web v1.5.237

일일 알림 배치의 '출력물 미등록' 안내메일에 부서장(부서 DEPT_MGR) 통지를 더했다. 요구사항 시트 56행이
출력물 폐기정보 미등록 주기 안내를 "안내메일(부서장, 출력자)"로 명시하는데, 그동안 출력자(본인)에게만
발송되고 부서원의 폐기자료를 결재신청하는 책임자인 부서장에게는 통지가 없었다. 점검 경과 알림의
담당자+팀장 이중 통지(v1.5.209)와 동일 정책으로 부서장을 수신자에 포함한다.

## 배경 — 발견 경위

스펙-대-구현 깊이 감사(제품안내서·sample.xlsx 요구사항 행 정밀 대조)에서 발견. 요구사항 64행(점검계획)의
"담당자, 팀장에 경과 항목 알림"은 v1.5.209(INSPTL)에서 담당자+팀장 이중 통지로 구현됐으나, 같은 이중-수신자
클래스인 56행(출력물폐기현황) "주기적으로 안내메일(부서장, 출력자)"은 출력자 단일 통지에 머물러 있었다.
부서장은 부서원 폐기자료를 취합·결재신청하는 역할이라, 부서에 미등록 출력물이 있으면 통지받아야 감사 루프가
닫힌다.

## 주요 변경
- `lib/notify.ts` '출력물 미등록' 안내:
  - 미등록 출력물이 있는 부서의 부서장(ACCOUNTS 의 DEPT_MGR, 부서 일치)을 수신자에 포함.
  - 수신자 = 출력자 ∪ 해당 부서 부서장, 재직 명단(s.people) 교집합. 출력자·부서장이 동일인이면 Set 으로 1회.
  - DEPT_MGR 역할은 Person 에 없어 ACCOUNTS 로 해석(qna 담당 지정과 동일 패턴). `ACCOUNTS` import 추가.

## 호환성·영향
- 무회귀: '출력물 미등록' 수신자만 확장. 다른 알림 유형·이관 배치·집계 무변경.
- 부서장이 없는 부서(ACCOUNTS 에 해당 DEPT_MGR 없음)의 미등록 출력물은 종전대로 출력자만 통지 —
  팀장 미지정 점검 계획이 담당자만 통지하는 것과 동일(무해 폴백).
- 재직 교집합 정책 유지 — 퇴사한 출력자·부서장에게 유령 독촉이 가지 않는다.

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt · keycheck · health · **e2e 90**(신규 시나리오
  sc_printout_deptlead).
- `sc_printout_deptlead`: 격리 데이터(경영지원팀 정민서의 미등록 출력물 1건)로 알림 배치 실행 후 감사 로그의
  '알림 배치 실행' 상세에서 '출력물 미등록 2명'(출력자 정민서 + 부서장 이수진)을 검증. 부서장 통지 제거 후
  재빌드 시 '출력물 미등록 1명'으로 단언 실패함을 실측 대조(fails-without-fix).
