# 릴리스 노트 — portal-web v1.5.189

이 릴리스는 재사용 프레임워크의 **프로필 격리** 무결성을 닫는다(감사 항목 AD-7). 한 이미지를 `PORTAL_PROFILE`
로 고객사 전환하는 구조에서, 영속화 파일(`PORTAL_DATA_FILE`)에는 프로필 스코프 런타임 설정(연동 채널
가동상태·메뉴권한 오버레이)이 들어 있으나 어느 프로필로 저장됐는지 표식이 없었다. 그래서 한 데이터 파일을
프로필 전환에 재사용하면 A 프로필의 채널 토글·메뉴 제한이 B 프로필로 새어 운영 통제가 어긋날 수 있었다.
이제 파일에 프로필을 각인하고, 불일치 시 프로필 스코프 설정을 활성 프로필 기본으로 되돌린다. 전 게이트가 그린이다.

## 주요 변경

### 프로필 스탬프 + 격리 리셋
- **저장(saveNow):** 데이터 파일에 `__profileStamp`(현재 `PORTAL_PROFILE`, 미설정 시 `default`)을 각인한다.
  시드에 없는 키라 재로드 머지에서 무시되므로 도메인 데이터·기존 동작에 영향이 없다.
- **로드(loadFromFile):** 파일 스탬프가 활성 프로필과 다르면, 프로필 스코프 런타임 설정(`channelStates`·
  `menuOverrides`)을 활성 프로필 시드 기본으로 리셋한다. 업무 도메인 데이터(인사·SR·자산 등)는 그대로 보존한다.
- **무회귀:** 스탬프가 없는 파일(구버전·테스트 픽스처)은 `undefined` 로 리셋하지 않는다 — 기존 영속화·손상
  내성 동작이 불변이다.

## 호환성·영향
- 저장 스키마: 최상위에 메타 키 `__profileStamp` 만 추가(스토어 컬렉션 불변). 구버전 파일과 상호 호환.
- 동작: 같은 프로필로 계속 쓰면 스탬프가 일치해 리셋이 발생하지 않는다 — 정상 운영 무영향.
