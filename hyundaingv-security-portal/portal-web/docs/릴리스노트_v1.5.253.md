# 릴리스 노트 — portal-web v1.5.253

상신취소(회수) 시 참조 업무 상태 복원을 **컴파일 타임에 강제**하도록 리팩터링했다. 회수 가능 문서 유형과
그 복원 핸들러의 대응을 타입 시스템이 전수 요구해, 유형을 늘리면 복원 누락이 빌드 에러로 잡힌다. 동작은
불변(순수 구조 개선).

## 배경 — 발견 경위

결재 엔진 방어 감사(승인·반려·회수 이중효과·고아 in-flight 클래스)에서, 회수 복원 대응이 **수동 불변식**임을
확인했다. `WITHDRAWABLE_DOC_TYPES`(회수 가능 유형 목록)와 `withdraw` 액션의 유형별 복원 `if` 블록이
문자열로만 짝지어져 있어, 향후 회수 가능 유형을 추가하면서 복원 핸들러를 빠뜨리면 컴파일러가 잡지 못하고
해당 참조 업무가 '결재중'에 갇히는 고아 in-flight 가 될 수 있었다(현 시점 대응은 정확 — 5종 전부 복원됨).
현재 결함은 아니나, 코드베이스가 이미 쓰는 방어 스타일(AuditAction 엄격 Record, ChannelKind 전수 switch)과
동일하게 타입으로 강제하면 이 회귀 부류를 원천 차단할 수 있어 사용자 요청으로 반영한다.

## 주요 변경
- `lib/approvals.ts`:
  - `WithdrawableDocType` 유니온 타입 신설(ApprovalDocType 의 회수 가능 부분집합).
  - `WITHDRAW_RESTORERS: Record<WithdrawableDocType, (s, ref) => void>` 신설 — 회수 시 참조 업무 복원
    로직의 단일 원천. `Record` 키가 유니온을 전수 요구하므로 유형 추가 시 복원기 누락이 컴파일 에러(TS2741).
    각 복원기는 진행중 상태(예: SR '결재중')일 때만 되돌린다(경합·중복 회수 방어 — 기존 인라인 가드 보존).
  - `WITHDRAWABLE_DOC_TYPES` 를 복원 맵 키에서 파생(단일 원천)로 변경. 화면·서버 가드의 `.includes` 소비 불변.
  - `isWithdrawableDocType` 타입가드 신설 — 캐스트 없이 ApprovalDocType→WithdrawableDocType 로 좁혀 복원기 인덱싱.
- `app/(app)/work/approvals/actions.ts` `withdraw`: 유형별 5개 인라인 복원 `if` 블록을 복원 맵 단일 디스패치
  (`if (ap.ref) WITHDRAW_RESTORERS[docType](s, ap.ref)`)로 대체. 가드는 `isWithdrawableDocType` 로 좁혀 캐스트 제거.

## 호환성·영향
- 무동작변경: 회수 가능 유형 5종(SR 신청·적용요청·변경계획·변경결과·보안위반 확인서)과 각 복원 전이는 종전과
  동일. 순수 구조 개선이라 런타임 동작·데이터·화면 불변. 회수 불가 유형(정산품의·장애·출력물·서약현황)은 종전과
  동일하게 회수 대상이 아니다.
- 향후 회수 가능 유형 추가 시, 복원 핸들러를 함께 넣지 않으면 `next build` 가 실패한다(의도된 강제).

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt · keycheck · health · e2e 96.
- 타입 강제 실증(fails-without-fix): `WithdrawableDocType` 에 임의 유형('투자 정산품의')을 복원기 없이 추가하면
  `tsc --noEmit` 가 `error TS2741: Property '"투자 정산품의"' is missing … Record<WithdrawableDocType, …>` 로
  실패함을 실측(TSC exit 2), 복원 후 exit 0.

  전후 동일 동작 확인.
