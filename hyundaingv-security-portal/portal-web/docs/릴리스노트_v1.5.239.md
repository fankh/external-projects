# 릴리스 노트 — portal-web v1.5.239

정산품의(투자·비용)에 삭제(폐기) 기능을 더했다. 요구사항 시트 11·17행이 정산품의 화면에 P=삭제◎를
부여하는데, 다른 P=삭제◎ 화면(게시판·인프라 랙/HW/서버/시스템/배치/인터페이스·장애·프로젝트·공통코드)이
모두 삭제 액션을 구현한 반면 정산품의만 삭제 경로가 없었다. 기안자 본인의 미상신(작성중)·반려 정산을
폐기할 수 있게 하고, 파괴적 통제 행위라 감사 로그에 남긴다.

## 배경 — 발견 경위

스펙-대-구현 깊이 감사(요구사항 sample.xlsx 행 권한 매트릭스 대조)에서 발견. P=삭제◎로 표기된 화면들을
구현된 delete 액션과 대조하니 정산품의(11·17행)만 삭제가 없었다. 잘못 만든 초안·반려된 정산을 폐기할 경로가
없어 목록에 계속 남던 갭이다. 결재중(대기 결재 존재)·지급완료(집행 확정)는 무결성상 삭제 대상이 아니므로
제외하고, 작성중·반려 건만 대상으로 한다(재상신 가드 resubmitSettlement 와 동일 상태 스코프).

## 주요 변경
- `app/(app)/finance/actions.ts` `deleteSettlement`(신규, 공용 액션): 기안자 본인의 작성중·반려 정산만 삭제.
  대기 결재가 없을 때만(이중 방어), 품의 소속 화면(투자/비용)의 런타임 메뉴 제한을 쓰기에도 적용. 삭제 시
  `audit(기안자, '정산품의 삭제', 품의번호·종류·계약·항목·금액·상태)`.
- `lib/audit.ts`: AuditAction '정산품의 삭제' 추가.
- `app/(app)/settings/audit/page.tsx`: ACTION_TONE(strict Record) '정산품의 삭제': 'warn' 매핑(삭제 계열 톤).
- `app/(app)/finance/invest/page.tsx`·`expense/page.tsx`: 정산 행의 작성중·반려(본인) 건에 '삭제' 버튼 추가
  (기존 상신/재상신 버튼 옆). deleteSettlement import.

## 호환성·영향
- 무회귀: 결재중·지급완료 정산은 삭제 버튼이 렌더되지 않고 서버 가드로도 차단 — 집행·결재 무결성 보존.
- 삭제는 기안자 본인·DEPT_MGR+·해당 화면 메뉴권한 3중 가드(resubmitSettlement 와 동일 스코프). USER 는
  정산 카드 자체에 접근하지 않는다(v1.5.42).
- 삭제가 감사 로그에 남아 §VI 이력추적성 유지(sibling delete 들과 동일 정책).
