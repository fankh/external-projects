# 릴리스 노트 — portal-web v1.5.243

보안위반 결재제외 완료(closeExempt)가 반려 상태 위반자의 '재상신' 할일을 고아로 남기던 결함을 고쳤다.
보안위반 확인서가 반려되면 위반자에게 '재상신' 할일이 생기고 위반은 징구중으로 돌아가는데, 이 상태에서
업무담당자가 결재제외 별도관리로 완료 처리하면 위반이 완료로 바뀌어 재상신 경로(submitStatement=징구중 필요)가
사라진다. 그 결과 '재상신' 할일이 영영 닫히지 못하고 일일 배치 '반려 방치'가 위반자에게 무한 안내메일을 보냈다.

## 배경 — 발견 경위

정산품의 삭제 고아-할일 회귀(v1.5.241) 수정 후, '고아 할일/유령 독촉' 클래스를 제거·종결 액션 전반에 걸쳐
독립 에이전트로 체계 점검하다 발견. 이 클래스는 코드베이스가 여러 곳에서 이미 막아온 것(SR submitApply·변경
closeChangeResignTodo·점검 registerResult·프로젝트 완료·QnA 삭제·정산 삭제)인데, closeExempt(v1.5.217에서
'영구 징구중' 갭 수정으로 추가됨)만 반려 재상신 할일을 닫지 않는 구멍이 남아 있었다. closeExempt 의 가드는
status==='징구중'뿐이라, 확인서 반려 직후(징구중 복귀 + 재상신 할일 존재) 상태에서 그대로 완료 처리된다.

## 주요 변경
- `app/(app)/awareness/violations/page.tsx` `closeExempt`: 완료 처리 후 매칭되는 열린 '재상신' 할일을 닫는다 —
  `t.kind === '재상신' && t.title.startsWith(\`[보안위반 확인서] ${v.id} \`)` 인 미완료 할일을 done 처리
  (deleteSettlement·inspection registerResult 와 동일 유형+ref 선두 고정 폐쇄).

## 호환성·영향
- 무회귀: 완료 처리·스캔 증빙·감사·상태 전이 무변경. 반려 이력이 없는(재상신 할일 없는) 위반의 결재제외
  완료는 이 루프가 무동작(무해). 반려 후 결재제외 완료만 할일이 함께 닫혀 고아·무한 알림이 사라진다.
