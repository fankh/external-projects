# 릴리스 노트 — portal-web v1.5.209

요구사항(sample.xlsx)의 보안점검 경과 알림을 "담당자, **팀장**에 경과 항목 알림 - 메일" 명세대로 완성했다.
기존에는 경과 점검 항목의 담당자(inspector)에게만 안내메일이 갔는데, 이번에 각 점검 계획에 팀장(teamLead)을
두어 담당자와 팀장 양쪽에 통지한다.

## 배경 — 요구사항 대비 갭

sample.xlsx 보안점검 요구는 "담당자, 팀장에 경과 항목 알림 - 메일"을 명시한다. 감사 결과:
- 알림 배치(`lib/notify.ts`)의 '점검 경과'는 예정월 경과·미완료 점검의 **담당자에게만** 발송했다 —
  요구가 명시한 **팀장**은 통지에서 빠져 있었다.
- 데이터 모델(`InspectionPlan`)에 팀장 참조 필드가 없어, 팀장 통지가 구조적으로 불가능했다(`Person` 은
  name·dept 만 있어 담당자 부서로부터 팀장을 안전하게 유도할 수도 없다).

## 주요 변경

### 점검 계획에 팀장(teamLead) 필드 (`lib/types.ts`, `lib/store.ts`)
`InspectionPlan` 에 `teamLead?: string`(플랫 필드)을 더했다. 담당자와 별개로 경과 알림을 함께 받는 팀장을
계획별로 명시한다(부서→팀장의 불완전한 유도 대신 명시적 지정 — 실배포에서 각 점검의 책임 라인을 정확히
반영). 시드 점검 계획에 팀장을 지정했다.

### 담당자+팀장 경과 알림 (`lib/notify.ts`)
'점검 경과' 배치가 경과 점검의 담당자와 팀장을 함께 수신자로 삼는다(둘 다 재직 명단 교집합, 팀장 미지정
계획은 담당자만). 중복 수신자는 기존대로 `Set` 으로 정리된다.

### 팀장 지정·표시 (`app/(app)/compliance/inspection/page.tsx`)
- 점검계획 수립 폼에 팀장 선택(비-USER 계정, 선택 항목) 추가 — 임의 POST 는 담당자와 동일 집합으로 검증,
  미지정은 허용.
- 점검 진행내역 표에 '팀장' 열 추가.

## 호환성·영향
- 무회귀: teamLead 는 선택 필드. 미지정 계획·기존 데이터 파일(필드 없음)은 담당자만 통지(기존 동작 유지).
- 플랫 문자열 필드라 스토어 손상 가드(중첩 객체 필드 제거) 영향 없음.

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt · keycheck · health · **e2e 82**.
- e2e `sc_inspection_teamlead`: 격리 데이터 파일(경과 점검 1건, 담당자 박정호·팀장 시스템관리자, 둘 다 재직)로
  알림 배치를 실행하고 감사 로그의 '점검 경과'가 **2명**(담당자+팀장)임을 확인한다. 수정 전(팀장 미통지)엔
  '점검 경과 1명'으로 두 단언이 실패함을 대조 확인(테스트 유효성) 후 복원했다.
