# 릴리스 노트 — portal-web v1.5.271

**신규 도메인 — 정보보호 정책·지침 관리대장(ISMS 관리체계 1.1).** 정보보호 정책·지침·절차 문서를 버전·
시행일·재검토 주기로 관리하고, 재검토 예정일 경과를 추적해 주기적 재검토를 강제한다. ISMS 인증의
관리체계 요건 중 위험평가(v1.5.259~) 다음으로 기초가 되는 정책 문서 관리 갭을 닫는다.

## 배경 — 발견 경위

방어적 도메인 커버리지 점검에서 발견 — 포털이 ISMS 근거로 위험평가·교육·점검·보안성 검토·위반을 다루면서도
관리체계의 최상위 요건인 **정책 문서 관리**(문서 버전·시행·주기적 재검토)가 없었다. 게시판 공지에 '정책·규정'
분류가 있으나 그것은 '알림'이고, 정책 문서의 버전·재검토 '생명주기'를 추적하는 대장은 부재했다. ISMS 는
정책·지침을 문서화하고 연 1회 이상 재검토하도록 요구하므로, 위험관리대장과 동형 패턴으로 신규 도메인 구현.

## 주요 변경
- `lib/dates.ts` `addMonths(date, months)` — 재검토 예정일(nextReviewDue) 산출용(월 오버플로 캐리·말일 클램프).
- `lib/types.ts` `SecurityPolicy`(분류·버전·담당·상태·시행일·재검토주기·최근검토일) + `PolicyCategory`(정책·지침·
  절차)·`PolicyStatus`(시행·개정중·폐지) 유니온.
- `lib/policy.ts`(신규 단일 원천): `nextReviewDue`(=최근검토일+주기, 저장 않고 파생)·`isReviewOverdue`
  (시행+예정일 경과)·`computePolicyKpis`(전체·시행·개정중·재검토 경과).
- `app/(app)/compliance/policies/page.tsx`(신규): 관리대장(재검토 경과·개정중 우선 정렬) + 등록/재검토(시계
  리셋)/개정 착수→완료(신 버전 시행)/폐지/삭제 생명주기. 삭제는 폐지 정책만(문서 이력 보존, 서버 상태 가드).
- `lib/store.ts`: `securityPolicies` 컬렉션 + 시드 4건(기본정책·접근통제 지침[재검토 경과]·자산 절차[개정중]·
  개인정보 처리방침). `components/chrome/menus.ts`: 보안 컴플라이언스 그룹에 `정책·지침 관리`(BIZ).
- `lib/audit.ts`·`settings/audit`: `정책 등록·변경·삭제` 감사 액션 + ACTION_TONE. `export` policies 엑셀(BIZ 게이트).
- 게이트 등록(emptystate·health·smoke).

## 호환성·영향
- 무회귀: 신규 독립 도메인 추가로 기존 화면·집계 불변. securityPolicies 는 시드-머지 제네릭 경로가 자동
  정규화(수치·문자열 강제, 손상 내성). 삭제는 폐지 정책만(서버 가드) — 시행·개정중 문서 은닉 삭제 차단.

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt(40/40) · keycheck · health(50) · **e2e 103**(신규 sc_policy_lifecycle).
- `sc_policy_lifecycle`(격리): 재검토 예정일 경과 정책을 '재검토'로 경과 해소(시계 리셋) → 개정 착수→완료
  (v2.0 시행) → 폐지 → 삭제 전 생명주기. 재검토 시 최근검토일 갱신 제거 시 경과 미해소로 실패 대조(fails-without-fix).
