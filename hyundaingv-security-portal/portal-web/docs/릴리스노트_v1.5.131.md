# 릴리스 노트 — portal-web v1.5.131

이 릴리스는 v1.5.120 에서 신규 도메인으로 추가한 **보안성 검토**에 **심각도 등급**을 더한다. 종전에는
취약점을 발견 수·조치 수의 단일 총계로만 관리했으나, 실제 보안 운영에서는 심각도가 조치 우선순위를
가른다. 이제 발견·조치를 심각·높음·보통·낮음 등급으로 나눠 기록하고, **고위험(심각+높음) 미조치**를
우선 조치 신호로 화면·대시보드·감사 근거 산출물 전반에 드러낸다. 전 게이트가 그린이다(e2e 68/68).

## 주요 변경

### 심각도 등급별 발견·조치
보안성 검토의 발견/조치를 등급별로 세분한다.
- 검토 결과 기록 시 심각·높음·보통·낮음 등급마다 발견 수와 조치 수를 입력한다. 각 등급의 조치는 그 등급
  발견을 넘지 못하며(무결성), 총 발견·조치는 등급 합으로 유지된다.
- 발견 취약점을 전건 조치해야 완료로 확정되는 기존 무결성 가드는 그대로다.

### 고위험 미조치 우선 신호
심각·높음 등급의 미조치 취약점을 '고위험 미조치'로 별도 집계해, 우선 대응이 필요한 지점을 한눈에 준다.
- 보안성 검토 화면: 상단 '고위험 미조치' 지표와 각 검토 행의 '고위험 N' 마커.
- 개인별현황 전사 운영 스냅샷: '고위험 미조치'를 오류(적색) 신호로, 전 등급 '미조치 취약점'은 경고로 구분.
- 컴플라이언스 종합 현황 export: 보안성 검토 항목에 '고위험 미조치 N건' 표기.

세 지점 모두 `highSevOpen` 단일 원천에서 산출하므로 화면과 산출물의 수치가 어긋나지 않는다.

## 호환성·영향
- 무회귀: 총계(findings/fixed)는 등급 합으로 유지되므로 이를 쓰는 기존 소비처(대시보드·일일 배치·검색·
  export)는 변경 없이 동작한다. 등급별 필드는 손상 내성을 위해 중첩 객체가 아닌 평면 숫자 필드로 두어
  스토어 정규화가 자동으로 방어한다(빈·손상 스토어 38/38 렌더 정상).
- 데이터: 신규 등급 필드는 시드 3건에 등급 분해로 채워지며, 신규 검토는 0 으로 시작한다.

## 검증
- 게이트 전량 그린: build · smoke 575 · a11y 697 · emptystate/corrupt 38 · keycheck 3 · health 48 · e2e 68.
- e2e `sc_security_review` 를 등급별 흐름으로 갱신 — 고위험 미조치 마커 확인 → 완료 차단 → 등급별 전건
  조치 → 고위험 소거 → 완료 확정을 실브라우저로 검증.
- 운영 메모: 게이트 keycheck 실패가 '역전된 결과'(커스텀 키 거부·기본 키 통과)면 코드 회귀가 아니라
  포트 3419 유령 서버에 붙은 것이다(일회용 검증 스크립트 잔존 서버) — 확인·회수 후 재실행하면 그린.
