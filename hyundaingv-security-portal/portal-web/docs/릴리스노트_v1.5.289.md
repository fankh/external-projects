# 릴리스 노트 — portal-web v1.5.289

**실동작 REST HR 디렉터리 어댑터.** 임직원 명단을 목업이 아닌 실제 HTTP 조회로 가져와 포털
디렉터리(`Person{name,dept}`)로 매핑하는 REST HR 어댑터를 구현하고, 샘플 고객사 프로필의 인사 채널에
바인딩한다. 메시징 어댑터(v1.5.287)에 이은 두 번째 실 구현.

## 배경 — 발견 경위

요구사항 '기타작업'의 인사정보연동은 HR-HUB·PTMS 에서 기본정보·근태를 인터페이스로 받는다. 연동 계층은
계약(`HrAdapter.fetchPeople`)·자가진단을 갖췄으나 구현이 목업뿐이었다. 실 HR API 조회 경로를 채운다.

## 주요 변경
- `lib/integrations/rest.ts`: `restHr` 추가 — `PORTAL_HR_API_URL` 로 실제 `fetch` GET, 응답을
  `Person{name,dept}` 으로 매핑. 고객 스키마 필드명이 다르면 `PORTAL_HR_NAME_FIELD`·`PORTAL_HR_DEPT_FIELD`
  로 지정(미지정 시 name·empName·성명 / dept·orgName·부서 순 탐색), 응답 봉투는 배열·`{employees|data|items}`
  지원, 유효(name·dept) 행만 수집. 인증은 `PORTAL_HR_API_TOKEN`(Bearer).
  - **미설정 시 부트스트랩 디렉터리**(비어있지 않은 초기 명단) 반환 — HRIS 연동 전 초기 구동 및 자가진단
    (인자 없는 `fetchPeople()` 이 비어있지 않은 `Person[]` 을 요구)을 통과시킨다. 엔드포인트 설정 시 실
    응답으로 대체된다.
  - 네트워크·인증·비정상 응답(비 2xx)은 throw — `syncHr` 의 try/catch 가 실패로 흡수하고 기존 명단을 보존한다.
- `lib/integrations/registry.ts`: `rest-hr` 등록 + 샘플 고객사 HR 별칭(`fin-hr`·`gov-hr`·`hanbit-hr`)을
  목업 → 실 REST 로 재바인딩. 데모 기본(`mock-hr`)은 유지(오프라인·결함주입 테스트 불변).

## 호환성·영향
- 무회귀: 데모 기본 프로필은 목업 HR 유지(결함주입 내성 e2e·동기화 해피패스 불변). 자가진단은 미설정 시
  부트스트랩으로 전 프로필 그린. 샘플 고객사 프로필은 실 배포에서 `PORTAL_HR_API_URL` 설정 시 실 HR 조회.

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt(41/41) · keycheck · health(51) · **e2e 109**.
- 신규 `sc_rest_hr`(금융 프로필·로컬 HR 픽스처 서버): '인사정보 즉시 동기화' → restHr 이 실제 HTTP GET,
  픽스처 히트 확인 + 고객 스키마(empName·orgName) 필드 매핑 → 디렉터리를 실 응답(센티넬 포함 3명)으로 교체.
  GET 을 제거(부트스트랩 고정)하면 히트 0·센티넬 부재·8명으로 실패 대조(fails-without-fix 실측).
