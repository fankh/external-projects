# 릴리스 노트 — portal-web v1.5.265

정보보호 위험관리대장의 **삭제 서버 가드**를 화면 의도와 일치시킨다. 미종결(식별·조치중) 위험은 화면에
삭제 버튼이 없으나 서버액션은 직접 POST 가능했다 — 서버에서도 종결(완료) 위험만 삭제하도록 가드해,
미해결 위험이 은닉 삭제로 ISMS 감사 트레일에서 사라지는 것을 막는다.

## 배경 — 발견 경위

신규 위험평가 도메인(v1.5.259~263) 방어적 자체 감사(직접 POST 우회 클래스)에서 발견. `deleteRisk` 서버액션이
기안자·존재만 확인하고 **상태는 확인하지 않아**, 종결 건에만 삭제 버튼을 노출하는 화면 의도와 달리 미종결
위험도 위조 POST 로 삭제될 수 있었다. 코드베이스가 이미 이 부류를 서버에서 방어한다 — `updateProgress`
(완료 프로젝트 진척 되돌리기 차단, "화면은 숨기나 서버액션 직접 POST 가능하므로 서버 가드")·`deleteSettlement`
(반려·작성중 정산만 삭제). 위험 삭제도 동일 방어를 적용한다.

## 주요 변경
- `app/(app)/compliance/risks/page.tsx` `deleteRisk`: 상태 가드 추가(`!r || !isRiskClosed(r)`) — 종결(완료)된
  위험만 삭제. 미종결 위험은 종결(수용·완화 조치로 완료 처리)로 다루지 삭제로 없애지 않는다(감사 트레일 보존).
  화면 안전장치(종결 건만 삭제 버튼)의 서버측 이중화(updateProgress·deleteSettlement 상태 가드 계열).

## 호환성·영향
- 무회귀: 종결 위험 삭제(정상 경로)·미종결 위험의 재평가·종결 진행은 종전과 동일. 달라지는 것은 미종결
  위험을 위조 POST 로 삭제하려는 우회 시도가 차단되는 것뿐(교정). 참조무결성(첨부 정리)은 종결 삭제 시 그대로.

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt · keycheck · health · **e2e 100**(신규 sc_risk_delete_guard).
- `sc_risk_delete_guard`(격리): 종결(RK-91)·미종결(RK-92) 2건에서, 종결 건 삭제폼의 hidden id 를 미종결 건으로
  위조해 직접 POST 해도 RK-92 가 대장에 남음을 검증(서버 가드). 가드 제거 시 RK-92 삭제됨을 실측 대조
  (fails-without-fix). 화면 안전장치도 sc_risk_register 에 '미종결 위험 삭제 버튼 미노출' 단언으로 추가.
