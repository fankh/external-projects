# 릴리스 노트 — portal-web v1.5.259

**신규 도메인 — 정보보호 위험평가(ISMS 위험관리대장).** 포털의 핵심 목표인 ISMS 감사 대응에서 그동안
빠져 있던 필수 산출물, 위험평가/위험관리대장을 추가했다. 자산·영역의 위협×취약점을 발생가능성·영향도로
평가하고 처리 전략(완화·수용·전가·회피)·조치계획으로 종결까지 추적한다.

## 배경 — 발견 경위

방어적 자체 감사(결함 표면 소진 후)에서 도메인 커버리지를 점검하다, 포털이 ISMS 감사 근거로 컴플라이언스
포스처·보안점검·보안성 검토·보안위반·장애를 다루면서도 ISMS 인증의 **필수 요건인 위험평가(위험관리대장)**
만 비어 있음을 확인했다. 위험은 포스처 점수의 리스크 축(고위험 미조치 취약점·위반)으로 간접 반영될 뿐,
자산 기반 위협×취약점 위험을 식별·평가·처리하는 정식 대장이 없었다. ISMS 위험평가는 감사 시 반드시 요구되는
산출물이라 커버리지 갭 1순위로 판단해 신규 도메인으로 구현한다.

## 주요 변경
- `lib/types.ts`: `RiskItem`(자산·영역·위협·취약점·발생가능성·영향도·처리전략·담당·조치계획·기한·상태) +
  `RiskTreatment`(완화·수용·전가·회피)·`RiskStatus`(식별·조치중·완료) 유니온·상수배열.
- `lib/risk.ts`(신규) 단일 원천: `riskScore`(=발생가능성×영향도, 1~5 클램프)·`riskTier`(5×5 등급: 심각≥15·
  높음≥10·보통≥5·낮음)·`isHighRisk`(≥10)·`isRiskClosed`·`computeRiskKpis`(미종결·높음↑ 미종결·기한경과·종결률).
  위험도·등급은 **저장하지 않고 L·I 에서 파생**(재평가 시 한 곳만 바뀜) — fixRate·finance 처럼 경계 처리까지
  단일화(종결률은 false-100 방어, 지연은 `dueDate < today` 문자열 비교).
- `app/(app)/compliance/risks/page.tsx`(신규): KPI 5종 + **5×5 위험 히트맵**(미종결 위험 분포, 등급 색) +
  위험 등록 폼 + 위험관리대장(위험도 내림·미종결 우선 정렬) + 재평가/종결 진행/삭제 처리. BIZ_MGR·ADMIN 관리.
- `components/chrome/menus.ts`: 보안 컴플라이언스 그룹에 `정보보호 위험평가`(/compliance/risks, BIZ) 추가.
- `lib/store.ts`: `riskItems` 컬렉션 + 시드 4건(개인정보 오남용·EOL 서버·협력업체 원격·DR 부재). 시드-머지
  제네릭 경로가 자동 정규화(L·I 숫자 강제, 중첩 제거 — 손상 내성).
- `lib/audit.ts`·`settings/audit`: `위험 등록`·`위험 변경`·`위험 삭제` 감사 액션 + ACTION_TONE(컴파일 강제).
- `app/api/export/route.ts`: `risks` 엑셀(위험관리대장, BIZ 게이트, 위험도·등급 lib/risk 산출) + `EXPORT_MENU`
  등록 + **컴플라이언스 종합현황에 위험평가 한 줄**(종결률·높음↑ 미종결·기한경과) 추가로 ISMS 종합 근거에 편입.

## 호환성·영향
- 기존 화면·집계·포스처 점수 불변 — 위험평가는 **신규 독립 도메인**으로 추가되며, 포스처 점수 산식에는
  개입하지 않는다(컴플라이언스 종합현황 export 에 정보 행 1줄만 추가). 무회귀.
- 실서비스: 위험평가 방법론(척도·매트릭스 구간)은 lib/risk 한 곳에서 조정한다(고객사 ISMS 기준 반영 용이).
