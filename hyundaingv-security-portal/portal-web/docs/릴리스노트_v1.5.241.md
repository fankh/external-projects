# 릴리스 노트 — portal-web v1.5.241

정산품의 삭제(v1.5.239)가 반려 건의 '재상신' 할일을 고아로 남기던 회귀를 고쳤다. deleteSettlement 이 품의만
제거하고 반려로 생성된 재상신 할일은 닫지 않아, 삭제 후 그 할일을 닫을 경로가 사라져(재상신은 품의 존재 필요,
회전 닫기는 같은 ref 필요) 영구 미완료로 남고 일일 배치 '반려 방치'가 매일 무한 안내메일을 보내던 결함이다.

## 배경 — 발견 경위

v1.5.235·237·239 세 변경에 대한 적대적 자체 리뷰(독립 에이전트)에서 발견. 반려 정산은 결재 반려 시 기안자에게
'재상신' 할일을 남긴다(work/approvals). 정산품의 삭제 대상은 작성중·반려인데, 반려 건은 재상신 할일이 열려
있는 동안에만 삭제 가능(재상신하면 결재중으로 바뀌어 삭제 불가)하므로, 삭제되는 반려 정산은 항상 열린 재상신
할일을 물고 있다. deleteSettlement 이 품의를 지우면 그 할일은 resubmitSettlement(품의 존재 필요)·draftApproval
회전 닫기(같은 ref 필요) 어느 경로로도 닫히지 않아 고아가 되고, notify '반려 방치'가 매일 발송된다 — 코드베이스가
곳곳에서 막아온 '유령 독촉' 클래스(SR submitApply·변경·점검 registerResult 선례와 동일).

## 주요 변경
- `app/(app)/finance/actions.ts` `deleteSettlement`: 삭제 전 매칭되는 열린 '재상신' 할일을 닫는다 —
  `t.kind === '재상신' && t.title.startsWith(\`[${docType}] ${st.id} \`)` 인 미완료 할일을 done 처리
  (inspection registerResult 의 유형+ref 선두 고정 닫기와 동일 패턴). 재상신이 아니라 폐기로 종결하므로 할일도
  함께 닫는 것이 폐쇄 루프상 정합.

## 호환성·영향
- 무회귀: 삭제 자체·상태/소유자/메뉴 가드·감사 무변경. 반려 정산 삭제 시 재상신 할일이 함께 닫혀 고아·무한
  알림이 사라진다. 작성중 정산은 재상신 할일이 없어 이 루프가 무동작(무해).

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt · keycheck · health · **e2e 91**(시나리오 수 불변,
  sc_settle_delete 강화).
- `sc_settle_delete` 강화: 격리(settlements·approvals 비움)로 이수진 상신 → 박정호 반려(→재상신 할일 생성 확인)
  → 이수진 삭제 → 품의 목록·재상신 할일에서 모두 제거·감사 기록 검증. 할일 닫기 블록 제거·재빌드 시 재상신
  할일이 잔존해 단언 실패함을 실측 대조(fails-without-fix).
