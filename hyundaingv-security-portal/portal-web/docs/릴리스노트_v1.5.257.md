# 릴리스 노트 — portal-web v1.5.257

컴플라이언스 추세 스냅샷의 **취약점 조치율(fixRate)** 을 포스처 점수의 fix 축과 동일 단일 원천으로 맞췄다.
취약점 발견이 0건인 청정 기간이 추세에서 조치율 0%(실패)로 오표기되던 결함을 없앤다.

## 배경 — 발견 경위

단일 원천 정합 감사(같은 개념을 여러 곳에서 다르게 산출하는 드리프트 클래스)에서 발견. '취약점 조치율'을
세 소비처가 no-findings(`fixFindings === 0`) 케이스에서 서로 다르게 처리하고 있었다.
- 포스처 점수 fix 축(`postureAxes`): `fixFindings > 0 ? complianceKpiPct(...) : 100` → **100**(조치 대상 없음=만점).
- 종합 현황 화면(export 요약): `fixFindings > 0 ? '…%' : '해당없음'` → **해당없음**(N/A).
- 추세 스냅샷(`upsertComplianceSnapshot.fixRate`): `complianceKpiPct(k.fixDone, k.fixFindings)` → **0**
  (`complianceKpiPct` 는 분모 0 이면 0 반환).

스냅샷만 0 을 저장해, 취약점 발견이 없는 **청정 기간**(가장 이상적 상태)이 추세표·엑셀에서 조치율 **0%**
(전면 조치 실패처럼) 표기됐고, **같은 스냅샷의 score**(fix 축을 100 으로 반영)와도 모순됐다. 스냅샷 기록
감사 로그(`조치 0%`)에도 그대로 새어나왔다.

## 주요 변경
- `lib/compliance.ts`: `complianceFixRate(k)` 헬퍼 신설 — `fixFindings > 0 ? complianceKpiPct(k.fixDone, k.fixFindings) : 100`.
  포스처 fix 축(`postureAxes`)과 추세 스냅샷(`upsertComplianceSnapshot.fixRate`)이 이 헬퍼를 공유해, 두 곳이
  no-findings 를 다르게 처리하던 드리프트를 구조적으로 차단한다(같은 스냅샷 score↔fixRate 정합).
- 종합 현황 화면의 '해당없음' 표기는 유지 — 표시용 라벨이며 이미 0% 로 오표기하지 않는다(의미상 만점과 동치).

## 호환성·영향
- 무회귀: `fixFindings > 0` 인 일반적 상황(발견이 있는 기간)의 조치율은 종전과 동일(`complianceKpiPct`).
  달라지는 것은 발견 0건 기간의 스냅샷 fixRate 뿐(0 → 100) — 이는 교정(fix 축·점수와 일치).
- 포스처 fix 축은 값이 불변(이미 100 로직) — 헬퍼로 표현만 단일화. 점수 산출 불변.

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt · keycheck · health · **e2e 97**(신규 sc_compliance_fixrate_clean).
- `sc_compliance_fixrate_clean`: 격리(보안성검토·스냅샷·감사 비움)로 스냅샷 기록 → 유일 '컴플라이언스 스냅샷'
  감사에 '조치 100%' 기록(발견 0건=만점) 확인. 스냅샷 fixRate 를 `complianceKpiPct(k.fixDone, k.fixFindings)`
  로 되돌려 재빌드 시 '조치 0%'로 단언 실패함을 실측 대조(fails-without-fix).
