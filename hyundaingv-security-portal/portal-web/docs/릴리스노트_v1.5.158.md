# 릴리스 노트 — portal-web v1.5.158

이 릴리스는 인프라 운영의 **가동 상태를 한눈에** 보이게 한다. 지금까지 배치 실패·인터페이스 오류·디스크
경고는 각각 운영 화면·시스템 화면 안에서만 계산돼, 대시보드나 경영 보고용 종합 현황에서는 인프라가 전혀
보이지 않았다. "지금 뭔가 잘못됐나"를 판단하려면 화면 두 개를 따로 열어야 했다. 이제 세 신호를 단일 원천
헬퍼로 모아 대시보드 스냅샷과 IT 운영 종합 현황에 함께 노출한다. 전 게이트가 그린이다.

## 주요 변경

### 인프라 헬스 단일 원천
새 `lib/infra.ts` `computeInfraHealth(s)` 가 세 가지 운영 헬스 신호를 한 곳에서 산출한다: 배치 최근 실행
실패(`lastResult === '실패'`), 인터페이스 오류(`status === '오류'`), 디스크 경고(사용률 > 임계). 임계값
`DISK_WARN`(85%)도 여기서 export 해, 시스템 화면이 상수를 재정의하지 않고 공유한다. 데이터는 전부 in-store라
연동이 필요 없다.

### 중복 제거 — 화면이 헬퍼를 소비
운영 화면(배치·인터페이스)과 시스템 화면(디스크)이 각자 인라인으로 세던 계산을 헬퍼 호출로 바꿨다.
이로써 화면·대시보드·export 가 같은 술어를 공유해 수치가 어긋날 여지를 없앴다(컴플라이언스·재무와 동일 패턴).

### 대시보드·산출물 노출
- 개인별현황 전사 운영 스냅샷: **배치 실패·인터페이스 오류·디스크 경고** 타일을 더했다. 각 타일은 출처
  화면의 유효권한으로 게이트한다 — 배치·인터페이스는 운영 화면, 디스크는 시스템 화면 기준(교차도메인
  게이트 일관성).
- IT 운영 종합 현황 export: **인프라 운영** 행(배치 실패·IF 오류·디스크 경고 + 전체 대수)을 더해, 관리
  리포트가 인프라까지 포괄한다.

## 호환성·영향
- 무회귀: 신규 신호로 기존 KPI·동작 불변. 화면 stat 값은 리팩터 전과 동일(같은 술어를 헬퍼로 옮겼을 뿐).
- 저장 스키마 변경 없음 — 기존 store 필드(`batchJobs.lastResult`·`interfaces.status`·`servers.diskUsedPct`)로 산출.

## 검증
- 게이트 전량 그린: build · smoke 579 · a11y 698 · emptystate/corrupt 38 · keycheck 3 · health 48 · e2e 70.
- e2e `sc_infra_health`: 대시보드 인프라 타일 값이 **출처 화면 stat 과 일치**함을 실브라우저로 대조(단일
  원천 증명)하고, IT 운영 종합 export 의 인프라 행을 확인. smoke: 종합 export 인프라 헬스 행 needle.
