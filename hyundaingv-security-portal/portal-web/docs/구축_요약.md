# 전사 IT·보안 거버넌스 포털 — 구축 요약

제품안내서(`전사_IT보안_거버넌스포털_제품안내서.pdf`, 17p)와 요구사항 원본(`sample.xlsx`:
메뉴체계 84행 · 결재 14건 · 첨부 32지점)을 구현 스코프로 한 웹 포털이다. 특정 고객사에
하드코딩하지 않는 재사용 프레임워크로 설계되어, 고객사 프로필과 어댑터 교체만으로
다른 고객사에 배포할 수 있다.

## 구현 범위

10대 업무 도메인의 37개 화면이 구현되어 있다 (35개 요구 화면 + 감사 이력 +
통합 검색 — v1.1.5 랙·H/W 관리 포함). 모든 업무는 공통 전자결재·권한관리·공통코드·첨부 기반 위에서 폐쇄 루프
(신청 → 결재 → 처리 → 집계)로 동작하며, 결재는 상세 확인 → 승인/사유 반려 →
보완 재상신과 기안자 상신취소(회수), 다단(2단) 결재까지의 전체 생명주기를 갖는다.

| 도메인 | 화면 | 핵심 폐쇄 루프 |
|--------|------|----------------|
| Main | 개인별현황·공지·QnA | 관리대상 현황 포틀릿, 전사 운영 스냅샷(담당), 필독·답변 |
| IT 투자/비용 | 투자·비용·자산등록 | 경영계획→확정→계약→정산품의 결재→지급완료→계획대비실적, 속보 기준금액(정산>계약>계획), 자산관리 API 등록번호 취득 |
| IT Request | 신청·내역·CI·관리·지연 | 신청(첨부)→결재→CI 배정→개발/처리→완료. 유형별 분기: 시스템개발은 테스트·적용요청을 거쳐 변경관리 최종완료 시 완료 전파, 데이터·계정/권한은 처리→완료 직행. 결재 없는 건은 CI 직접 접수(보안/업무 구분)→처리 이력 |
| 인프라 운영 | 시스템·랙/H·W·운영·장애·변경 | 랙·H/W CRUD(사용중 삭제 가드)→랙구성도(랙→H/W→서버→시스템→배치·인터페이스 도식), 장애 등록→조치→통계 결재상신→향후대책, 변경 계획/결과 2단 상신, 상신 시 엑셀양식(XT) 자동첨부, SR 적용요청 편입, 디스크 경고·배치 재실행 |
| 프로젝트 | 현황·일정·보고 | 계약 연동 등록, 진척 100%→완료, 산출물 점검·이슈, 주간보고, 참여 서약(특별서약서-프로젝트) 집계 |
| 임직원 의식제고 | 서약 4화면·재택·출력물·위반 | 양식 개정→전원 재서약 재산출→안내메일·할일 재생성, 특별/협력업체 서약, 부서 서약 현황 결재상신, 재택 대상자 명단(일자별 등록·CSV 업로드·기간별 조회)→체크리스트·알림 스코핑, 출력물 일배치 이관→본인 폐기→결재, 위반 확인서(본인 상신) |
| 보안 컴플라이언스 | 교육·점검 | 명단 등록→할일 자동 마감→이수현황, ISMS 기준관리(대·중분류 등록·CSV 업로드·엑셀, 참조 중 삭제 가드)→계획→결과 결재→현황판 |
| My Work | 할일·결재함 | 결재 승인·반려가 참조 업무 상태로 전파(전 문서 유형), 반려는 기안자 '재상신' 할일로 순환(방치 시 일일 안내메일), 재상신 문서 상세에 이전 회차 반려 이력 표시, 대기 문서는 기안자가 상신취소(회수) — 참조 업무를 상신 이전 상태로 복원 |
| 환경설정 | 6화면 | 결재선(전 상신 액션의 단일 원천)·공통코드(장애등급 실소비)·권한 매트릭스·엑셀양식·감사 이력 |
| 기타(기반) | 연동·인프라 | 채널 토글·HR 동기화·발송/배치 이력 |

## 아키텍처

Next.js(App Router) 풀스택 데모다. 실서비스에서는 스토어가 MS-SQL로, 목업 어댑터가
고객사 시스템 연동으로 대체된다.

핵심 모듈은 다음과 같고, 각각이 단일 원천이다.

- `components/chrome/menus.ts` — 메뉴 체계 × 권한그룹. 내비 렌더링, 서버사이드 가드
  (`requireMenu` — 전 화면이 역할 목록을 중복 선언하지 않고 이 파일에서 도출), 권한
  매트릭스 화면, 스모크 스위트가 모두 이 파일 하나를 따른다. 런타임 제한(`menuOverrides`)은
  축소 전용 오버레이로, 메뉴권한 화면에서 토글한다.
- `lib/approvals.ts` — 결재 상신 공통 로직. 문서 유형별 기본 결재선(환경설정에서 유지보수 — 1차·선택 2차)에서
  결재자 체인을 해석하고, 단계별 자기 결재를 차단하며, 결재자에게 '결재' 할일을 만든다.
  중간 승인은 다음 결재자로 회부되고 업무 전파는 최종 승인만 한다.
  승인·반려의 업무 상태 전파는 `app/(app)/work/approvals/actions.ts`에 문서 유형별로 모여 있다.
- `lib/store.ts` — globalThis 싱글턴 인메모리 스토어. `PORTAL_DATA_FILE` 설정 시
  디바운스 저장(tmp→rename)으로 파일 영속화되고, 구버전 부분 파일은 시드 위에 머지해
  새 컬렉션·채널 기본값이 보전된다.
- `lib/integrations/` — 어댑터 계층. `types.ts`가 계약(메시징·HR·자산·보안자료),
  `mock.ts`가 데모 구현, `registry.ts`가 채널 상태 게이트(중지 채널은 호출 없이 실패 반환)·
  `resolveAdapter`(id 해석), `conformance.ts`가 자가진단(프로필 구조 정합·전 프로필 바인딩 완결성·계약
  적합성 — 고객사 어댑터 투입 전 통과 게이트, 연동·인프라 화면에 노출)이다.
- `lib/attachments.ts` — 공통 첨부. 업무 문서 번호(refId) 하나로 업무 화면과 결재함이
  같은 첨부를 본다. 실파일 업로드를 받아 크기·파일명을 서버에서 재검증한다.
- `lib/audit.ts` — 통제 행위 append-only 감사 로그 (결재 상신·승인·반려, 결재선·채널·코드
  변경, 양식 개정, 배치·이관 실행) — 결재 생명주기 전 구간이 추적된다.

## 고객사 커스터마이징

고객사 전환은 빌드 없이 환경변수로 한다 — 한 번 빌드한 이미지가 여러 고객사 프로필을
담고, `PORTAL_PROFILE` 로 선택한다(예: `PORTAL_PROFILE=manufacturer`). 브랜딩(타이틀바·
상태바·로그인)과 연동 채널 구성이 통째로 바뀐다.

새 고객사 온보딩은 세 단계다.

1. `profiles/` 에 구성 파일 추가 — 브랜딩과 채널 바인딩(채널 → 어댑터 id → 기본 활성).
2. `lib/integrations/` 에 고객사 어댑터 구현(REST API·DB 연계·SAML) 등록.
3. `portal.config.ts` 선택지에 프로필을 올리고 환경변수로 기동.

제조업 예시(`profiles/sample-manufacturer.config.ts`)는 SMS 채널을 제거하고 자산관리를
ERP 내장 모듈로 바인딩하는 구성으로, e2e 스위트의 `profile` 시나리오가 브랜딩 전환부터
어댑터 실동작까지 자동 검증한다.

구체적인 코드 예시(어댑터 구현·registry 등록·프로필 작성)와 오류·타임아웃 계약은
[`docs/어댑터_연동_가이드.md`](어댑터_연동_가이드.md)에 단계별 런북으로 정리했다.

## 품질 게이트

배포 전 `npm run gates` 한 명령으로 6단(+정보성 부하) 게이트를 모두 돌린다:
빌드 → 스모크 → 접근성 → 데이터 견고성 → 세션 격리 → 헬스 → e2e (+ `npm run load` 정보성).

- **스모크** (`npm run smoke`) — 프로덕션 서버를 띄우고 568개 체크: 라우트 × 권한 매트릭스 전수
  (허용→200, 차단→리다이렉트), 데이터 스코핑(본인/부서/전사) 긍·부정 검증, SSR 본문,
  결재 문서 상세 접근 통제, 세션 위조·만료 거부, 보안 헤더 5종(X-Frame-Options·
  nosniff·Referrer-Policy·CSP·Permissions-Policy), CSV 내려받기 권한·스코핑.
- **접근성** (`scripts/a11y.mjs`) — 전 화면 SSR 정적 검사 694체크: 폼 컨트롤·버튼 접근가능 이름,
  제목 계층(h1 1개)·본문 바로가기, img alt, lang, 토큰·상태색 대비(≥4.5:1), 라이브 리전.
- **데이터 견고성** (`scripts/emptystate.mjs`) — 빈 스토어(첫 배포)와 손상 파일(타입 오염) 2회
  기동으로 전 37화면 200·무크래시 + 정상 키 머지를 검증한다.
- **세션 격리** (`scripts/session_keycheck.mjs`) — 커스텀 `SESSION_SECRET` 세션만 통과·타 키 거부.
- **헬스** (`scripts/client_health.py`) — 실제 브라우저로 47화면(관리자 전 화면 + 사용자 분기 +
  모바일 뷰포트)을 로드해 콘솔 오류·하이드레이션 크래시·가로 오버플로를 잡는다.
- **e2e** (`scripts/e2e_suite.py`) — 핵심 폐쇄 루프 34시나리오를 실제 브라우저로 검증한다:
  서약 제출·양식 개정 재산출(당일 개정 무효화)·프로젝트 서약 과다계수·비-일반 재서약 교차마감,
  SR 생명주기(첨부·반려·재상신·CI 처리 할일)·전체 개발 사슬·상신취소, 회전참조 동시 반려,
  정산 재상신, 어댑터 채널 토글·일배치 이관·예외/타임아웃 내성(폴트주입), 공통코드→업무 선택지
  반영, 결재선 변경, 메뉴권한 런타임 제한, 스케줄러 자동 발화, 404·ChunkReload 복구, 고객사
  프로필 스위칭(2종), 상신 묶음 번호 재사용 금지, 데이터 파일 영속화·백업, 그리고 크래프트
  데이터로 재현하는 회귀군(교육 orphan 이수율·재무 집행률·year 필터·export kind 스코프).
  시나리오마다 독립 서버(시드 초기화)를 쓴다.

## 배포

단일 컨테이너는 `Dockerfile`(KST 시간대, `/data` 볼륨 영속화), nginx 리버스 프록시 포함
구성은 `deploy/docker-compose.yml`을 쓴다. 버전별 변경 이력은 `README.md`의 단계 표를 참고한다.
운영자용 배포 절차(비밀값 생성·환경변수·HTTPS·백업/복구·헬스체크·롤백·체크리스트)는
[`docs/배포_운영_가이드.md`](배포_운영_가이드.md)에 런북으로 정리했다.
