# 릴리스 노트 — portal-web v1.5.223

인프라변경 등록(addInfraChange)에 이중 등록 방어 가드를 더했다. 서버액션 폼은 제출 후 자동 비활성화되지
않아 '등록' 더블클릭 시 동일 변경이 두 벌 생겼는데, 이 클래스는 codebase가 이미 다른 등록 액션(createSr·
receiveCiSr·부서서약 상신)에서 가드하고 있었고 addInfraChange만 누락돼 있었다.

## 배경 — 발견 경위

등록 액션의 이중 제출 가드 정합성을 점검하던 중 발견했다. createSr("중복 제출 방어 — 상신 폼 이중 클릭 시
동일 SR·결재·할일이 두 벌 생긴다")·receiveCiSr("이중 접수 방지")·부서서약 상신은 모두 dedup 가드가 있으나,
addInfraChange는 매 호출 새 ChangeWork를 unshift할 뿐 중복 검사가 없었다. 더블클릭·재전송 시 같은 제목의
변경이 2건 생겨 각자 계획결재→결과결재 워크플로를 밟는 데이터 중복이 발생한다.

## 주요 변경
- `app/(app)/infra/changes/page.tsx` `addInfraChange`: 같은 제목의 미상신(작업등록) 인프라 변경이 이미 있으면
  직전 제출의 중복으로 보고 무시하는 가드 추가(createSr·receiveCiSr 와 동일 패턴 — 단일 스레드에서 POST#1이
  먼저 삽입한 뒤 POST#2의 이 검사가 잡는다).

## 호환성·영향
- 무회귀: 이중 등록만 차단. 서로 다른 제목의 변경, 상신 후(작업등록승인 등) 같은 제목 재등록은 영향 없음.
  addDevChange(SR 편입)는 이미 srNo 중복 가드 보유.

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt · keycheck · health · **e2e 87**(기존
  sc_infra_rollback_plan 시나리오에 이중 등록 단언 추가 — 시나리오 수 불변).
- `sc_infra_rollback_plan` 확장: 같은 제목을 재등록해도 변경 목록에 1건만 유지됨을 검증. 가드 제거 시 2건이
  생겨 단언이 실패함을 대조 확인(테스트 유효성).
