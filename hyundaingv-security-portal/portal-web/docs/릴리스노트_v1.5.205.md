# 릴리스 노트 — portal-web v1.5.205

이 릴리스는 재사용 프레임워크의 **산업 확장**을 한 단계 더 증명한다 — 세 번째 예시 고객사 프로필
(금융권, `finance`)을 더했다. 제조업(`manufacturer`)·공공기관(`public`)에 이어, 포털 본체 코드를 한 줄도
고치지 않고 프로필 구성과 `fin-*` 어댑터 등록만으로 세 번째 산업 토폴로지가 그대로 뜬다. 전 게이트가 그린이다.

## 주요 변경

### 세 번째 예시 프로필 — 금융권(`finance`)
`profiles/sample-finance.config.ts` — 브랜드(나래금융 예시·NARAE FIN PORTAL)와 채널 토폴로지를 정의한다.
금융권 특성을 반영해:
- 문자(SMS)를 **OTP·이상거래·경과 알림**용 별도 실채널로 유지(공공과 같은 축, 제조업과 대비).
- 보안·출력물 관제(secdata)를 **기본 가동** — 개인정보·출력물 통제가 강한 규제 대상.
- 전 채널 `adapterId`를 `fin-*`로 신규 부여.

레지스트리 등록 두 곳만 손댔다: `profiles/registry.ts`(프로필 등록)와 `lib/integrations/registry.ts`
(`fin-mail`·`fin-sms`·`fin-hr`·`fin-asset`·`fin-secdata` → 목업 매핑, 실배포 시 고객사 구현으로 교체).
포털 본체·화면·비즈니스 로직은 **무변경**이다.

### 왜 세 번째인가
두 개면 "우연한 비결합"을 의심할 여지가 남는다. 서로 다른 세 산업(제조·공공·금융) 토폴로지가 본체 무변경으로
뜨고, 어댑터 계약 자가진단이 **네 프로필 전부 적합**으로 확인되면, 커스터마이징 표면이 프로필·어댑터 계층으로
확실히 격리됐음을 보인다(제품안내서의 "고객사별 커스터마이징 = 프로필 교체 + 어댑터 구현" 주장의 실증).

## 호환성·영향
- 무회귀: 신규 프로필 추가만. 기존 프로필(default·manufacturer·public)·본체 동작 불변. 기본 프로필은 그대로.
- 자가진단: `finance` 채널의 `fin-*` 어댑터를 레지스트리에 등록했으므로 자가진단이 전 프로필 적합을 유지한다
  (미등록 시 자가진단 red — 등록으로 정합).
