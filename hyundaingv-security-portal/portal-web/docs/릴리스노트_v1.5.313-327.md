# 릴리스 노트 — portal-web v1.5.313 ~ v1.5.327

**보안 하드닝·이력추적성·화면-산출물 정합 아크.** 요구 소스가 소진된 뒤 프레임워크 무결성 축에서
전진한 릴리스 묶음이다. 세션 쿠키·SSO 인증의 fail-closed 강화, 감사 로깅 커버리지, 어댑터 장애 내성
테스트, 그리고 공식 산출물(엑셀·CSV)이 화면과 어긋나던 집계 드리프트를 마감했다. 게이트 e2e 는
115 → 124 시나리오로 늘었고 전 구간 그린이다.

## 배경 — 발견 경위

적대적 보안 리뷰의 잔여 배포 caveat, 도메인 심층 감사(장애관리·PMO), 교차 관심사 스윕(감사 로깅
커버리지·화면-vs-export 정합·연도 리터럴 완전성)에서 나온 실결함과 하드닝 항목을 순차 마감했다.
모든 수정은 fails-without-fix(수정을 되돌려 테스트가 실제로 실패하는지 실측)로 검증했다.

## 주요 변경

### 보안 — 인증·세션 fail-closed
- **v1.5.313 세션 쿠키 `Secure` 프로덕션 기본 활성.** `cookieSecure()` — 프로덕션은 기본 활성(HTTPS 종단
  전제), `PORTAL_COOKIE_SECURE=0` 으로만 해제(http 데모·게이트). 로그인 서버액션·SSO ACS 발급에 적용.
  Next 는 전송로와 무관하게 Set-Cookie 에 `Secure` 를 emit 하므로 http 게이트에서 raw 헤더로 검증 가능
  (HTTPS 프록시 불필요). e2e `sc_cookie_secure`.
- **v1.5.315 SSO subject 매핑 fail-closed.** `PORTAL_SSO_SUBJECT_MAP`(subject=login) 설정 시 그 매핑이
  유일한 신원 근거이고 미등재 subject 는 거부한다. IdP subject 네임스페이스가 로컬 로그인과 달라 문자열
  일치만으로 권한 계정(admin 등)에 잘못 매핑되는 것을 막는다. 미설정 시 NameID 직접대응(하위호환).
  e2e `sc_sso_subject_map`.
- **v1.5.325 SSO subject 매핑 오설정 하드닝.** '매핑 설정됨'을 파싱 성공(map≠null)으로 판정하던 것을
  '변수 존재(raw)'로 변경 — 설정됐으나 형식 오류로 유효 쌍이 0개여도 NameID 직접대응으로 폴백하지
  않는다(폴백=오설정이 더 느슨한 매칭으로 새는 fail-open). e2e `sc_sso_subject_map_malformed`.

### 어댑터 경계 내성 — 결함 4종 소비자 레벨 커버리지
- **v1.5.317 자산·secdata 어댑터 throw/hang 소비자 테스트.** 결함 4종(미연동·throw·hang·계약위반)
  방어의 소비자 레벨 테스트를 완성했다. 코드 가드는 이미 건전(withTimeout·try/catch·`.catch(()=>[])`)했으나
  throw/hang 소비자 e2e 가 인사·보안관제에만 있었다. `mockAsset.searchAssets`·`mockSecdata.fetchPrintouts`
  에 결함 주입 훅 추가 + `adapter_asset_throw/hang`·`adapter_secdata_throw/hang`. secdata 는 서버액션 POST
  상태로 500 을 검출(후속 GET 은 정상이라 재네비게이션만으론 미검출).

### 이력추적성 — 감사 로깅 커버리지(§VI)
- **v1.5.319 장애관리·화면정의서 감사 갭 + 연도 리터럴.** 장애(사고) 등록·조치완료·재발방지 결과 등록이
  무기록·등록자 필드 부재였으나 인프라 형제 화면(systems·racks·operations)은 모두 감사 → `장애 등록`·
  `장애 조치` 감사 추가. settings/menus 화면 정의서 파괴적 교체(ADMIN)가 설정 도메인 유일 무기록 →
  `화면 정의서 변경` 추가. work/approvals 부서서약 상세의 `p.year==='2026'` 리터럴 → `currentYear()`
  (연차 컴플라이언스 리터럴 버그의 7번째 소비처). e2e `incident_audit`.

### 화면-산출물 정합 — 공식 대장이 화면과 어긋남
- **v1.5.321 PMO 참여서약 export 드리프트 + 집행률 거짓 100%.** 프로젝트 참여서약 export 가 빈 명단
  (`members=[]`, 파일 재로딩이 undefined→[] 로 정규화)을 bare `p.members ?` 로 판정해 `[].filter=0` 을
  내보내 화면 signedCount(length 판정)와 어긋났다 → 화면과 동일 판정으로 정합. 재무 집행률이 Math.round
  로 99.5~99.9% 미집행을 100% 로 올려 '완전 집행'을 거짓 표기하던 것을 캡(compliance·risk 의 거짓100
  방지 규약과 정합, 초과는 실값 유지). e2e `project_emptymembers_signcount`(export 단언 확장)·
  `finance_exec_false100`.

### 배포 문서 정합
- **v1.5.323 `.env.example` 실 REST 어댑터 변수 참조.** 배포 환경변수 참조가 실 연동 프로필의 REST 어댑터
  변수(HR·자산·전자결재·보안관제·출력물)를 누락 → 채널별 대표 변수 요약 + `docs/어댑터_연동_가이드.md`
  매트릭스 포인터(중복 미기재로 드리프트 방지).
- **v1.5.327 배포 운영 가이드 쿠키 Secure 현행화 + SSO 매핑.** 운영 가이드가 v1.5.313 이전 `PORTAL_COOKIE_SECURE`
  의미(=1 로 켬, 기본 0)로 스테일 → 프로덕션 기본 활성·=0 으로만 해제로 현행화(6곳). 스테일 런북은
  운영자가 프로덕션에서 실수로 =0(Secure 해제)하게 만들 수 있는 리스크였다. `PORTAL_SSO_SUBJECT_MAP`
  문서화.

## 검증

- 게이트 전량 그린(전 릴리스): build · smoke · a11y · emptystate/corrupt(41/41) · keycheck(4) ·
  health(51) · **e2e 115→124**(신규 시나리오: cookie_secure · sso_subject_map · sso_subject_map_malformed ·
  adapter_asset_throw/hang · adapter_secdata_throw/hang · incident_audit · finance_exec_false100).
- 모든 코드 수정에 fails-without-fix 실측(수정 되돌려 테스트 실패 확인).
- **검증 클린(무결함)으로 확인된 축**: de-AI 디자인 패스(플레이라이트 스크린샷 — 인라인 SVG 아이콘·단일
  뮤트 액센트·조밀 테이블·실 푸터, AI 흔적 없음), 화면-vs-export 전 타입 정합 감사(공유 헬퍼·동일 로직),
  SR 생명주기 도메인 감사(상태 가드·스코핑·집계 단일원천·퇴사 CI 유령 없음).

## 호환성·영향

- 무회귀. 쿠키 Secure 는 프로덕션 기본 활성이나 http 게이트·데모는 `=0` 로 유지, 로그인 정상. SSO subject
  매핑은 미설정 시 기존 NameID 직접대응 유지(하위호환). 어댑터 결함 훅·감사 어휘 추가는 기존 동작 무영향.
