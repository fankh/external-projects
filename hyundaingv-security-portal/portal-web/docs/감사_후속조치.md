# 적대 감사 후속조치 (미조치 잔여 항목)

v1.5.x 에서 9개 핵심 서브시스템(결재·영속화·SR/변경·컴플라이언스·재무·보안의식·인프라·
게시판/설정, 그리고 직전 델타)을 적대적으로 감사해 확정 결함을 전수 수정했다. 아래는 감사가
찾은 저심각·잠재 항목의 처리 현황이다. 전부 상태 불일치·데이터 손상이 아니라 알림/가시성/
정합성 성격이며, portal-web 은 본 트랙 단독 소유다(병렬 v1.24x~ 트랙은 별개 프로젝트
`seekerslab-itam/itam-web` 소속으로 portal-web 파일을 건드리지 않는다).

**#1·#3 은 조치 완료(v1.5.31·v1.5.32).** 남은 #2·#4·#5 는 데이터 모델/제품 결정이 필요하거나
현재 트리거 불가한 휴면 사안이라, 임의 구현 대신 결정을 위해 남겨 둔다.

| # | 상태 | 위치 | 내용 | 심각도 | 비고 / 권장 조치 |
|---|:---:|------|------|:---:|-----------|
| 1 | ✅ v1.5.31 | `work/approvals/actions.ts` | SR 신청 승인이 `'SR 처리'` 할일을 안 만들어 `assignCi` 마감 루프가 반쪽이었음. | 저 | 승인 시 업무담당(BIZ_MGR)에게 할일 생성(시드 TD-104 형태), assignCi 가 마감. e2e sr 회귀테스트 추가. |
| 2 | ⏸ 결정 필요 | 서약 상태 판정 전 화면 | 서약 유효 판정 `signedAt >= revisedAt` 가 **날짜 단위** 라, 같은 날 개정 전 서명이 유효로 남아 재서약을 안 하게 된다(당일 창). | 저~중 | 전 화면 **동일 규칙**이라 화면 간 불일치는 아님. 근본 해결=`signedAt`/`revisedAt` 타임스탬프 승격 + `>` 비교(비교 지점 다수·시드 영향). **재서약 당일 정밀도가 요구될 때 제품 결정으로 진행.** |
| 3 | ✅ v1.5.32 | `dashboard`·`work/approvals`·`notify` | 일반 서약 집계 3곳에 `year` 필터 누락(다른 뷰는 있음) — 레거시 데이터 파일에서만 갈리는 잠재 불일치. | 저(latent) | 세 곳에 `p.year === '2026'` 추가해 전 뷰 정합. |
| 4 | ⏸ 설계 결정 | `pledge/manage` (`reviseForm`) + `notify` | 비-일반 양식(관리책임자·재택·특별·프로젝트) 개정은 서명을 무효화하나 재서약 할일·리마인더가 없다(일반만 있음). | 저 | 코드 주석상 **의도(일반=연례 전직원 서약이 1차 의무, 그 외 상황형)** 로 보임. 유형별 재서약 리마인더가 정책상 필요하면 대상자(프로젝트 참여자·관리책임자 등) 산정 로직과 함께 확장 — **제품 결정 사안.** |
| 5 | ⏸ 휴면 | `awareness/prints` (`submitDiscards`) | 개인 폐기 제출이 부서 취합 할일(시드 TD-103)까지 닫을 수 있음. | 매우 저(휴면) | `printouts` 시드가 비어 현재 트리거 불가. 개인 폐기용 할일 모델이 아직 미정 — 정정 시 개인/부서 취합 할일을 제목·참조로 구분. 데이터가 채워질 때 함께 설계. |

> 참고: 확정 결함(수정 완료)과 감사 범위는 `docs/구축_요약.md`·커밋 이력(v1.5.14~30) 참조.
