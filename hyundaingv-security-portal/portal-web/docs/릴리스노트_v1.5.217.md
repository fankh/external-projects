# 릴리스 노트 — portal-web v1.5.217

보안위반 사실확인서의 **결재제외자 별도관리**를 구현했다. 요구사항(sample.xlsx)은 "결재제외자는 별도 관리
— 확인서 징구 후 스캔해서 증빙으로 업로드"를 명시하나, 기존에는 모든 위반이 위반자 본인의 온라인 확인서
결재 경로 하나만 탈 수 있어, 녹스계정 없는 위반자(온라인 결재 불가)의 위반이 징구중 상태로 방치됐다.

## 배경 — 요구사항 대비 갭

sample.xlsx 보안위반관리는 두 경로를 요구한다:
- 일반: 위반자 본인이 확인서 작성 → 부서장 결재 → 완료.
- 결재제외: 녹스계정 없어 온라인 결재가 불가한 위반자는 "확인서 징구 후 스캔해서 증빙으로 업로드"하는 별도
  관리.

기존 구현은 첫 경로(submitStatement → draftApproval)만 있었다. 등록 시 스캔 증빙 업로드는 있었으나(등록
첨부), 그것으로 위반을 완료 처리하는 경로가 없어 결재제외 위반은 영구 징구중이었다.

## 설계 결정 (검토 요망)

스펙이 모델링을 못박지 않아 다음을 택했다(리뷰 시 확인):
- **결재제외를 위반 단위 처리로** 모델링했다(사람 속성 아님) — 위반별로 온라인 결재 가능 여부가 갈리고, 본
  코드베이스가 레코드 단위로 상태를 관리하기 때문. `Violation.exempt?: boolean` 플랫 필드.
- **스캔 업로드가 결재를 대신한다** — 업무담당자가 스캔 확인서를 올리면 위반이 징구중 → 완료로 직행하며
  draftApproval 을 타지 않는다("별도 관리"의 해석).

## 주요 변경
- **lib/types.ts**: `Violation.exempt?: boolean` 추가(결재제외 별도관리 완료 표식).
- **awareness/violations/page.tsx**: `closeExempt` 서버 액션(BIZ_MGR/ADMIN) — 징구중 위반에 스캔 증빙 필수
  업로드 → 완료+exempt, 결재 미생성, 감사 기록. 위반 내역 표에서 업무담당자가 '위반자 본인 작성 대기' 건에
  스캔 업로드로 '결재제외 완료(스캔)' 처리, 완료 시 결재제외 칩 표시.
- **api/export/route.ts**: 위반 export 에 '처리구분'(결재제외(별도관리)/결재) 열 추가.

## 호환성·영향
- 무회귀: exempt 는 선택 필드. 기존 위반·일반 결재 경로 불변. 스캔 없이는 완료 불가(증빙 필수 가드).

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt · keycheck · health · **e2e 86**.
- e2e `sc_violation_exempt`: 격리 데이터에서 업무담당자가 위반 등록(징구중) → 스캔 확인서 업로드 → 결재제외
  완료 검증, 결재함에 확인서 결재가 생기지 않음을 확인(별도관리 = 결재 미경유). 상태 칩만 검사해 버튼 라벨
  오탐을 배제했고, 완료 처리 제거 시 실패함을 대조 확인(테스트 유효성).
