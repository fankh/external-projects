# 릴리스 노트 — portal-web v1.5.301

**SSO(SAML) 어댑터 계약 + 참조 구현 — 전 채널 종류 계약화 완료.** 마지막 남은 planned 채널인 SSO 에
어댑터 계약(`SsoAdapter`)을 정의하고, SP-initiated 로그인 리다이렉트 생성 + IdP SAMLResponse 서명 검증
로그인의 참조 구현을 붙인다. 이로써 계약이 정의된 어댑터 종류가 8종 전부가 됐다.

## 배경 — 발견 경위

요구사항: "SSO구현 — SAML 적용 (Knox portal 연동)". SSO 채널은 planned(계약 미정의)로만 존재했다. 계약을
정의하고 실 crypto(RSA-SHA256) 검증을 갖춘 참조 SP 구현을 붙여, 프레임워크가 SAML IdP 와 연동될 수 있음을
실증한다.

## 주요 변경
- `lib/integrations/types.ts`: `SsoAdapter` 계약 — `loginRedirect(relayState)→{url}`(SP-initiated,
  부작용·네트워크 없음)·`verifyResponse(samlB64)→SsoAssertion`(서명·조건 검증, 실패 시 throw) + `SsoAssertion`.
- `lib/integrations/saml.ts`(신규) `samlSso` 참조 구현:
  - loginRedirect — 실 AuthnRequest XML + DEFLATE + base64 + urlencode(HTTP-Redirect 바인딩).
  - verifyResponse — `node:crypto` RSA-SHA256 로 어설션 서명 검증 + 조건(NotOnOrAfter 만료·Audience·Issuer)
    + NameID·속성 추출. IdP 인증서는 `PORTAL_SAML_IDP_CERT`(PEM)·`PORTAL_SAML_IDP_CERT_FILE`(경로)로 주입.
  - 서명 범위: 어설션 직렬 바이트에 대한 RSA-SHA256(암호학적으로 실효). 실 배포는 XML-DSig(C14N) 전용
    라이브러리로 교체(계약 동일) — 문서화.
  - `mock.ts` `mockSso`(데모는 계정 선택 로그인 유지, verifyResponse throw).
- `app/api/sso/login`·`app/api/sso/acs`(신규 라우트): login 은 SP-initiated 리다이렉트, ACS 는 SAMLResponse
  를 POST 받아 검증 성공 + nameId→계정 매핑 시에만 세션 발급(인증 우회 불가). RelayState 는 로컬 경로만
  허용(오픈 리다이렉트 방지). 채널 미가동이면 로그인 화면으로 폴백(데모 불변).
- `registry.ts`·`conformance.ts`: `sso` 리졸버·`ssoAdapter()` + CONTRACTED 편입(자가진단은 부작용 없는
  loginRedirect 만 호출). 4개 프로필 sso 채널 planned 해제(데모→목업/샘플→samlSso).

## 호환성·영향
- 무회귀: 데모 기본 프로필은 목업(계정 선택 로그인 유지) — ACS 는 목업 verifyResponse throw 로 세션 미발급.
  자가진단은 loginRedirect 만 호출(안전). sso 계약화로 비계획 채널 7→8종·활성 5→6(데모 기본).

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt(41/41) · keycheck · health(51) · **e2e 114**.
- 신규 `sc_sso_saml`(금융 프로필·테스트 키쌍): SP-initiated 로그인 → IdP 리다이렉트(SAMLRequest). 테스트
  개인키로 서명한 어설션 → ACS → 서명 검증 통과 → 세션 발급 → 대시보드 접근. 변조 어설션(서명 불일치)은
  거부(세션 미발급). 서명 검증 무력화 시 변조 수용으로 실패 대조(fails-without-fix 실측). 채널 계수 e2e(6/8) 갱신.
