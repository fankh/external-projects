# 릴리스 노트 — portal-web v1.5.229

보안성 검토 export(security-reviews 관리대장)에 고위험 미조치 열을 더했다. 화면은 검토별 고위험(심각+높음)
미조치 건수를 우선 조치 신호로 표시하는데(v1.5.127), export는 발견·조치 총계만 담아 ISMS 감사 산출물에서
그 신호가 빠져 있던 화면-export 불일치를 닫는다.

## 배경 — 발견 경위

화면-export drift 계열(SR 상태 v1.5.221, 점검 팀장 v1.5.227)을 export 전반으로 훑던 중 발견했다. 보안성 검토
화면은 검토 행마다 `고위험 {highSevOpen}` 칩을 띄우고(v1.5.127 우선 조치 신호), 전사 '고위험 미조치' Stat도
있으나, security-reviews export는 발견·조치·조치율 총계만 담고 고위험 미조치는 없었다. 발견 총계에서 등급별
분해는 복원 불가라(발견 5건이 몇 건이 고위험인지 알 수 없다), 감사자가 CSV만으로는 어느 검토에 심각/높음
미조치가 남았는지 볼 수 없었다.

## 주요 변경
- `app/api/export/route.ts` security-reviews: '고위험 미조치' 열 추가(조치 다음), 값은 화면과 같은 store
  단일 원천 `highSevOpen(r)`(심각+높음 발견 − 심각+높음 조치). import 추가.

## 호환성·영향
- 무회귀: export 열 1개 추가. 화면·저장·집계 로직 무변경. highSevOpen 은 기존 단일 원천(화면·대시보드·
  컴플라이언스 종합 export 공유).

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt · keycheck · health · **e2e 87**(기존
  sc_security_review 시나리오에 export 단언 추가 — 시나리오 수 불변).
- `sc_security_review` 확장: 시드 SEC-2026-02(심각1/0·높음2/1 = 고위험 미조치 2)가 security-reviews export
  CSV에서 '고위험 미조치' 열·값 2로 나옴을 헤더 인덱스 파싱으로 검증. export를 그 열 없이 되돌리면 단언이
  실패함을 대조 확인(테스트 유효성).
