# 릴리스 노트 — portal-web v1.5.309

**세션 서명 키 미설정 시 프로덕션 기동 거부(fail-closed).** 적대적 리뷰가 '최고 영향 잠재 이슈'로 지목한
`SESSION_SECRET` 개발 기본값 폴백을 경고에서 하드페일로 격상한다. 프로덕션에서 공개된 개발용 서명 키로는
서버가 기동하지 않는다 — 위조 가능한 세션으로 운영이 뜨는 것을 원천 차단한다.

## 배경 — 발견 경위

`SESSION_SECRET` 미설정 시 소스에 있는 개발 기본키로 폴백하면 누구나 ADMIN 세션 쿠키를 위조할 수 있다.
기존에는 기동 시 콘솔 경고만 있어(무시 가능), 잘못 구성된 운영이 조용히 뜰 수 있었다. 리뷰 권고대로
경고 → 기동 거부(fail-closed)로 바꾼다.

## 주요 변경
- `instrumentation.ts`: 프로덕션(`NODE_ENV=production`) + `SESSION_SECRET` 개발 기본값이면 치명 로그 후
  `process.exit(1)` — 부팅 자체를 막는다. 게이트/데모는 서버 기동 시 비-기본 `SESSION_SECRET` 을 주입하므로
  이 경로를 타지 않는다.
- 게이트 인프라: 서버를 띄우는 전 게이트 스크립트(smoke·a11y·emptystate·client_health·e2e)가 비-기본
  `SESSION_SECRET`(미설정 시 `ngv-gate-nondefault-secret`)을 서버 env 로 주입 + 테스트 쿠키 서명 키를 일치.
  session_keycheck 는 이미 커스텀 키 사용.
- `lib/readiness.ts`: '세션 서명 키' 항목 상세를 '프로덕션 기동 거부'로 현행화.

## 호환성·영향
- 무회귀: 게이트·데모는 비-기본 키를 주입해 정상 기동. 운영은 `SESSION_SECRET` 설정 필수(미설정 시 기동
  거부로 즉시 인지). 개발 모드(`next dev`)는 영향 없음.

## 검증
- 게이트 전량 그린: build · smoke 632 · a11y · emptystate/corrupt(41/41) · keycheck(4) · health(51) · **e2e 114**.
- `session_keycheck` 신규 4번째 검사: 개발 기본 키 + 프로덕션 → 서버 기동 거부(부팅 후 미서빙) 확인.
  `process.exit(1)` 제거 시 기동·서빙되어 실패 대조(fails-without-fix 실측).
