# 릴리스 노트 — portal-web v1.5.311

**어댑터 fetch 취소 — 상한 초과 시 연결 중단(소켓 정리).** 적대적 리뷰가 지적한 마지막 실결함:
`registry.withTimeout` 은 대기 프라미스만 거부하고 실제 `fetch` 연결은 열린 채 남아, 무응답 고객 엔드포인트가
소켓을 계속 점유하던 문제를 닫는다. 전 REST 어댑터 fetch 에 `AbortSignal.timeout` 을 걸어 상한 시점에
연결까지 중단한다.

## 배경 — 발견 경위

`withTimeout(adapter.call(), ...)` 은 상한 시 프라미스를 거부하지만 그 안의 `fetch` 는 취소되지 않아, 응답이
지연/무응답인 고객 시스템에 대해 소켓이 상한 후에도 열려 있었다. 부하 시 hang 연결이 누적돼 소켓/커넥션
고갈로 이어질 수 있다. 리뷰 권고대로 요청 자체를 취소한다.

## 주요 변경
- `lib/integrations/rest.ts` `adapterSignal()`(신규): `AbortSignal.timeout(PORTAL_ADAPTER_TIMEOUT_MS, 기본 10초)`.
  전 어댑터 fetch 7곳(메일·문자·인사·자산 조회/등록·보안관제·출력물·전자결재)에 `signal` 적용 — 상한 초과 시
  fetch 가 abort 되어 연결이 정리된다(withTimeout 의 대기 거부와 이중 방어).

## 호환성·영향
- 무회귀: 정상 응답 경로 불변. 상한 초과 시 기존엔 프라미스만 거부됐으나 이제 연결도 취소된다(abort 예외는
  sendVia·수집 지점의 try/catch 가 기존과 동일하게 흡수).

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt(41/41) · keycheck(4) · health(51) · **e2e 115**.
- 신규 `sc_adapter_abort`(무응답 원시 TCP 프로브·낮은 상한 600ms): 알림 배치 발송 → 어댑터가 상한 시점에
  연결 종료(FIN) → 프로브가 recv 로 감지. `signal` 제거 시 소켓이 열린 채 방치되어 미감지로 실패 대조
  (fails-without-fix 실측). 쓰기 기반 감지의 TCP 버퍼링 불신뢰성을 피해 연결 종료를 직접 관찰.
