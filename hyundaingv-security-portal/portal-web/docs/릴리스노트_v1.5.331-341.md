# 릴리스 노트 — portal-web v1.5.331 ~ v1.5.341

**역량 강화 아크 — 발견·조치·계획.** 요구 소스와 결함 표면이 소진된 뒤, 이미 구현된 데이터를 실제
업무에 더 잘 쓰이게 하는 역량 축에서 전진한 릴리스 묶음이다. 감사관·운영자·컴플라이언스 담당이
'찾고(search)·바로 조치하고(drill-down)·미리 계획하는(schedule)' 흐름을 완성했다. 게이트 e2e 는
124 → 128 시나리오로 늘었고 전 구간 그린이다.

## 배경 — 발견 경위

직전 아크(v1.5.313~327)에서 보안 하드닝·이력추적성·화면-산출물 정합을 마감했다. 이후 도메인 심층
감사(SR·정책/DR)가 연속 무결함으로 돌아와 결함 광맥 소진이 확인되자, '결함 찾기'에서 '역량 빌드'로
전환했다. 각 항목은 실제 사용 흐름의 단절(신호는 있는데 조치로 못 감·기록은 있는데 못 찾음·경과는
보이는데 사전 계획 못 함)을 메운다.

## 주요 변경

### 발견 (Search)
- **v1.5.331 감사 이력 조회 필터.** 감사 화면(§VI 이력추적성)이 최근 500건 평면 목록뿐이라 감사관이
  '누가·무엇을·언제'로 증적을 찾을 수 없었다. `lib/audit.ts` `filterAuditLogs(logs, {actor,action,q,from,to})`
  단일 원천으로 화면·엑셀 export 가 같은 필터를 공유한다(감사관이 좁힌 뒤 그 조회분만 다운로드). GET
  필터 폼(행위자·행위 셀렉트=관측값·기간·검색어) + '조회 N/전체 M' 표시.
- **v1.5.333 · v1.5.335 통합 검색 커버리지 완성.** 통합 검색이 SR·게시판·계약·인프라·프로젝트·보안성
  검토만 다뤄, 전자결재 포털의 핵심인 결재 문서와 컴플라이언스 등록부를 못 찾았다. 전 거버넌스 엔티티를
  편입하되 **각 화면의 스코핑을 그대로 복제해 검색이 권한 우회 경로가 되지 않게** 했다:
  전자결재(신원 스코핑 — 기안자·결재자 본인 문서만)·위험평가·정책지침·정보보호 점검·재해복구·보안위반
  (본인 스코핑 — BIZ/ADMIN 전체, 그 외 본인 것만). 이제 '통합 검색'이 실제로 통합적이다.

### 조치 (Drill-down)
- **v1.5.337 대시보드 타일 드릴다운.** 전사 운영 스냅샷·개인 타일이 count 표시뿐이라 '조치중 장애 1' 을
  보고도 어느 건인지 보려면 메뉴로 수동 이동해야 했다(신호→조치 단절). `Stat` 컴포넌트에 optional href
  추가 — 있으면 타일 전체가 출처 화면 드릴다운 링크(호버는 표·메뉴와 동일 컨벤션), 없으면 기존 표시용.
  운영 18타일·개인 8타일이 각 출처 화면(장애→incidents·정책경과→policies·나의할일→todo 등)으로 이동한다.
  타일은 접근 게이트로만 노출되므로 링크 대상도 항상 접근 가능(깨진 링크 없음).

### 계획 (Schedule)
- **v1.5.339 · v1.5.341 다가오는 컴플라이언스 일정.** 대시보드가 컴플라이언스 '경과'(사후 count)만 보여줘
  ISMS 담당이 재검토·복구훈련·조치기한 도래를 사전에 계획할 수 없었다(반응적만·능동적 없음).
  `lib/schedule.ts` `upcomingComplianceItems(s, today, withinDays)` 단일 원천으로 향후 90일 내 도래분
  (정책 재검토·복구훈련·위험 조치기한)을 도메인 통합·기한순으로 산출한다(경과분은 제외 — 그건 경과 신호
  담당). 대시보드 카드(컴플라이언스 접근 역할·빈 경우 숨김)는 예정일·D-day(임박 warn)·구분·대상(출처
  화면 링크)을 보여주고, 엑셀 export(90일 창 전량, 컴플라이언스 미접근 역할 403)로 계획회의·감사 증적을
  내려받는다.

## 검증

- 게이트 전량 그린(전 릴리스): build · smoke · a11y · emptystate/corrupt(41/41) · keycheck(4) ·
  health(51) · **e2e 124→128**(신규: audit_search · search_coverage · dashboard_drilldown · compliance_schedule).
- 모든 코드 수정에 fails-without-fix 실측(수정 되돌려 테스트 실패 확인). 검색·집계 편입은 화면 스코핑을
  그대로 복제했는지 회귀로 확인(전자결재 무관 결재 유출 차단·보안위반 타인 미노출·일정 export 권한 403).
- 신규 UI(감사 필터 폼·컴플라이언스 일정 카드·드릴다운 타일)는 기존 컨트롤 클래스 재사용 + 플레이라이트
  스크린샷으로 디자인 정합 확인(AI 흔적 없는 인하우스 엔터프라이즈 톤 유지).

## 호환성·영향

- 무회귀. `Stat` href 는 옵셔널(기존 표시용 타일 무변). 검색·일정은 접근 가능 데이터만 노출하며 화면
  스코핑을 초과하지 않는다. 컴플라이언스 일정 카드·export 는 컴플라이언스 접근 역할에만 노출·허용.
