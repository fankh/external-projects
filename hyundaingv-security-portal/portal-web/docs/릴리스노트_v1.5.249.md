# 릴리스 노트 — portal-web v1.5.249

보안관제(secmon) 어댑터를 더해 연동 계층의 4번째 고객 시스템 범주(보안 모니터링)를 완성했다. 제품안내서
§V가 포털을 그룹웨어·인사/근태·자산관리·**보안 모니터링** 4종 고객 시스템과 어댑터로 연동하는 재사용
프레임워크로 정의하는데, 그동안 앞 3종(mail/approval/sso·hr·asset·secdata)만 어댑터가 있고 보안 모니터링은
비어 있었다. DLP·EDR·SIEM 탐지 이벤트를 보안위반(징구중)으로 자동 편입하는 secmon 어댑터를 목업·계약·
레지스트리·프로필·이관 로직까지 hr/secdata 와 동일 패턴으로 추가한다.

## 배경 — 발견 경위

방어적 자체 감사(결함 표면 소진 후)에서 PM 브리프의 핵심 산출물인 '어댑터/연동 계층'을 범주별로 대조하다
발견. 4개 명시 범주 중 보안 모니터링만 어댑터가 없었다. 포털 보안위반 유형(ViolationType: 출력물 방치·화면
미잠금·인가되지 않은 USB 사용)이 곧 DLP·EDR 이 탐지하는 사건이라, 탐지 → 위반 자동 등록이 자연스러운
연동점이다(수동 addViolation 을 자동화). secdata 어댑터가 전일자 출력물을 출력물폐기로 이관하는 것과 대칭.

## 주요 변경
- `lib/integrations/types.ts`: ChannelKind 에 'secmon' 추가, `SecurityEvent`·`SecMonAdapter` 계약 정의, AdapterSet 확장.
- `lib/integrations/mock.ts`: `mockSecmon`(목업 탐지 3건) — throw·hang·malformed·badtype 결함 주입 훅(hr/secdata 대칭).
- `lib/integrations/conformance.ts`: KINDS·CONTRACTED 에 secmon 추가, `isSecurityEvent` 형태 검증 + exerciseContract
  secmon 케이스 — 고객사 어댑터 착수 전 계약 자가진단 대상에 포함.
- `lib/integrations/registry.ts`: SECMON 레지스트리·`resolveAdapter` secmon 케이스·`secmonAdapter()` 리졸버(채널 비활성 게이트).
- `profiles/*.config.ts`(4종): `sec-monitor` 채널 추가(전 프로필 opt-in, 기본 비활성 — 기존 프로필 기본 동작·집계 불변).
- `lib/secmon.ts`(신규) `importSecurityEvents`: 탐지 이벤트 조회 → 형태(5필드)·유효 유형(VIOLATION_TYPE 코드) 검증,
  (위반자·유형·발생일) by-value 중복 방지, 위반(징구중) 명시 구성·감사('[보안관제 자동]'). secdata importDaily 와 동일
  수집 방어(원시 스프레드 금지·오형 스킵). 편입 위반의 확인서 흐름은 기존 경로가 이어받는다(편입 시 개별 메일 없음).
- `lib/notify.ts`: 일배치에 0-c 보안관제 이벤트 자동 이관 단계 추가(secdata 이관과 대칭, 채널 비활성 시 실패 기록).
- `app/(app)/awareness/violations/page.tsx`: `importSecmon` 수동 액션 + 위반 등록 카드에 '보안관제 이벤트 가져오기'
  버튼(sec-monitor 채널 보유 프로필만, BIZ_MGR/ADMIN).

## 호환성·영향
- 무회귀: sec-monitor 채널은 전 프로필 기본 비활성(opt-in) — 기존 화면·집계·프로필 스위칭 동작 불변. 채널 ON 시에만
  이관이 동작한다. 어댑터 계약 위반(오형·미정의 유형)·중복은 수집 단계에서 스킵(스토어 오염·중복 등록 방지).
- 실서비스 커스터마이징: mockSecmon 을 고객사 SIEM/DLP REST 어댑터로 교체하고 프로필 adapterId 만 바꾼다(포털 본체 무변경).
