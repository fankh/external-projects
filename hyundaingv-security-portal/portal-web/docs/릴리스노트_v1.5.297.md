# 릴리스 노트 — portal-web v1.5.297

**실동작 REST 출력물 어댑터 — 계약된 6종 어댑터 실 구현 완료.** 보안·출력물 시스템 연동을 실제 HTTP
조회로 구현한다. 이로써 계약이 정의된 6종 어댑터(메일·문자·인사·자산·보안관제·출력물)가 모두 실
REST 구현을 갖춘다 — 목업에서 실동작으로의 전환 완료.

## 배경 — 발견 경위

요구사항 출력물 개인정보관리: 보안·출력물 시스템 자료를 일배치로 이관. 계약(`SecdataAdapter.fetchPrintouts`)
·이관 로직은 있었으나 구현이 목업뿐이었다. 마지막 남은 계약 어댑터의 실 조회 경로를 채운다.

## 주요 변경
- `lib/integrations/rest.ts`: `restSecdata` 추가 — `PORTAL_SECDATA_API_URL` GET 으로 전일자 출력물 자료
  조회, `PrintoutSourceRow{printedAt,name,dept,document,pages,personalInfo}` 매핑. 고객 스키마는 통용
  필드명으로, **매수(pages)는 수치·개인정보 포함(personalInfo)은 불리언으로 강제 변환**(문자열 '4'→4,
  'Y'→true 등). 인증 `PORTAL_SECDATA_API_TOKEN`. 미설정 시 빈 배열(자가진단 통과), 비정상 응답은
  throw(이관 지점 try/catch 흡수). 수치/불리언 변환 헬퍼(`pickNumber`·`pickBool`) 추가.
- `lib/integrations/registry.ts`: `rest-secdata` 등록 + 샘플 고객사 출력물(`fin-secdata`·`gov-secdata`)을
  목업 → 실 REST 재바인딩. 데모 기본(`mock-secdata`)은 유지.

## 어댑터 실 구현 현황 (마일스톤)
계약 6종 전부 실 REST 구현 완료: **메일·문자**(v1.5.287) · **인사**(v1.5.289) · **자산**(v1.5.291,
쓰기 폐쇄루프) · **보안관제**(v1.5.295, 탐지→위반) · **출력물**(v1.5.297). 데모 기본 프로필만 목업 유지.

## 호환성·영향
- 무회귀: 데모 기본 프로필은 목업 유지(secdata 계약위반 내성·이관 e2e 불변). 자가진단은 미설정 시 빈
  조회로 통과. security-db 채널은 기본 off — 실 배포에서 채널 ON + 엔드포인트 설정 시 동작.

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt(41/41) · keycheck · health(51) · **e2e 112**.
- 신규 `sc_rest_secdata`(금융 프로필·로컬 출력물 픽스처): '전일자 이관 실행' → restSecdata 실 GET(픽스처
  히트) → 고객 스키마(empName·docName·pageCount·hasPii) 매핑 + 수치/불리언 변환 → 출력물 2건 이관.
  GET 제거 시 이관 0건 실패 대조(fails-without-fix 실측).
