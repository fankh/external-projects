# 릴리스 노트 — portal-web v1.5.215

협력업체서약서의 징구→결재상신→승인 폐쇄루프에 회귀 e2e 커버리지를 더했다. 이 흐름은 이미 완전 구현돼
있었으나(요구사항: 협력업체서약서 · 결재 시트 12번), 전체 결재 워크플로우 경로가 e2e 로 검증되지 않고 있었다.

## 배경

잔여 커버리지를 정찰하던 중, 협력업체서약서 흐름이 완전 구현(addCompanyPledge 징구 등록 → submitCompanyPledges
선택 결재상신 → 승인 시 완료 전파)이나 e2e 가 전혀 없음을 확인했다. 대칭 흐름인 부서서약 현황 상신은 e2e 로
검증(sc_pledge)되는데, 협력업체 경로만 무검증인 비대칭이 있었다 — 전체 결재 워크플로우가 회귀 보호 부재.

## 주요 변경

### 회귀 e2e 커버리지 (`scripts/e2e_suite.py`)
`sc_company_pledge` 신규 — 격리 데이터 파일(협력업체 서약 없는 상태)에서:
1. 업무담당(시스템관리자)이 협력업체 서약을 징구 등록(상태 등록),
2. 선택 결재상신(상태 결재중, '서약 현황 상신' 결재 생성),
3. 결재자(박정호) 승인 → 협력업체 서약 완료 전파

전 구간을 실브라우저로 검증한다. 승인 시 완료 전파(work/approvals actions.ts 폐쇄루프 1-8)를 제거하면 단언이
실패함을 대조 확인해(테스트 유효성) 이 테스트가 실제로 승인→완료 전파를 지키는지 보증했다.

## 호환성·영향
- 무회귀: 테스트 추가만. 기능·데이터·산식 무변경.
- 결재자는 등록자(시스템관리자)와 다른 박정호라 자기결재 대체 경로를 타지 않는 정상 결재 흐름을 검증한다.

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt · keycheck · health · **e2e 85**.
- `sc_company_pledge` 는 승인→완료 전파 제거 시 실패함을 대조 확인 후 복원(테스트가 워크플로우를 지킴).
