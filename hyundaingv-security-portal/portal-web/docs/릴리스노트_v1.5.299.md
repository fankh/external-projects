# 릴리스 노트 — portal-web v1.5.299

**전자결재(그룹웨어) 상신 푸시 어댑터 — 신규 계약 정의 + 실 구현.** 그동안 '연동 예정'(planned)으로만
있던 전자결재 채널에 어댑터 계약(`ApprovalAdapter`)을 정의하고, 포털 대기 결재를 외부 그룹웨어 결재함에
실제 HTTP 로 푸시하는 REST 구현을 붙인다. 계약이 정의된 어댑터 종류가 6종 → 7종으로 늘었다.

## 배경 — 발견 경위

요구사항 결재: "결재 상신 연동 (결재는 그룹웨어에서 확인)". 전자결재 채널은 `planned`(계약 미정의)로만
존재했다. 상신을 외부 그룹웨어에 등록하고 추적 id 로 잇는 실 연동 계약을 정의·구현한다.

## 주요 변경
- `lib/integrations/types.ts`: `ApprovalAdapter.pushApproval(doc) → {externalId}` 계약 + `ApprovalPushDoc`.
  자가진단 안전 규약 — `docId`가 `__probe`로 시작하면 네트워크·부작용 없이 합성 id 반환(실 그룹웨어 유령
  결재 방지).
- `lib/integrations/rest.ts` `restApproval`: `PORTAL_APPROVAL_API_URL` POST(`ApprovalPushDoc`→`{externalId}`),
  인증 `PORTAL_APPROVAL_API_TOKEN`. 프로브 단락, 미설정·비정상 응답은 throw(푸시 지점 흡수). `mock.ts`
  `mockApproval`(데모 합성 `KNOX-<id>`).
- `lib/approvalsync.ts`(신규) `pushPendingApprovals`: 대기+미연동(externalRef 없음) 결재만 푸시, 연동 id 저장·
  감사(`전자결재 상신 연동`). 상신 시점과 분리(외부 장애가 포털 상신을 막지 않음)·중복 방지. `lib/notify.ts`
  배치에 자동 편입(secmon·secdata 이관과 동일 계열).
- `lib/types.ts` `Approval.externalRef` + `work/approvals` 상세에 '그룹웨어 결재함' 연동 id 표시.
- `lib/integrations/registry.ts`: `approval` 리졸버·`approvalAdapter()` + `internal-approval`→목업/샘플 고객사
  (`fin`·`gov`·`hanbit-approval`)→실 REST 바인딩. 4개 프로필에서 approval 채널 `planned` 해제(계약화).
- `lib/integrations/conformance.ts`: `approval` 을 CONTRACTED 에 편입 + 프로브 기반 계약 검사(부작용 없이).

## 호환성·영향
- 무회귀: 데모 기본 프로필은 목업(합성 id). 자가진단은 프로브 단락으로 실 그룹웨어에 결재를 만들지 않는다.
  approval 채널이 계약화되며 비계획 채널 6→7종·활성 4→5(데모 기본, approval 기본 가동)로 계수 변경.

## 검증
- 게이트 전량 그린: build · smoke · a11y · emptystate/corrupt(41/41) · keycheck · health(51) · **e2e 113**.
- 신규 `sc_rest_approval`(금융 프로필·로컬 그룹웨어 픽스처): 알림 배치 → restApproval 실 POST(픽스처 히트)
  → 응답 externalId(GWDOC-77777)를 연동 id 로 저장·감사. POST 제거 시 픽스처 0·로컬 id 로 실패 대조
  (fails-without-fix 실측). 채널 계수 e2e(활성 5/7) 갱신.
