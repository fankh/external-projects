# 샘플 산출물 — AI 리포트 자동 생성 8종

`itam-web`의 **AI 인텔리전스 › 리포트 자동 생성** 화면에서 실제로 생성해 내려받은 결재 첨부용
산출물이다. 손으로 작성한 예시 문서가 아니라, 실행 중인 플랫폼이 자산 대장·발견 저장소·계약·
권한·정책·감사 로그를 읽어 만든 결과물을 그대로 저장한 것.

각 리포트는 **문서(Markdown)** 와 **엑셀 호환 CSV(UTF-8 BOM)** 두 형식으로 저장했다.

| 리포트 | 파일 | 주기 | 주요 내용 |
|---|---|---|---|
| 주간 Shadow IT 브리핑 | `샘플_주간ShadowIT브리핑.{md,csv}` | 주간 | 신규 발견 미등록 자산, 외부 공격표면 노출, 미인가 SaaS, 인증·계정·엔드포인트 정책 위반, 조치 현황 |

| 라이선스 컴플라이언스 | `샘플_라이선스컴플라이언스.{md,csv}` | 월간 | 보유–사용 대사, 초과 사용(감사 리스크), 미사용 회수 후보·절감액, 갱신 협상 근거, 중복 SaaS 통합 후보 |
| 재물조사 결과 요약 | `샘플_재물조사결과요약.{md,csv}` | 수시 | 회차별 진행률, 차이 항목(미확인 자산), 조정 결재 대상 |
| 감사 대응 자료 | `샘플_감사대응자료.{md,csv}` | 수시 | 권한 통제, 대장 정합성(CMDB 정확도), 필수 결재, 탐지 정책, 운영·거버넌스 정책 기준, SW·SaaS 정책 상태, 외부·계정·SW 위협 대응 현황, 이상 자산 행위 탐지(프로파일 이탈), 감사 로그 |
| 연간 교체 계획 | `샘플_연간교체계획.{md,csv}` | 수시 | 내용연수·보증 경과·장애 이력(잦은 수리) 교체 대상·잔존가치, 유형별 예산 추정, OS 지원 종료(EOL) 자산 |
| 취약점 조치 우선순위 | `샘플_취약점조치우선순위.{md,csv}` | 주간 | 자산 중요도 × 노출도 스코어링 P1/P2/P3, 출처별 분포, 우선순위 상세(점수순) |
| AI 거버넌스·성능 | `샘플_AI거버넌스성능.{md,csv}` | 월간 | 모델·프롬프트·분류 정확도, AI 기능별 제안 채택률(재학습 신호), 거버넌스 준수 |

## 생성 방법

```
AI 인텔리전스 › 리포트 자동 생성 → 원하는 리포트 행의 [생성]
                                → [엑셀(CSV)] 또는 [문서] 다운로드
```

다운로드 라우트(`/api/reports/[id]`)에는 권한 가드가 있어 사용자 권한그룹은 403을 받는다.

이 문서의 8종 샘플은 위 화면에서 내려받은 스냅샷이며, 리포트 섹션이 늘면 함께 갱신해야 한다.
재현 스크립트로 일괄 재생성한다 — 시드 기준일(2026-07-29)을 고정하고 자산담당 권한으로 8종을
생성해 `md`·`csv` 원본 바이트 그대로 저장한다(UTF-8 BOM 보존):

```
node scripts/gen-samples.mjs           # 재생성(파일 덮어쓰기) 후 git diff 로 드리프트만 반영됐는지 확인
node scripts/gen-samples.mjs --check    # 드리프트 감지만(파일 미변경) — 커밋된 샘플이 현재 생성기와 어긋나면 비정상 종료
```

감사 대응 자료의 ‘감사 로그(최근)’ 섹션은 생성 시점의 로그를 담으므로, 스크립트는 이 리포트를 맨 먼저
UI 경로로 생성해 시드 로그만 남게 한다(재현성 확보). `--check` 는 8종 모두 결정적으로 재현되는지 검증한다.

## 수치의 출처

표 항목은 `lib/reports.ts`가 스토어 데이터에서 결정적으로 산출하므로 화면 데이터와 항상
일치한다. 맨 위 요약 서술만 AI가 그 표를 근거로 작성하며, `ANTHROPIC_API_KEY`가 없으면
규칙 기반 서술로 대체된다 — 이 샘플들의 머리말 `규칙 생성`이 그 경우다. 키가 설정되면
동일한 표 위에 LLM이 작성한 서술이 얹히고 머리말이 `AI 생성`으로 바뀐다.

> 데모 스토어(시드 데이터) 기준이므로 계정·자산 정보는 실제 조직 정보가 아니다.
> 생성일은 플랫폼 기준일(`lib/dates.ts`의 `TODAY`)을 따른다.
