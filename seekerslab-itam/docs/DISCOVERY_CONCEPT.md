# Shadow IT Discovery 기능 — 초기 컨셉

작성일: 2026-07-28 · 상태: 내부 초안 (문의 범위 확인 전)

## 1. 목표

관리 대장(CMDB/ITAM)에 없는 미인가 자산을 자동 발견하고, 등록 자산과 대사(reconciliation)해
"발견됨 ↔ 등록됨" 차이를 상시 가시화한다. Shadow IT 는 단말·서버뿐 아니라 SaaS 구독,
개인 계정 클라우드 리소스, 부서 자체 도입 솔루션까지 포함하는 것이 최근 범위.

## 2. 탐지 채널 (Discovery 소스)

| 채널 | 발견 대상 | 방식 | 비고 |
|------|-----------|------|------|
| 네트워크 능동 스캔 | 미등록 단말·서버·IoT | Nmap 계열 스캔, SNMP, ARP/NetBIOS | 스캔 정책·시간대 협의 필요 (운영망 영향) |
| 패시브 트래픽 분석 | 스캔이 닿지 않는 세그먼트의 활성 장비 | 미러링/NetFlow, DHCP·ARP 테이블 수집 | 능동 스캔 보완, 무중단 |
| DNS·프록시·방화벽 로그 | 미인가 SaaS 사용 (Shadow SaaS) | 아웃바운드 도메인 분석 → SaaS 카탈로그 매칭 | CASB 경량 대체 접근 |
| 엔드포인트 에이전트/EDR 연계 | 설치 SW 인벤토리, USB·로컬 가상머신 | 기존 EDR·백신 콘솔 API 연동 | 신규 에이전트 배포 없이 시작 가능 |
| 클라우드 API 인벤토리 | 미관리 클라우드 리소스·계정 | CSP API (AWS Config, Azure Resource Graph 등) | 개인·부서 계정 발견은 조직 정책 병행 필요 |
| AD/IdP·SSO 로그 | 미인가 앱 OAuth 연동, 휴면 계정 | Entra ID/AD 로그, SSO 앱 카탈로그 | 계정 기반 Shadow IT |

## 3. 처리 파이프라인

수집(채널별 커넥터) → 정규화·중복 제거(자산 지문: MAC/호스트명/시리얼/도메인)
→ CMDB 대사(등록/미등록 판정) → 분류·위험도(자산 유형, 노출 서비스, 데이터 등급)
→ 워크플로(소유자 지정 → 등록 전환 또는 차단 요청) → 대시보드·리포트

핵심은 스캔 도구가 아니라 **대사와 워크플로** — 발견만 하고 등록·차단으로 이어지지 않으면
목록만 쌓인다. 발견 자산의 소유자 확인 프로세스(부서 확인 요청, 미확인 시 격리 정책)까지가 기능 범위.

## 4. 단계화 제안 (초안)

1. **1단계 — 가시화**: 네트워크 스캔 + DHCP/AD 수집 → 미등록 단말 목록, CMDB 대사 리포트
2. **2단계 — Shadow SaaS**: DNS/프록시 로그 기반 SaaS 발견, 부서별 사용 현황
3. **3단계 — 워크플로·자동화**: 소유자 확인·등록 전환 워크플로, NAC/방화벽 연계 격리, 클라우드 API 확장

## 5. 문의자에게 확인할 것

1. 자산관리 시스템 전체 신규 구축인가, 기존 ITAM/CMDB 에 Discovery 모듈 추가인가
2. 관리 대상: 사내망 단말·서버 / SaaS / 클라우드 리소스 중 우선순위
3. 자산 규모(단말 수, 사이트 수)와 망 구성(망분리 여부)
4. 기존 보유 도구: NAC, EDR, 프록시/방화벽, AD/Entra — 연계 가능 소스 파악
5. 자체 사용인가, 고객사에 제공할 상품화인가
