## 2. 동작하는 폐쇄 루프 43종

화면이 서로 연결되어 있어, 한 화면의 판정이 다른 화면의 상태를 실제로 바꾼다.
아래 항목은 모두 Playwright로 실제 UI를 조작해 검증했다(코드 단정이 아님).

| # | 루프 | 검증된 결과 |
|---|---|---|
| 1 | Discovery 편입 요청 → 결재 승인 | 자산 대장에 등록 + 최초 발견 채널·일시가 자산 이력에 승계 |
| 2 | 격리 요청 → 보안담당 결재 | NAC 격리 조치 상태 반영 |
| 3 | 검수 체크리스트 완료 → 채번 | 대장 검수중 등록 + 라벨(QR·바코드) 발행 |
| 4 | 스캔 실사 차이 → 조정 결재 | 대장 위치가 실사값으로 보정(IDC-B → IDC-A) + 점검 이력 기록 |
| 5 | 폐기 대상 선정 → 결재 → 소거 | 소거 방식·확인서 번호가 자산 이력에 영구 기록 |
| 6 | SaaS 카탈로그 인가 판정 (또는 Shadow SaaS 화면에서 직접 판정) | Shadow SaaS 미인가 집계 4 → 3, 해당 서비스 인가로 전환 — 두 화면이 같은 카탈로그를 본다 |
| 6' | 탐지 채널 중지 | 상태바 커넥터 6/6 → 5/6 즉시 반영 |
| 7 | QnA 질문 → 담당자 답변 | 답변 대기 → 완료 전환 + 감사 로그 적재 |
| 8 | CMDB 대사 미확인 → 재물조사 편성 | 유령 자산이 수시 조사 회차로 편성(기한 +14일) → 조사 개시 → 실사 화면 연결. 재편성은 차단 |
| 9 | 사용자 신청 → 결재 → 불출 처리 | 사용자가 상신한 건이 승인 후 불출 대기열로, 유휴 재고 배정 시 대장의 소유자·부서·위치 갱신 + 불출 이력. 신청자는 결재 확정 전 본인 신청을 상신 취소 가능(전자결재 회수) |
| 10 | 반납 승인 → 접수·점검 → 유휴 풀 | 반납대기 → 상태 점검 결과에 따라 유휴 풀 또는 폐기예정으로 분기, 유휴 풀은 다시 불출 배정 재고가 됨 |
| 11 | AI 제안 → 판정 → 조치 → 환류 | 이상탐지 승인 시 격리 요청·라이선스 최적화 승인 시 추가 구매·회수 결재·수명예측 승인 시 연간 교체 계획 리포트·취약점 우선순위 승인 시 EOL 자산 폐기(교체) 대상 선정, 반려는 사유 필수 → 기능별 채택률로 집계 (재학습 신호) |
| 12 | 소유자 확인 → 응답 → 에스컬레이션 | 확인 메일 발송·이력 적재 → 부서 사용자 응답 → 기한 7일 무응답은 격리 요청으로 자동 전환 |
| 13 | 만료 임박 → 알림 발송 | 계약·라이선스·보증을 한 번에 훑어 주관부서 통지 + 발송 이력 적재, 당일 중복 발송 차단 |
| 14 | 라이선스 검출 → 조치 | 초과 사용은 추가 구매 품의, 미사용 보유는 회수 — 둘 다 결재로 연결 (컴플라이언스 STEP 4) |
| 15 | 스캔 실행 → 관측 → 발견 | 채널 선택 실행 → 재관측 11·신규 발견 4, 미확인 자산 생존 복귀, 창 밖 실행은 사유가 이력·감사에 기록 |
| 16 | 외부 재탐지 → 노출 확인 | 수동 수집은 후보만(생존 미확인), 능동 확인에서 생존·서비스·CVE 판정. 미협의 도메인은 능동 차단 |
| 17 | 스케줄 → 리포트 생성 → 배포 | 기한 도래 스케줄만 실행(중지분 제외) → 리포트 생성 → 수신자 배포 이력 적재 |
| 18 | 원시 관측 → 지문 병합 | 16건 관측 → 11건으로 병합, 3채널 자산은 세 필터 모두에 노출. 수동 병합 시 관측·최초발견일·위험도 승계 |
| 19 | 권한그룹 배정 → 결재선 거버넌스 | 사용자 권한그룹 변경이 STEP 3 매트릭스에 그룹 단위로 적용, 본인·마지막 관리자 강등 차단, 필수 결재선(폐기·격리·편입·차이 조정) 해제 불가 — 변경은 감사 로그 적재 |
| 20 | 공통코드 등록 → 전 화면 반영 | 코드 값 추가가 그 그룹을 참조하는 전 화면 드롭다운(재물조사 대상 범위 등)에 즉시 반영, 형식 검증·중복 차단, 삭제 없이 미사용 전환만 |
| 21 | 구성변경 기록 → 대장·이력 반영 | 자산 대장 상세의 사양 변경(메모리·OS 등) 기록이 대장 필드 갱신 + `구성변경` 타임라인 이벤트 적재, 코드는 불변 — 등록·이동·구성변경·점검·폐기 단일 화면 추적 |
| 22 | 커넥터 연결 테스트 → 상태·감사 반영 | 지연·오류·미연동 커넥터 재연동이 상태 정상·최근 수집 갱신 + 같은 화면 감사 로그 적재. 커넥터 관리는 보안담당·Admin, 자산담당은 조회만 |
| 23 | 계약 갱신 → 만료 임박 해소 | 만료 임박·경과 계약 1·2·3년 갱신이 만료일 연장 + 상태 정상 전환 → 만료 임박 집계에서 제외. 만료 전이면 만료일 기준, 지났으면 오늘 기준. 감사·발송 이력 적재 |
| 24 | 보증 연장 → 보증 만료 임박 해소 | 자산 보증 1·2·3년 연장이 보증 만료일 연장 + `보증연장` 타임라인 이벤트 → 보증 만료 임박 집계에서 제외. 보증 없는 자산(SW·가상자원)은 대상 아님 |
| 25 | 다단계 결재선 집행 | 자산신청 부서장(ADMIN)→자산담당(ASSET_MGR), 격리 보안담당(SEC_MGR)→IT기획팀장(ADMIN). 현재 단계 역할만 처리(ADMIN 오버라이드), 중간 승인은 다음 단계로, 효과는 마지막 단계에서만. Playwright 15건 검증(역할 게이트·진행·확정) |
| 26 | 반납 수리 필요 → 수리중 → 수리 완료/불가 | '수리 필요' 판정 자산이 유휴가 아니라 수리중으로 편성(불출 대상 제외 — 고장 자산 재불출 방지). 수리 완료→유휴, 수리 불가→폐기예정, `수리` 이력 적재 |
| 27 | 발주 계약 → 입고 등록 → 검수 대기열 | 구매 계약 연계 입고 등록(그동안 진입점 부재, 시드만)이 즉시 `입고 대기`로 검수 파이프라인 진입. 기본 검수 체크리스트 자동 부여, 공급사는 계약 승계. 이후 검수→채번→대장(3) |
| 28 | 유출 검출 → 대응 조치 → 알림·감사 | 다크웹 유출(유출 계정·스틸러 로그·코드 시크릿·랜섬웨어)을 검출에서 끝내지 않고 보안담당이 유형별 표준 조치 확정 → 미조치→조치 완료, 보안운영팀 통지·감사 적재. 자산담당은 조회만 |
| 29 | 외부 노출 검출 → 편입/차단 요청 → 알림·감사 | 외부 노출 자산을 표시에서 끝내지 않고 보안담당이 편입 요청(대장) 또는 차단 요청(NAC 격리·노출 차단) 상신. action 미설정→편입요청/차단요청, 담당팀 통지·감사 적재. 자산담당은 조회만 |
| 30 | 분실·도난 신고 → 분실 처리 → 회수/폐기 | 재물조사가 수동적으로 잡던 분실 후보와 별개로 자산팀이 직접 분실·도난을 신고 → 상태 `분실`(불출 대상 제외). 도난은 보안운영팀에 데이터 유출 위험 점검 통보. 회수 시 유휴 풀 복귀, 미회수 확정 시 폐기 절차(5)로. 미처리 분실 자산은 대시보드 운영 큐에 노출. 자산담당·Admin |
| 31 | 필독 공지 → 사용자 읽음 확인 → 커버리지 | '필독'이 상단 고정 표시뿐이고 열람 추적이 없던 것을, 전 권한그룹이 자기 명의로 읽음 확인 → 확인 이력(사용자·일시) 감사 적재 + 확인 N/전체 M명 커버리지 집계. 멱등·자기 확인만. QnA와 함께 사용자 쓰기 접점 |
| 32 | 계약 해지 → 만료 임박 집계·알림 제외 | 등록·갱신·만료뿐이던 계약에 조기 해지 추가 → 상태 `해지`로 만료 임박 집계(대시보드·발송)에서 제외, 갱신 차단, 주관부서·공급사 앞 해지 통보 발송. 23(갱신)의 짝 — 계약 생애주기(등록·갱신·해지) 완결. 자산담당·Admin |
| 33 | 재물조사 실측 → 대장 최근 실측일 → 장기 미실측 식별 | 실사 스캔이 대장의 최근 실측일을 갱신(위치 불일치여도 실물 확인이므로) → CMDB 미확인 판정이 정적 시드가 아닌 실사 데이터에 근거. 최근 실측 없거나 180일 초과 자산을 '장기 미실측(유령 후보)'으로 대장 필터에 노출, 실측하면 빠짐 |
| 34 | 장기 미실측 → 수시 재물조사 자동 편성 | 33이 식별한 장기 미실측 자산을 재물조사 계획에서 한 번에 수시 회차로 편성(대장 실사 데이터 원천 — 8의 발견 저장소 원천과 대칭). 개시 전·진행 중 회차 중복 편성 방지, 개시·스캔 시 33의 최근 실측일 갱신으로 해소. 자산담당·Admin |
| 35 | 대여(반출) → 대여중 → 반환/연체 | 불출(영구)과 달리 반환 기한부 반출 — 유휴 재고를 대여자·부서·기한과 함께 대여하면 상태 `대여중`(불출 대상 제외), 반환 시 유휴 풀 복귀. 반납 없이 반환 기한 연장 가능, 반환 임박(D-7) 사전 표시. 기한 경과는 연체로 대시보드 운영 큐·대장 상세에 노출. 자산담당·Admin |
| 36 | 재물조사 완료 → 결과 요약 리포트 자동 생성·배포 | 실사 회차 마감(차이 전건 조정 필수) 시 `재물조사 결과 요약` 리포트 자동 생성 + 담당·IT기획팀 배포(발송 이력). 그동안 리포트는 스케줄(17)·수동뿐 — 완료가 종결 표시로 끝나지 않고 결과 보고서(증적)를 남긴다. 자산담당·Admin |
| 37 | SaaS 차단 판정 → 차단 집행 요청 | 카탈로그에서 서비스를 `차단`으로 판정하면 Shadow SaaS 미인가 집계 반영(6)에 더해 보안운영팀에 프록시·DNS 차단 집행 통보(발송 이력·감사). 그동안 차단은 상태만 바꿨다 — 외부 노출 차단(29)과 대칭. Admin |
| 38 | 공지 예약 발행 → 발행일 도래 시 전사 공개 | 미래 발행일과 함께 등록한 공지는 관리자에게만 `예약`으로 보이고, 발행일이 도래하면(기준일≥발행일) 전사 공개. 크론 없이 조회 시점 필터로 동작 — 발행 전에는 일반 사용자 목록에서 제외. 과거 발행일은 즉시 발행. Admin |

## 3. 설계 결정

**크롬 구조** — edim-web-next의 AppChrome을 계승: 타이틀바 · 모듈 메뉴바(LV1) · MDI 탭
(방문 화면 localStorage 유지) · 모듈 좌측 내비(LV2) · 상태바. 비주얼만 제품안내서의
모던-덴스 언어로 현대화했다.

**권한 모델** — 화면 단위는 코드 가드(`lib/authz.ts`), 기능 단위는 편집 가능한 권한 매트릭스가
통제한다. 매트릭스는 **필요조건**이라 켜도 코드 규칙을 넘지 못하고, Admin 의 권한 화면 접근은
잠겨 있어 자기 잠금이 불가능하다. 화면·기능 단위 최소권한. 사이드바 숨김과 별개로 `lib/authz.ts`의 서버사이드
가드가 직접 URL 진입을 차단하며, AI 질의 컨텍스트도 동일한 권한 필터를 통과한다.
라우트 권한 변경 시 갱신할 3곳: `lib/authz.ts` · `components/chrome/menus.ts` · `scripts/smoke.mjs`.

**라벨** — QR은 `qrcode` 패키지, Code128-B 바코드는 패턴 테이블 + modulo-103 체크섬으로 직접
인코딩(`lib/label.ts`). 둘 다 SVG로 출력해 인쇄 시 해상도 손실이 없다.

**리포트** — 표 항목은 `lib/reports.ts`가 스토어에서 **결정적으로 산출**하고, AI는 그 표를
근거로 요약 서술만 작성한다. 따라서 리포트 수치는 화면 데이터와 항상 일치하며, AI가 수치를
지어낼 수 없다. 키가 없으면 규칙 기반 서술로 대체되어 리포트 생성 자체는 동일하게 동작한다.

## 5. 범위 밖 · 미완

| 항목 | 상태 |
|---|---|
| 데이터 영속화 | **파일 기반 스냅샷** — `ITAM_DATA_FILE`/Docker 볼륨(`itam-data:/data`)로 재시작·재생성 후 유지. 2초 주기+종료 flush, 원자적 쓰기. 미설정 시(로컬·스모크) 인메모리. RDB/CMDB 는 범위 밖 |
| SSO | 쿠키 기반 목업 4계정 (SAML 실연동 아님) |
| 스캐너·커넥터 | NAC·EDR·CSP API 연동은 시뮬레이션 |
| 리포트 출력 | 리포트는 CSV · Markdown, 그리드 내보내기는 네이티브 `.xlsx` |
| 기준일 | 실제 현재 날짜를 사용(시드는 2026-07-29 기준). 특정 날짜 재현은 `ITAM_TODAY` 환경변수 |
| **AI 라이브 모드** | **미검증** — 연동 코드는 완성(키 감지·권한 필터·refusal 처리·폴백)이나, 사용한 키의 계정에 크레딧이 없어 규칙 모드로만 동작함 |

AI 라이브 모드는 크레딧이 있는 키를 `~/.itam.env`에 넣고 컨테이너를 재생성하면
(`docker restart`로는 env-file이 재적용되지 않음) 코드 변경 없이 동작한다.
사전 검증: `docker exec itam-web node scripts/ai-keycheck.mjs`.
