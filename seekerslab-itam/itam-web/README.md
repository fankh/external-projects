# SEEKERSLAB ITAM — AI 기반 IT 자산관리 플랫폼

`AI기반_IT자산관리시스템_제품안내서.pdf`(v1.0, 2026.07)를 구현 스코프로 한 웹 플랫폼.
자산 수명주기 관리 · Shadow IT Discovery · AI 자산 인텔리전스를 단일 플랫폼에서 다룬다 —
"발견되지 않은 자산을 찾아 대장에 편입시키는 것까지"가 관리 범위.

제품안내서가 정의한 **8대 업무 도메인의 명시 화면 30종**이 모두 구현되어 있다.

## 실행

```powershell
cd itam-web
npm install
npm run dev        # http://localhost:3000
```

로그인 화면에서 권한그룹별 목업 계정(SSO 대체) 4종 중 선택:
**사용자**(김민준) · **자산담당**(박자산) · **보안담당**(윤보안) · **Admin**(시스템관리자).
권한그룹에 따라 메뉴바·좌측 내비와 화면 내 기능(편입·격리·결재·정책 변경)이 다르게 노출되며,
모든 제한 화면은 `lib/authz.ts`의 서버사이드 가드로 직접 URL 진입도 차단한다.

## 테스트

```powershell
npm run verify     # 빌드 → 스모크 → e2e → 헬스 → 레이아웃 → 빈 대장 → 리포트 샘플 드리프트 순차 실행

# 개별 실행
npm run build
npm run smoke      # 프로덕션 서버 기동 → 1042개 검증(SSR HTML) → 종료
npm run health     # 실제 브라우저로 권한그룹 4종 × 접근 화면 74회 로드 + 역할별 링크·API 링크 권한 8건 → 응답 상태·클라이언트 크래시·하이드레이션 오류 검사
npm run e2e        # 실제 브라우저로 보안 findings 대응(45~50)·AI 제안 판정(11) 클릭·상태 전환·역할 게이트 검증
npm run layout     # 화면 30종 × 폭 5종 (+ 좁은 폭 상세 패널·시드에서 수집한 필터 경로) — 카드 밖으로 이탈해 도달 불가한 컨트롤(스크롤 조상 없는 넘침) 검사
npm run empty      # 빈 대장(갓 배포한 상태) — 데이터 0에서 화면 30종 + 시드에서 수집한 필터·드릴다운 링크 × 권한그룹 4종이 5xx·NaN 없이 열리는지
```

네 스위트 모두 `next start` 로 **이미 만들어진** `.next` 를 띄운다 — 그래서 소스가 빌드보다 새로우면
시작하지 않고 무엇이 새로운지 알리며 멈춘다(`scripts/build-guard.mjs`). 빌드를 잊으면 예전 코드를 검증하면서
초록으로 통과하기 때문이다(고친 결함이 그대로인데 회귀는 통과한다). 원격 대상(`SMOKE_BASE`·`HEALTH_BASE`·`E2E_BASE`·`LAYOUT_BASE`)일 때는 건너뛴다.

`smoke` 는 서버 렌더 HTML만 보므로 클라이언트 하이드레이션 크래시를 못 잡는다. `health`(Playwright)가
권한그룹 4종으로 각자 접근 가능한 화면을 실제 브라우저에서 열어 응답 상태·`pageerror`·클라이언트 예외를 잡는다(원격: `HEALTH_BASE`).
역할 조건부 렌더가 많아 Admin 만 열면 자산담당·보안담당 전용 패널의 크래시를 못 본다 — 대상 화면은 내비 정의(menus.ts)에서 읽어 목록을 따로 두지 않는다.
`e2e`(Playwright)는 SSR 스모크가 못 잡는 **인터랙션**을 검증한다 — 크리덴셜·휴면 계정·미인가 SW·USB·로컬 VM·IOC
대응 버튼을 실제로 눌러 상태 전환·감사 적재를 확인하고, AI 제안 판정(승인→조치·반려 사유 필수)을 검증하며,
자산담당의 조치 버튼 미노출(역할 게이트)을 확인한다(원격: `E2E_BASE`).

배포 후에는 **같은 스위트를 배포본에 한 번 더** 돌린다 — 로컬에서 통과해도 배포본에서만
틀리는 결함이 실재한다(컨테이너 TZ 가 UTC 라 KST 00~09시에 날짜가 하루 뒤처지던 건).

```powershell
ssh -f -N -L 3390:127.0.0.1:3390 <host>
$env:SMOKE_BASE="http://localhost:3390"; node scripts/smoke.mjs
```

원격 대상일 때는 로컬 서버를 띄우지 않고, 문서 정합성 검사(로컬 소스 기준)는 건너뛴다.

`scripts/smoke.mjs`가 인증 리다이렉트, 라우트 × 권한그룹 접근 매트릭스(30 라우트 × 4 권한),
자산 대장 데이터 스코핑(사용자=본인 자산만), 주요 화면 콘텐츠 렌더를 검증한다.
**라우트(화면) 권한**을 바꿀 때는 **세 곳**을 함께 갱신해야 한다 — `lib/authz.ts`의 `requireRole`,
`components/chrome/menus.ts`의 `roles`, `scripts/smoke.mjs`의 `ROUTES`.
**기능(버튼) 권한**은 코드가 아니라 스토어의 권한 매트릭스가 원천이며, 환경설정 › 권한·정책에서
편집하면 서버가 즉시 강제한다 (`lib/perm.ts`).

## 판정 규약

화면·리포트·반출·AI 답변이 같은 것을 다르게 말하지 않도록, 판정과 표기를 한 곳에 모아 두고 스모크가 이탈을 잡는다.

- **상태 게이트는 단일 소스.** 비운영(분실·수리중·반납대기·폐기 경로)은 `lib/types` 의 `NON_OPERATIONAL_STATUSES`,
  EOL 대상은 `lib/eol` 의 `isEolTarget`, 예방 정비 대상은 `lib/dates` 의 `isMaintenanceDue` 하나만 쓴다.
  같은 개념을 화면마다 다시 적으면 "대장에는 있는데 큐에는 없는" 자산이 생긴다.
- **자리표시자는 값이 아니다.** 보유자 `미지정`·위치 `실사 확인 필요`·`-` 는 정합성 판정에서 빈 값으로 보고,
  보정 경로(`correctField`)도 같은 규약을 쓴다. 판정은 "미흡"이라 하면서 보정이 "이미 값이 있다"고 거절하면
  화면이 내준 입력이 막다른 컨트롤이 된다.
- **비율은 이정표 정직.** 집행률·소진률·사용률·진행률은 `lib/dates` 의 `ratioPct` 로만 만든다 — 0%·100% 는
  실제로 그 상태일 때만 쓰고, 사이는 내림, 초과분은 감추지 않는다. 반올림은 89.6% 를 90% 로 만들어
  같은 행의 판정(소진 임박 기준 90%)과 어긋나게 한다.
- **상태를 바꾸면 남기고 갱신한다.** 서버 액션이 스토어를 바꾸면 감사 기록(§07 추적성)과 `revalidatePath` 가
  함께 따라온다. 둘 중 하나가 빠지면 "누가 바꿨는지 모르는 변경"이거나 "바뀐 줄 모르는 화면"이 된다.
- **일괄 조치는 건너뛴 선택분을 밝힌다.** 선택 수와 처리 수가 다르면 이유와 건수를 결과에 적는다 —
  침묵하면 오프보딩 일괄 회수에서 빠진 자산이 떠나는 사람 손에 남는다.
- **손을 떠난 자산은 한 기준.** 분실·폐기예정·폐기완료(`lib/types` `GONE_STATUSES`)는 계약 커버리지
  (`contractAssetCount`)·재배치 풀(`availableAssets`)·예정 일정(`upcomingSchedule`)에서 함께 빠진다.
  연계 가드가 "종료 상태는 커버리지를 부풀린다"며 막는 이유는 연계된 뒤 죽은 자산에도 그대로 적용된다.
- **격리는 상태를 바꾸지 않지만 운영은 멈춘다.** NAC 격리(`quarantinedAt`) 자산은 대여·불출·재배정을
  서버가 거절하고, 가용·배정 재고에서 빠지며, 하위 의존에는 상위 이탈(`isDegraded`)로 잡힌다.
  화면은 컨트롤 대신 사유를 보여 준다 — 눌러야 막히는 버튼을 내주지 않는다.
- **권한 매트릭스는 화면과 데이터 API 가 함께 본다.** 화면 가드(`requireView`)뿐 아니라 인쇄 문서·리포트
  API 도 `can(메뉴, '조회')` 를 거친다. 한쪽만 보면 조회를 회수한 뒤에도 같은 데이터가 문서로 나간다.
- **통지·독촉은 당일 발송분을 뺀 대상 수로 말한다.** 대상 산출은 `lib/reminders` 한 곳이고, 화면 버튼 건수와
  액션이 그 집합을 공유한다 — 보낸 뒤에도 같은 건수로 남는 버튼은 알림 피로만 남긴다.
- **필터는 목록까지 다시 계산한다.** 목록 메모(`useMemo`)의 의존성에 필터 상태를 빠뜨리면 칩만 켜지고
  표·건수는 그대로다. 반출도 같은 규약 — 서버 빌더가 모르는 필터가 켜져 있으면 보이는 행 번호를 넘긴다.

## 동작하는 폐쇄 루프

화면이 서로 연결되어 있어, 한 화면의 판정이 다른 화면의 상태를 실제로 바꾼다.

1. **발견 → 편입** — Discovery 발견 자산 편입 요청 → 결재 승인 → 자산 대장 등록
   (최초 발견 채널·일시가 자산 이력에 승계, 메뉴 뱃지 감소)
2. **발견 → 격리** — 격리 요청 → 보안담당 결재 → NAC 격리 조치 상태 반영
3. **입고 → 대장** — 검수 체크리스트 완료 → 자산번호 채번 → 대장 검수중 등록 + 라벨 발행
4. **실사 → 대장 보정** — 스캔 차이(위치·상태·미등록) → 조정 결재 → 대장 자동 보정 + 이력 기록
5. **폐기 → 증적** — 대상 선정 → 결재 → 데이터 소거 방식 기록 → 확인서 번호가 자산 이력에 영구 보존
6. **정책 → 운영** — SaaS 카탈로그(또는 Shadow SaaS 화면)에서 인가/차단 판정 → Shadow SaaS
   미인가 집계에서 제외 (두 화면이 같은 카탈로그를 본다. 발견 이전 서비스도 보안담당이 검토중으로 직접 카탈로그 등록 가능) / 탐지 채널 중지 → 상태바 커넥터 수(6/6→5/6) 즉시 반영
7. **문의 → 답변** — 사용자 QnA 등록 → 담당자 답변 → 상태 전환 + 감사 로그
8. **대사 미확인 → 재물조사** — CMDB 대사에서 **미확인(유령 자산)** 판정 → 수시 조사 회차로
   자동 편성(기한 +14일) → 조사 개시 → 실사 화면에서 실물 확인. 이미 편성된 자산은 재편성되지 않는다
9. **신청 → 결재 → 불출** — 사용자가 자산 신청 상신 → 결재 승인 → 자산담당이 유휴 재고를 배정해
   불출 처리 → 대장의 소유자·부서·위치가 갱신되고 `불출` 이력이 남는다. **승인만으로는 실물이 움직이지 않는다**.
   신청자는 결재 확정 전 본인 신청(자산 신청·반납·이동)을 **상신 취소**할 수 있다 (상신 시점엔 대장을 바꾸지 않아 되돌릴 상태가 없다)
10. **반납 → 점검 → 유휴 풀** — 반납 결재 승인 시 `반납대기` → 회수·상태 점검(정상/수리 필요/폐기 권고) →
    정상은 유휴 풀로, 수리 필요는 `수리중`으로(26 참조), 폐기 권고는 유휴를 건너뛰고 `폐기예정`으로.
    유휴 풀은 다시 불출 처리의 배정 재고가 된다
11. **AI 제안 → 판정 → 조치 → 환류** — 제안을 승인하면 조치로 이어진다(이상탐지 승인 → 격리 요청 자동 상신,
    라이선스 최적화 승인 → 대상 라이선스의 추가 구매·회수 결재 자동 상신, 수명예측 승인 → 연간 교체 계획 리포트 생성,
    취약점 우선순위 승인 → EOL·고위험 자산 폐기(교체) 대상 선정).
    반려는 **사유 입력이 필수**라
    오탐 유형이 재학습 신호로 남는다. 판정 누적이 기능별 채택률로 집계된다
12. **소유자 확인 → 응답 → 에스컬레이션** — 확인 요청 시 부서 앞 메일 발송(발송 이력 적재) →
    해당 부서 사용자가 직접 응답 → 기한(7일) 무응답 건은 격리 요청으로 자동 에스컬레이션
13. **만료 임박 → 알림 발송** — 계약·라이선스·보증(부서 단위 묶음)을 한 번에 훑어 주관부서 앞으로
    통지하고 발송 이력을 남긴다. 같은 날 같은 대상에는 재발송하지 않는다 (알림 피로가 알림을 무력화한다)
14. **라이선스 검출 → 조치** — 초과 사용은 추가 구매 품의, 미사용 보유는 회수로 이어지며 둘 다
    결재를 거친다 (컴플라이언스 4단계의 마지막 — 그동안 검출까지만 있었다)
15. **스캔 실행 → 관측 → 발견** — 채널을 골라 스캔하면 관측이 쌓이고, 아는 장비는 재관측으로
    생존 확인(미확인 상태는 되돌아감), 모르는 장비는 신규 발견으로 드러난다. 능동 스캔은 정책 시간대
    밖이면 사유가 필요하고 강도 **높음**은 아예 차단된다 — 실행 사유는 이력·감사 로그에 남는다
16. **외부 재탐지 → 노출 확인** — 도메인별 주기로 재탐지하며, **수동 수집**은 대상 무접촉으로 후보만 넓히고
    생존·서비스·CVE 는 **능동 확인**에서만 채워진다. 능동 탐지는 사전 협의된 도메인에서만 실행된다
17. **스케줄 → 리포트 자동 생성 → 배포** — 주간/월간 스케줄의 기한이 도래하면 예약 실행으로
    리포트를 만들고 수신자에게 배포한다. 중지된 스케줄은 기한이 지나도 돌지 않고, 밀린 스케줄은
    **기한 도래**로 드러난다. 배포 사실은 발송 이력에 남아 그 자체가 증적이 된다
18. **원시 관측 → 지문 병합** — 6채널이 각자 본 관측을 지문(MAC→호스트명→IP)으로 합쳐 발견 목록을
    만든다. 병합 자산은 어느 채널로 필터해도 잡히고, 지문이 갈린 중복 후보는 수동 병합으로 관측을 승계한다
19. **권한그룹 배정 → 결재선 거버넌스** — 사용자·그룹(STEP 4)에서 사용자의 권한그룹을 바꾸면 STEP 3
    매트릭스가 그 그룹 단위로 적용된다. 본인·마지막 관리자는 강등이 막혀 관리 화면이 잠기지 않고,
    폐기·격리·편입·차이 조정 결재선은 필수로 고정돼 선택으로 내릴 수 없다. 모든 변경은 감사 로그에 남는다
20. **공통코드 등록 → 전 화면 반영** — 공통코드에 값을 추가하면(위치·자산 유형 등) 그 값을 참조하는
    전 화면 드롭다운(재물조사 대상 범위·이동 목적지 등)에 즉시 선택지로 나타난다. 코드 삭제는 없고
    미사용 전환만 있어 기존 자산·이력이 참조하는 코드의 무결성이 보존된다
21. **구성변경 기록 → 대장·이력 반영** — 자산 대장 상세에서 사양 변경(메모리 증설·OS 재설치 등)을
    기록하면 대장의 해당 사양 필드가 갱신되고 변경 이력 타임라인에 `구성변경` 이벤트가 남는다.
    코드 자체는 참조 무결성 때문에 불변이며, 등록·이동·구성변경·점검·폐기가 한 화면에서 추적된다
22. **커넥터 연결 테스트 → 상태·감사 반영** — 연동·인프라에서 지연·오류·미연동 커넥터를 재연동하면
    상태가 정상으로, 최근 수집 시각이 현재로 갱신되고 그 사실이 같은 화면의 감사 로그에 남는다.
    커넥터 관리는 보안담당·Admin 만 가능하고 자산담당은 조회만 한다
23. **계약 갱신 → 만료 임박 해소** — 만료 임박·경과 계약을 1·2·3년 갱신하면 만료일이 연장되고
    상태가 정상으로 바뀌어 만료 임박 집계에서 빠진다(그동안 알림만 있고 갱신 처리가 없었다).
    만료 전이면 만료일 기준, 지났으면 오늘 기준으로 연장하며 갱신 사실은 감사 로그·발송 이력에 남는다
24. **보증 연장 → 보증 만료 임박 해소** — 자산 대장 상세에서 보증을 1·2·3년 연장하면 보증 만료일이
    연장되고 타임라인에 `보증연장` 이벤트가 남으며 보증 만료 임박 집계에서 빠진다(만료 알림이
    "연장·교체 검토"를 요청하는데 연장 처리가 없었다). 보증 없는 자산(SW·가상자원)은 대상 아님

25. **다단계 결재선 집행 → 단계별 역할 결재 → 최종 효과** — 각 결재는 결재선의 남은 단계를
    순서대로 밟는다. 자산 신청은 부서장(ADMIN)→자산담당(ASSET_MGR), 격리는 보안담당(SEC_MGR)→
    IT기획팀장(ADMIN). 현재 단계 역할만 처리할 수 있고(ADMIN 오버라이드), 중간 승인은 다음 단계로
    넘어가며 **효과는 마지막 단계에서만** 적용된다. 반려는 전체 반려. (부서장=요청자 부서장을 4-역할
    모델에서 ADMIN 으로 근사)
26. **반납 수리 필요 → 수리중 → 수리 완료/불가** — 반납 점검에서 '수리 필요'로 판정된 자산은 유휴 풀이
    아니라 **수리중**으로 편성된다(수리중은 불출 대상에서 제외 — 고장 자산이 재불출되지 않는다).
    수리 완료는 유휴 풀로, 수리 불가는 폐기예정으로 전환되며 `수리` 이력이 남는다.

27. **발주 계약 → 입고 등록 → 검수 대기열** — 도입·검수의 입고 건은 구매 계약에 연계해 등록하며,
    등록 즉시 `입고 대기`로 검수 파이프라인(3 참조)에 진입한다. 그동안 입고 건은 시드에만 있고
    등록 진입점이 없었다. 기본 검수 체크리스트가 자동 부여되고, 공급사는 계약에서 승계된다.

28. **유출 검출 → 대응 조치 → 알림·감사** — 다크웹 유출 수집(유출 계정·스틸러 로그·코드 시크릿·
    랜섬웨어 유출)을 검출에서 끝내지 않고 보안담당이 유형별 표준 조치(계정 재설정·시크릿 로테이션·
    침해 대응)를 확정한다. 상태 미조치→조치 완료로 바뀌고 보안운영팀 통지·감사 로그가 남는다.
    대응은 보안담당·Admin 만, 자산담당은 조회만. 오조치로 종결한 건은 **재개**(대응 취소)로 미조치 복귀한다(크리덴셜 45·IOC 50 동일 — 잘못 종결한 건이 미조치 큐·감사에서 사라지지 않게, 외부 노출 위험수용 해제와 동형).
29. **외부 노출 검출 → 편입/차단 요청 → 알림·감사** — 외부 노출 자산을 표시에서 끝내지 않고
    보안담당이 편입 요청(우리 자산 → 대장) 또는 차단 요청(노출 위험 → NAC 격리·노출 차단)을 상신한다.
    `action` 미설정 → 편입요청/차단요청으로 바뀌고 담당팀(자산관리팀/보안운영팀) 통지·감사가 남는다.
30. **분실·도난 신고 → 분실 처리 → 회수 / 폐기** — 재물조사 대사는 미확인 자산을 수동적으로
    유휴·분실 후보로만 잡는데, 자산팀이 직접 아는 분실·도난을 신고할 경로가 없었다. 자산 대장 상세에서
    분실·도난을 신고하면 상태가 `분실`로 전환되고(불출 대상에서 제외돼 재배치되지 않는다), **도난은
    데이터 유출 위험이 있어 보안운영팀에 침해 점검이 통보된다**. 실물을 되찾으면 회수하되 **상태 점검**으로 가른다
    (정상→유휴 · 수리 필요→수리중 · 폐기 권고→폐기예정 — 반납 10·대여 반환 35와 동일, 파손된 채 발견된 자산의 재불출 방지),
    미회수 확정이면 폐기 절차(5 참조)로 넘긴다. 분실·도난 신고서(보험 청구·보안 사고·감사)를 인쇄할 수 있다. 미처리 분실 자산은 대시보드 운영 대기 큐에 남는다.
31. **필독 공지 → 사용자 읽음 확인 → 커버리지 집계** — '필독'은 그동안 상단 고정이라는 표시뿐이고
    누가 읽었는지 추적이 없었다. 상단 고정(필독) 공지에 전 권한그룹이 자기 명의로 **읽음 확인**하면
    확인 이력(사용자·일시)이 감사 로그에 남고 **확인 N/전체 M명 커버리지**로 집계된다. 재확인은 멱등,
    자기 확인만 가능. QnA 등록과 함께 사용자의 쓰기 접점이다.
32. **계약 해지 → 만료 임박 집계·알림 제외** — 계약은 그동안 등록·갱신·만료뿐이라, 공급사 교체·서비스
    중단으로 조기 종료된 계약도 만료 임박 알림을 계속 울렸다. 해지하면 상태가 `해지`로 바뀌어 만료 임박
    집계(대시보드·발송 대상)에서 빠지고 갱신도 막히며, 주관부서·공급사 앞 해지 통보가 발송 이력에 남는다.
    23(계약 갱신 → 만료 임박 해소)의 짝으로 계약 생애주기(등록·갱신·해지)를 완결한다. 자산담당·Admin.
33. **재물조사 실측 → 대장 최근 실측일 기록 → 장기 미실측 식별** — 실사에서 라벨을 스캔하면(위치
    불일치여도 실물 확인이므로) 대장의 `최근 실측일`이 갱신되고 `점검` 이력이 남는다. 이로써 CMDB 대사의
    '미확인(일정 기간 실측 없음)' 판정이 정적 시드가 아니라 **실사 데이터에 근거**한다. 자산 대장은 최근 실측이
    없거나 오래된(180일 초과) 자산을 **장기 미실측(유령 자산 후보)**으로 걸러 보여 재물조사 재편성 대상이 드러난다.
    실측하면 그 자산은 목록에서 빠진다(폐쇄 루프).
34. **장기 미실측 → 수시 재물조사 자동 편성** — 33이 식별한 장기 미실측 자산을 재물조사 계획에서
    한 번에 **수시 조사 회차로 편성**한다. 대사 미확인 편성(8)이 발견 저장소를 원천으로 한다면 이 편성은
    **대장 실사 데이터(최근 실측일)**를 원천으로 한다. 개시 전·진행 중 회차에 이미 잡힌 자산은 중복 편성하지
    않으며, 편성된 회차를 개시해 실물을 스캔하면 33의 최근 실측일이 갱신돼 목록에서 빠진다 — 식별→편성→실측→해소가 닫힌다.
35. **대여(반출) → 대여중 → 반환 / 연체** — 불출(9)이 영구 배정이라면 대여는 **반환 기한부** 반출이다.
    유휴 재고를 대여자·부서·반환 기한과 함께 내주면 상태가 `대여중`으로 바뀌어 불출 대상에서 빠지고(영구 배정 방지),
    반환 접수 시 **상태 점검**으로 가른다 — 정상은 유휴 풀, **수리 필요는 수리중**(수리 후 유휴), 폐기 권고는 폐기예정
    (반납 점검 10·26과 동일 — 손상된 반환분이 검수 없이 바로 재대여되지 않게). 반납 없이 **반환 기한만 연장**할 수도 있다(현재 기한 이후로만). 반환 기한이
    지난 대여는 **연체**로 대시보드 운영 대기 큐(반환 독촉)와 대장 상세에 드러나고, **반환 임박(D-7 이내)**은 사전에 표시된다.
    대여자(사용자)는 셀프서비스로 **반환 기한 연장 요청**·**반납 신청**과 각 **취소**(자산담당 처리 전)를 하고, 두 요청은 자산담당 대시보드 대기 큐로도 드러나 통보만으로 놓치지 않는다. 자산담당·Admin.
36. **재물조사 완료 → 결과 요약 리포트 자동 생성·배포** — 실사 회차를 마감하면(차이 전건 조정 필수)
    `재물조사 결과 요약` 리포트가 **자동 생성**되어 담당자·IT기획팀에 배포된다(발송 이력 적재). 그동안 리포트는
    스케줄(17)·수동 생성뿐이라 실사 종료가 종결 표시로 끝났다 — 이제 완료가 결과 보고서(증적)를 남긴다.
37. **SaaS 차단 판정 → 차단 집행 요청** — SaaS 카탈로그에서 서비스를 `차단`으로 판정하면 Shadow SaaS
    미인가 집계 반영(6)에 더해 **보안운영팀에 프록시·DNS 차단 집행이 통보**된다(발송 이력 적재·감사). 그동안
    차단은 카탈로그 상태만 바꾸고 실제 차단 집행 요청이 없었다 — 외부 노출 차단(29)과 대칭으로 판정이 조치로 이어진다.
38. **공지 예약 발행 → 발행일 도래 시 전사 공개** — 공지를 미래 발행일과 함께 등록하면(예: 교육 사전 안내)
    관리자에게만 `예약`으로 보이고 발행일이 도래하면(기준일 ≥ 발행일) 전사에 공개된다. 별도 스케줄러 없이
    **조회 시점 필터**로 동작해, 발행일 이전에는 일반 사용자 목록에서 빠진다. 과거 발행일은 즉시 발행으로 처리. Admin.
39. **필독 확인 미달 → 미확인자 안내 발송** — 필독 공지 읽음 확인(31) 커버리지가 100% 미만이면 아직 확인하지
    않은 사용자에게 필독 확인 요청을 통보한다(발송 이력 적재·감사). 그동안 커버리지는 표시만 되고 독촉 수단이
    없었다 — 소유자 확인 미응답 에스컬레이션(12)과 같은 컴플라이언스 독촉으로 확인율을 끌어올린다. Admin.
40. **리포트 생성 → 결재 첨부 → 결재함 열람** — 생성한 리포트를 대기 중 결재의 **근거 문서로 첨부**하면
    결재함의 해당 건에 `📎 근거 리포트` 링크로 노출되어 결재자가 바로 연다(§05 "결재 첨부용 문서 산출"의 실제 연결 —
    그동안 리포트는 내려받기만 되고 결재에 붙지 않았다). 대기 결재만 대상, 중복 첨부는 무시, 첨부 해제 가능. 비사용자.
41. **대여 신청 → 결재 → 대여중 자동 집행** — 사용자가 대여할 **유휴 자산과 반환 기한**을 지정해 상신하면(불출(9)이
    영구 지급이라면 대여는 기한부 임시 반출) 자산담당 결재를 거친다. 요청에 자산·기한이 모두 담겨 있으므로 **승인 즉시
    그 자산이 신청자에게 반환 기한과 함께 자동 대여 처리(`대여중`)**된다 — 이후 반환/연체는 35가 잇는다. 승인 시점에 자산이
    빠졌으면(유휴 아님) 집행하지 않는다. 신청자는 확정 전 상신 취소 가능.
42. **대여 연체·임박 → 반환 독촉 발송** — 반환 기한이 지났거나(연체) 임박(D-7)한 대여 자산을 **드러내는 데서 끝내지 않고**,
    반납·유휴 화면 대여 현황에서 대여자에게 반환 요청 통지를 **한 번에 발송**한다(계약 만료 알림(13)·필독 미확인 안내(39)와
    같은 컴플라이언스 독촉의 대여판). 발송 이력이 알림 로그에 자산번호 참조와 함께 적재되고 감사 로그에 남는다. **당일 중복
    발송은 차단**한다(오늘 발송분 제외). 자산담당·Admin.
43. **ITSM SR·발주 → 도입 예정 사전 등록 → 도착 → 검수 대기열** — 그동안 입고는 물리 도착(입고 대기)에서만 시작됐다.
    ITSM·구매 연동(§06)의 **SR·발주 정보로 도착 전 자산을 사전 등록**(`도입 예정`)해 두고, 실제 도착 시 **입고 등록(도착)** 한 번으로
    입고 대기로 전환해 검수 대기열에 편입한다(이후 검수 → 채번 → 대장, 3과 연결). 도입 예정 단계는 아직 검수·채번 대상이 아니다. 자산담당·Admin.
44. **SaaS 인가 요청 → 보안담당 결재 → 카탈로그 반영** — 공지가 안내하는 "업무상 필요한 서비스는 인가 요청을 통해 사전 등재"를
    실제 경로로 구현한다. 전 권한그룹이 SaaS 서비스명을 적어 상신하면 **보안담당 결재선**으로 라우팅되고, 승인 시 기존 Shadow SaaS 는
    **인가로 전환**·미등재 서비스는 **인가 카탈로그에 사전 등재**된다(결과는 신청자에게 통보). 판정(보안담당 직접 인가/차단)과 짝을 이루는 요청 측 루프.
45. **인증 취약점 점검 → 크리덴셜 노출 대응** — 2단계 스캔에서 생존·서비스가 확인된 오픈 포트에 한해 기본·취약 크리덴셜을
    점검(SSH·DB·FTP·HTTP Basic·Redis·SMTP 등)해 서비스별 노출을 검출하고, 검출에서 끝내지 않고 **보안담당**이 서비스별 표준
    조치(계정 비활성화·비밀번호 재설정·외부 접근 차단 등)를 확정한다. 미조치→조치 완료로 바뀌고 보안운영팀 통지·감사 로그가
    남는다. 그동안 크리덴셜 점검은 설명 문구로만 있었다 — 다크웹 유출 대응(28)과 동형의 외부 위협 대응 루프. 오조치는 **재개**(대응 취소)로 미조치 복귀. 보안담당·Admin.
46. **휴면 계정 발견 → 비활성화 / 소유자 확인** — 탐지 채널 06(AD/IdP·SSO 로그)이 OAuth 앱과 함께 산출하는
    **휴면 계정**(일정 기간 로그인 없는 방치된 접근 경로 — 퇴직 미회수·미사용 서비스 계정·임시 관리자 잔존)을
    발견 자산 화면 계정 위생 섹션에 드러낸다. 그동안 커넥터·정책 문구로만 언급됐다. **보안담당**이 비활성화(보안운영팀
    집행 요청) 또는 소유자 확인(부서 사용 여부 조회)으로 조치하며, 요청 사실은 담당 채널 통지·감사 로그에 남는다.
    관리자·서비스 계정의 잔존 권한이 우선 대상 — 외부 노출 조치(29)와 동형의 계정 위생 루프. 보안담당·Admin.
47. **미인가 SW 검출 → 제거 요청 / 예외 승인** — 탐지 채널 04(EDR·백신 콘솔)의 설치 SW 인벤토리에서 금지 SW
    (P2P·크랙)·무단 원격제어·미승인 SW를 검출해 **설치 자산(대장)에 연결**하고, 발견 자산 화면 정책 위반 섹션에 드러낸다.
    그동안 컴플라이언스·이상탐지 문구로만 언급됐다(§03 "미인가 SW 설치는 Discovery 정책 위반 항목으로 보안담당 통보").
    **보안담당**이 제거 요청(설치 부서·보안운영팀 통지) 또는 예외 승인(업무상 정당·카탈로그 등재)으로 조치하며, 요청 사실은
    담당 채널 통지·감사 로그에 남는다. Shadow SaaS(6·37) 판정의 설치 SW 판 — 미인가 소프트웨어(SaaS·설치)를 함께 통제. 보안담당·Admin.
48. **USB 저장매체 정책 위반 검출 → 차단 / 예외 승인** — 탐지 채널 04(EDR·백신 콘솔)의 장치 제어 로그에서 이동식 매체
    사용(미등록 저장매체·대용량 반출 의심·암호화 미적용)을 검출해 **사용 자산(대장)에 연결**하고, 발견 자산 화면 USB 정책 위반
    섹션에 드러낸다. 그동안 EDR 채널 산출(USB)이 문구로만 있었다. **보안담당**이 차단(EDR 장치 제어) 또는 예외 승인(업무용 매체
    등록)으로 조치하며, 요청 사실은 담당 채널 통지·감사 로그에 남는다. 미인가 SW(47)와 함께 채널 04(EDR) 커버리지를 완결하는
    데이터 유출(DLP) 통제 루프. 보안담당·Admin.
49. **로컬 가상머신 정책 위반 검출 → 회수 / 예외 승인** — 탐지 채널 04(EDR·백신 콘솔)의 엔드포인트 내 로컬 VM
    (미인가 하이퍼바이저·EOL 미패치 게스트·미관리 VM)을 검출해 **실행 자산(대장)에 연결**하고, 발견 자산 화면 로컬 VM 섹션에
    드러낸다. 그동안 EDR 채널 산출(로컬 가상머신)이 문구로만 있었다. **보안담당**이 회수(하이퍼바이저 제거·VM 삭제) 또는
    예외 승인(업무용 VM 등록)으로 조치하며, 요청 사실은 담당 채널 통지·감사 로그에 남는다. 미인가 SW(47)·USB(48)와 함께
    **채널 04(EDR) 3종 산출을 완결**하는 관리 사각지대 통제 루프. 보안담당·Admin.
50. **위협 인텔 IOC 상관 → 차단 / 조사 착수** — 외부 위협 인텔 피드의 IOC(IP·도메인·파일 해시)를 조직 자산·관측(프록시·EDR 로그)과
    상관해 **위협 행위자를 귀속**하고, 외부 공격표면 화면 IOC 상관 섹션에 드러낸다. 신규 자산 발견이 아니라 **아는 자산의 악성 통신·감염
    징후**를 부각한다(§04 위협 인텔리전스). 그동안 위협 인텔은 유출 수집(다크웹) 카드로만 있었다. **보안담당**이 차단(프록시·방화벽·EDR)

65. **부속서류 미비 → 감사 리스크 표시 → 제출 요청 통보** — 진행 중 계약의 필수 부속서류(계약서·세금계산서 등) 누락은
    `📎 부속서류 미비 N건` 감사 리스크 배지로 집계되지만, 건별 등록(첨부)만 있고 책임 주체에게 제출을 요청하는 배치 조치 채널이
    없었다. 계약 카드에 **부속서류 제출 요청** 버튼을 두어, 미비 계약의 주관부서·공급사에 누락 서류 목록을 담아 제출을 요청하고
    감사·발송 이력을 남긴다(당일 중복 발송 차단). 만료 임박 알림·발주 이행 독촉과 같은 컴플라이언스 통보. 자산담당·Admin.
66. **AI 자동분류 제안 → 판정 → 발견 자산 표준 유형 확정(편입 승계)** — §05 그림4는 5대 AI 기능 전부를 판정→조치→환류
    루프에 넣는데, 자동분류(기능 01)만 제안 판정에 조치가 없어 승인해도 표준 유형이 대장에 반영되지 않았다(다른 4기능은
    격리·구매/회수 결재·리포트·폐기선정으로 이어짐). 미상 IoT 장비처럼 규칙 기본값(단말)으로 오분류될 소지가 있는 발견 자산에
    AI 표준 유형 제안을 **승인**하면 발견 자산에 확정 유형이 저장돼 **편입 시 대장 유형으로 승계**되고, 이미 매칭된 자산이면
    유형을 바로 보정(구성변경)한다. 반려는 오탐 사유가 재학습 신호로 남아 채택률·정확도에 반영된다. 자산담당·보안담당·Admin.
67. **발견 대사 불일치 → 대장 실측 보정** — CMDB 대사 화면은 `등록·불일치`(대장에 있으나 위치·소유자·구성 상이)의 처리로
    "대장 보정"을 약속하는데, 정합성 보정(`correctField`)은 **빈 필드 채움만** 허용하고(자리표시자 `-`·`미지정`·`실사 확인 필요`도 빈 값으로 본다) 기존 오값의 정정은 이동·불출(실물 이동)
    절차뿐이라 — 실물은 그대로인데 대장값만 틀린 **데이터 불일치**는 보정 경로가 없었다(대사 확인은 종결 표시만 남겼다).
    발견 레코드에 실측 필드·값(위치·소유자·부서)이 구조화돼 있으면 **대사 확인이 곧 대장 보정**이 되어, 실측값을 대장에 반영하고
    변경 전후를 자산 이력(점검)에 남긴 뒤 등록·일치로 종결한다(구성 상이처럼 필드가 특정되지 않는 불일치는 종전대로 검토·종결). 자산담당·Admin.
68. **발견 재관측(등록·일치) → 대장 생존 신호(최근 실측일 갱신)** — §04 그림3은 대사 결과 `등록·일치`의 처리를 "최종 확인 일시 갱신(생존 신호)"으로
    정의하는데, 실제로 대장 최근 실측일(`lastVerifiedAt`)은 **물리 재물조사 실사에서만** 갱신돼 — 네트워크·EDR 이 매일 살아있음을
    재관측해도 물리 방문이 밀린 원격·원격지 자산은 **장기 미실측(유령 자산 후보)**으로 오탐돼 재물조사 자동 편성(8·34)까지 흘렀다.
    등록·일치 재관측을 담당자가 **생존 확인**하면 대장 최근 실측일이 오늘로 갱신돼 장기 미실측·미확인 집계(33·8)에서 빠지고,
    갱신 전후가 자산 이력(점검)에 남는다. 4대 대사 결과 중 유일하게 조치가 없던 `등록·일치`를 닫는다. 자산담당·Admin.
69. **중복 기능 SaaS 통합 후보 → 통합 정리(표준 통합·차단)** — §05 라이선스 최적화(기능05)의 산출 '중복 기능 SaaS 통합 후보'는
    화면·리포트에 표시만 되고 조치가 없었다(AI 5대 기능 출력 중 유일한 display-only). 같은 기능 분류에 **인가 표준**이 있으면
    **통합 정리 요청**으로 그 분류의 미인가 중복 서비스를 표준으로 통합하고 나머지를 일괄 차단한다 — 개별 차단(로6·37)과 같은
    propagation(사용현황 동기화·보안운영팀 프록시·DNS 차단 집행 요청). 차단된 서비스는 통합 후보 집계에서 빠져(정리 완료),
    그동안 표시에만 머물던 통합 후보가 실제로 줄어든다. 표준이 없는 분류는 등재 안내만(먼저 표준을 인가). 보안담당·Admin.
70. **AI 이상탐지 승인 → 대장 관리 자산 격리(NAC 차단)** — §05 기능02 '이상 자산 행위 탐지'의 예시는 대부분 대장 관리 자산이다
    (미인가 SW 설치·휴면 자산 활동·**서버의 비정상 외부 통신**). 그런데 이상탐지 승인은 제목의 호스트명을 **발견 저장소에서만**
    찾아, 대장에만 있는 자산(발견 이력 없는 핵심 서버 등)의 이상행위는 승인해도 조치 없이 no-op 이었다(로11이 발견 자산만 격리).
    이상탐지 제안의 `refId`로 대장 자산을 지목해 **자산 키 격리 요청**을 상신하고, 보안담당→IT기획팀장 2단계 결재가 승인되면
    NAC 격리를 집행한다 — 자산은 상태를 유지한 채 네트워크만 격리되고(대장 `격리` 표시), 이력·보안운영팀 차단 통보가 남는다.
    발견 자산 격리(로2)의 대장 자산 대응. 보안담당·Admin.
71. **유지보수 SLA 위반 검출 → 공급사 SLA 이행 독촉** — §03 유지보수 계약의 세 하위기능(대상 자산·SLA·비용 이력) 중 대상 자산(로51)·
    비용 이력은 닫힌 루프인데 **SLA만 편집기(setContractSla)만 있고 준수 감시·조치가 없었다**. 유지보수 계약에 SLA 대응 목표
    일수(`slaResponseDays`)를 두고, 계약이 덮는 자산(`contractId`)의 **열린 수리(수리중)가 그 시한을 넘기면 SLA 위반**으로 판정 —
    유지보수 카드·대시보드 자산담당 큐에 위반 자산과 함께 노출하고, **SLA 위반 독촉** 버튼으로 주관부서·공급사에 SLA 이행(온사이트
    대응·수리 완료)을 촉구한다(당일 중복 발송 차단). 예산 통보(초과·소진)·미집행 독촉(로63)은 집행률 기준이라 SLA 준수와 무관했다. 자산담당·Admin.
72. **구매 계약 발주 정산 종결** — §03 구매 계약 검수 연계에서 '계약 관리 현황' 리포트는 **검수 완료액을 '대금 정산 근거'로** 약속하는데,
    그 근거를 확정해 발주 생애주기를 닫는 조치가 없어 **전량 입고·검수 완료된 계약도 이행 현황에 열린 채** 남았다(로27은 입고→검수,
    발주 이행 독촉은 미이행 독촉까지만). 발주가 전량 입고(발주 소진 완료)되고 활성 로트가 전부 검수 완료된 구매 계약을 **정산 종결**하면
    `settledAt`으로 대금 정산 근거(검수 완료액)를 확정하고 주관부서·재무에 통지한다 — 종결분은 발주 이행·미이행 위험 집계에서 빠져(생애주기
    종착) 이행 현황이 실제로 닫힌다. 발주 미소진·검수 미완 계약은 종결 대상이 아니다. 자산담당·Admin.
73. **복합 위험 자산 트리아지 → 우선 조치** — 개별 위험 신호(정합성 미흡·EOL OS·보증 임박·정기 점검 도래·단일 장애점(SPOF)·교체
    대상·장기 미실측)를 자산별로 합산해 **2개 이상 겹치는 자산**을 다중 이슈 우선 조치 대상으로 드러낸다. 판정은 `lib/risk`의
    `riskSignals` 단일 소스(각 신호는 대장 필터·분석 패널과 같은 lib 빌더 재사용 — 임계값 재계산 없음)이며 **5개 노출면이 공유**한다 —
    대장 상세 '위험 신호' 요약(자산별) · 대장 `?risk=1` 필터(집합) · 대시보드 '복합 위험 자산' 큐(사전 노출→드릴다운) · 어시스턴트
    '복합 위험' 질의(대화형) · **복합 위험 자산 리포트**(결재·감사 첨부용 xlsx — 신호 조합·신호별 빈도·부서별 분포). 신호가 몰린 자산은
    단일 조치(예: 교체 시 EOL·보증·정기 점검 동시 해소)로 여러 위험을 함께 해소해 우선순위가 높다. 보유상태(분실·연체)를 보는 `자산 운영
    리스크`와 달리 **기술·수명주기 신호의 중첩**을 본다. 자산담당·Admin.
74. **필수 결재 지정 → 직접 실행 차단** — 사용자·결재선(STEP 4)에서 결재선을 `필수`로 지정하면 그 종류의
    **직접 실행 경로가 막힌다** — 대여(직접 대여)·이동(재배정=직접 인계)·SaaS 인가(직접 인가 판정)가 서버에서
    사유와 함께 거부되고, 화면은 컨트롤 대신 '신청 · 결재로 상신하세요' 안내를 보여준다(상세·일괄 바 모두).
    승인 경로는 그대로 동작한다 — 상신 → 결재 승인 → 자동 집행(대여는 유휴 자산을 신청자에게 대여). 그전에는
    필수/선택 토글이 배지·지표·컴플라이언스 리포트에 표시만 되고 아무것도 막지 않았다.

75. **상위 자산 이탈 → 하위 의존 담당 부서 통지** — CMDB 의존 그래프는 상세 위험 표기·토폴로지·AI 답변에서
    "변경·정비 시 사전 통지 대상"이라고 말하면서도 실제로 통지를 보내는 경로가 없었다. 회수·분실·수리·폐기 절차로
    상위 자산이 운영에서 빠져도 그 자산에 물린 하위 자산의 담당 부서는 자기 자산 상세를 열어 보기 전에는 알 수 없었다.
    대장 상단 **의존 영향 통지 (N)** 버튼이 저하·이탈 상위 자산의 하위 담당 부서에 영향 자산을 열거해 발송하고
    (부서 단위 한 통·상위 자산 이력·감사 로그 적재), 같은 상위·같은 부서 당일 중복 발송은 차단한다.
    버튼 건수는 아직 통지하지 않은 부서가 남은 상위 자산 수(`lib/reminders`)라 발송 뒤 버튼이 사라진다 —
    수령 확인·정기 점검 독촉·EOL 통보와 같은 통지 규약. 대시보드 운영 대기에도 **하위 의존 영향 통지 대상**
    큐로 올라오고, 그 큐는 대장 필터(`?impact=1`)로 같은 집합을 열어 준다(큐 건수 = 드릴다운 목록). 자산담당·Admin.

라벨(QR·Code128)로 발행한 코드는 재물조사 스캔 실사에서 그대로 인식되어 3↔4가 연결된다.

## 권한 모델

**화면 단위**는 코드(`lib/authz.ts`)가, **기능 단위**는 스토어의 권한 매트릭스가 통제한다.
매트릭스는 환경설정 › 권한·정책에서 칸을 클릭해 편집하며, 서버가 즉시 강제한다.

- 서버가 직접 강제하는 칸(화면에 밑줄): 자산 대장·재고·계약·발견 자산·결재의 **엑셀**,
  발견 자산의 **편입 / 격리요청**, 신청·결재의 **결재**
- 매트릭스는 **필요조건**이다 — 권한을 켜도 코드 규칙(결재 종류별 담당자, 본인 자산 범위)을
  넘지 못한다. 편집으로 권한이 상승하는 경로를 만들지 않기 위한 제약
- Admin 의 `권한 · 정책 × 조회/저장`은 잠겨 있어 스스로를 화면 밖으로 밀어낼 수 없다
- 모든 변경은 감사 로그에 남는다

## 엑셀 내보내기

권한 매트릭스의 **엑셀** 기능이 있는 화면에서 `.xlsx`로 내려받는다 (`/api/export/<kind>`).

| 대상 | 시트 | 허용 권한그룹 |
|---|---|---|
| `assets` 자산 대장 | 자산 대장 (18열) | 자산담당 · 보안담당 · Admin |
| `stock` 재고 현황 | 유형별 · 부서별 · 위치별 | 자산담당 · Admin |
| `discovered` 발견 자산 | 발견 자산 · 채널별 관측 | 자산담당 · 보안담당 · Admin |
| `contracts` 계약·라이선스 | 계약 · SW 라이선스 | 자산담당 · 보안담당 · Admin |
| `approvals` 결재 이력 | 결재 이력 | 자산담당 · 보안담당 · Admin |

버튼 숨김은 UI 정리일 뿐이며, **서버 라우트가 같은 규칙으로 403을 반환**한다.
내보내기 데이터는 화면과 동일한 권한 필터를 통과하고, 반출 사실은 감사 로그에 남는다.
`.xlsx` 는 의존성 없이 `lib/xlsx.ts`가 직접 생성한다(ZIP 저장 + OOXML 4파트) — CSV 로 열 때
생기는 선행 0 손실·MAC 주소의 날짜 변환·지수 표기를 피하기 위해 식별자는 문자열 셀로 넣는다.

## 데모 시나리오

1. **자산담당(박자산)** — Discovery › 발견 자산에서 미등록 자산 **편입 요청** →
   워크플로에서 **승인** → 자산 대장에 신규 자산 편입 확인
2. **자산담당** — 도입·검수에서 체크리스트 완료 → **채번** → 라벨 발행(인쇄) →
   재물조사 수행에서 그 자산번호를 스캔해 **일치** 확인
3. **자산담당** — 재물조사에서 다른 위치로 스캔 → 차이 발생 → **조정 결재 상신** →
   **Admin** 승인 → 자산 대장 위치가 실사값으로 보정됨
4. **Admin** — 환경설정 › SaaS 카탈로그에서 Notion **인가** → Discovery › Shadow SaaS에서
   미인가 집계가 줄어드는 것 확인
5. **사용자(김민준)** — QnA 질문 등록(답변창 없음) → **자산담당**이 답변 → 사용자 화면에서 답변 확인
6. **자산담당** — 재물조사 계획에서 범위·담당자·기한을 지정해 회차 등록(대상 모수는 대장에서 자동 산출) →
   **조사 개시** → 실사 화면으로 이동. Discovery › CMDB 대사의 **미확인**행에서 **조사 편성**으로도 진입 가능

## 배포

```powershell
docker build -t itam-web .
docker run -d --name itam-web --restart unless-stopped -p 127.0.0.1:3390:3390 \
  -v itam-data:/data --env-file ~/.itam.env itam-web:latest
```

로컬호스트 바인딩이므로 접속은 SSH 터널을 사용한다 (`ssh -L 3390:localhost:3390 <host>`).
`--env-file`은 컨테이너 재생성 시에만 다시 읽히므로, 키를 바꾸면 `docker restart`가 아니라
`docker rm -f` 후 `docker run`으로 재기동해야 한다.

**데이터 영속화** — Dockerfile 이 `ITAM_DATA_FILE=/data/store.json` 을 설정하므로 스토어가
파일로 저장된다. `-v itam-data:/data` 명명 볼륨을 마운트하면 **재시작·재생성 후에도 상태가 유지**된다
(볼륨 없이 실행하면 컨테이너 쓰기 레이어에 저장돼 재생성 시 초기화된다). 저장은 2초 주기 dirty-비교 +
종료 시 flush, 원자적 쓰기(임시 파일 → rename). 스키마가 바뀌면 낡은 파일을 버리고 시드로 시작한다.
로컬 개발·스모크는 `ITAM_DATA_FILE` 미설정이라 종전대로 인메모리(매 기동 시 시드)로 동작해 결정성이 유지된다.
