## ISSUE-2026-001: DLP DB(MySQL) 로그 수집 미동작

### 증상

- DLP 솔루션 DB(MySQL) 연동 설정 후 수집 데이터 미유입
- 네트워크 통신 정상, `ss-database-checker` 서비스 정상 기동 상태
- 서비스 로그에 JDBC 관련 로그가 **전혀 출력되지 않음** (에러조차 없음)

### 타임라인

| 일자 | 내용 |
|------|------|
| 2026-07-19 | 이슈 접수. 패치 패키지 검증(정상 확인) 및 원인 분석 완료, 현장 점검 가이드 전달 |
| 2026-07-28 | 근본 원인 수정 개발/검증 완료 (내부 이슈 SSS-154) |
| 2026-08-02 | v3.4.4 패치 릴리스 및 배포 서버 업로드 |

### 원인 분석

1. **신규 로그 소스가 기본 비활성(`is_disabled=true`)으로 생성**되고, 콘솔에 활성화 토글 UI가 없어 등록 후 활성화할 방법이 없었음 (전 사이트 공통의 제품 결함)
2. 수집 모듈은 활성 DB 수집기가 0건이면 **로그 없이 조용히 종료** → "서비스는 정상인데 로그가 없다"는 증상으로 나타남
3. (검증 중 발견된 잠재 결함) 수집 중 예외 발생 시 수집 스레드가 죽으면서 내부 플래그가 복구되지 않아 **재시작 전까지 전체 DB 수집이 무증상 중단**될 수 있는 구조였음

### 현장 임시 조치 (v3.4.4 적용 전)

```sql
-- SIEM DB에서 DLP 수집기 활성화 (서비스 재시작 불필요, 10초 주기 자동 반영)
UPDATE log_sources SET is_disabled = false
WHERE log_type = 'db' AND name = '<DLP 수집기명>';
```

활성화 후 확인:

```bash
grep 'LogSource수집' /opt/seekurity-siem/logs/ss-database-checker/ss-database-checker.log | tail
# "수집 완료 N건" → 정상 / "수집 실패 + 에러" → 접속정보·권한·방화벽 확인
```

### 근본 조치 (v3.4.4)

| 항목 | 내용 |
|------|------|
| 콘솔 | 로그 소스 페이지에 수집 활성/비활성 토글 및 목록 활성화 컬럼 추가 |
| API | 신규 로그 소스 생성 시 기본 활성화로 변경 |
| 수집 모듈 | 활성 수집기 0건 시 10분 주기 진단 로그 출력 |
| 수집 모듈 | 수집 스레드 예외 시 플래그 복구 보장, 소스 단위 예외 격리, JDBC 접속 타임아웃 10초 |

### 패치 적용 안내

- 패치 파일: `seekurity-siem-patch-v3.4.4-20260802.tar.gz` (약 821MB)
- 다운로드: `https://siem.seekerslab.com/downloads/` (계정은 별도 전달)
- 적용: 압축 해제 후 `sudo ./patch.sh` (기존 데이터/설정 유지)
- **주의**: 기존에 등록된 비활성 수집기는 패치가 자동 활성화하지 않음 — 콘솔 토글 또는 위 SQL로 수동 활성화 필요

### 재발 방지 / 교훈

- DB 수집기 등록 후에는 반드시 **활성화 상태**와 수집 로그 유입을 함께 확인
- 표준 점검 절차는 `_template/CUSTOMER_NAME_08-운영이슈대응.md` 부록 A(DB 수집 연동 점검 체크리스트)로 패턴화함 — 타 고객사 동일 증상 시 재사용
