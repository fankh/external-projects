# 고객 제출 문서 작성 규칙 (Document Style Guide)

고객사에 납품 또는 공유되는 모든 산출물(projects/ 이하 번호 문서, 보고서, 매뉴얼)에 적용하는 작성 규칙.
내부 전용 문서(README, CLAUDE.md, docs/ 이하 엔지니어링 노트)에는 적용하지 않음.

## 1. 파일명 규칙

| 규칙 | 예시 |
|------|------|
| `{고객사}_{NN}-{문서명}.md` 형식, 번호는 2자리 | `KOVAN_08-운영이슈대응보고서.md` |
| 문서명은 산출물 성격을 나타내는 접미사로 종결 | 정의서, 설계서, 확인서, 매뉴얼, 보고서 |
| 템플릿은 `CUSTOMER_NAME_` 접두사 사용 | `CUSTOMER_NAME_08-운영이슈대응보고서.md` |
| 공백, 특수문자, 영문 약어 남용 금지 | (좋음) 운영이슈대응보고서 (나쁨) 운영이슈대응_v2_final |

## 2. 문체

- 개조식 문어체로 작성하고 문서 전체에서 통일함 (예: "~함", "~됨", "~필요")
- 본문 서술에 구어체, 감탄문, 의문문을 사용하지 않음
- 항목 나열은 번호(1. 2. 3.) 또는 붙임표(-)를 사용하고 계층은 2단계 이내로 제한함

## 3. 금지 요소 (기계 생성 문서로 보이는 표현)

| 금지 | 대체 |
|------|------|
| 이모지, 원문자(①②③), 화살표(→, ⇒), 체크마크 | 번호 목록, "다음 단계로", 표 |
| 본문 중간의 굵은 글씨 남용, 느낌표 | 필요한 경우 표의 유의 사항 행으로 기재 |
| 괄호 속 사족, 메타 주석("이 섹션을 복사하세요") | 템플릿에서는 HTML 주석(`<!-- -->`)으로 기재 |
| "완벽한", "강력한", "간단히" 등 수식어 | 사실과 수치만 기재 |
| 줄표(—) 구문 연결 | 쉼표 또는 문장 분리 |

## 4. 비노출 정보 (고객 문서에 기재 금지)

| 구분 | 예시 | 대체 표기 |
|------|------|-----------|
| 내부 이슈 번호 | Jira SSS-154 | "수정 사항 개발 및 검증 완료" |
| 내부 저장소, 커밋 해시 | GitHub, GitLab 경로 | 기재하지 않음 |
| 내부 서버 주소 | 172.x.x.x, dev/test 서버 | 기재하지 않음 |
| 실계정, 비밀번호 | 다운로드 계정 등 | "(접속 계정은 별도 전달)" |
| 제품 결함의 내부 명칭 | 클래스명, 변수명 수준의 상세 | 동작 관점으로 서술 |

## 5. 문서 구성 표준

- 문서 최상단: 제목 다음에 문서 정보 표(고객사, 문서 구분, 수행사, 보안등급, 최종 갱신일)
- 절 번호 체계: `1.` `1.1` 형식, 부록은 `부록 A.` `A.1` 형식
- 표를 우선 사용하고, 표로 표현이 어려운 경우에만 목록 사용
- 명령어와 쿼리는 코드 블록으로 구분하고, 자리 표시 값은 `(설명)` 형식으로 기재
- 날짜는 `YYYY. MM. DD.` 형식으로 통일

## 6. 템플릿 작성 규칙 (projects/_template/)

- 치환 대상은 `{CUSTOMER_NAME}` 형식의 플레이스홀더 사용 (`scripts/project.py init` 치환 대상)
- 작성자를 위한 지침은 문서 최상단 HTML 주석 블록에만 기재하고, 납품 시 제거됨을 주석에 명시
- 본문 예시 값은 실제 고객 데이터가 아닌 일반화된 값으로 기재

## 7. 납품 전 점검 목록

1. 금지 요소(3항) 및 비노출 정보(4항) 포함 여부 검색 확인
2. 템플릿 잔여 플레이스홀더(`{`, `CUSTOMER_NAME`) 검색 확인
3. HTML 주석 블록 제거 확인
4. 문서 정보 표의 최종 갱신일 갱신
5. PDF 변환 후 표와 코드 블록 레이아웃 확인
