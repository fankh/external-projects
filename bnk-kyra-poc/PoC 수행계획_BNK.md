|------|------|
| 고객 | BNK금융그룹 (정보보호 부문) |

## 1. 목표와 성공 기준

PoC의 목표는 "임직원이 외부 LLM을 업무에 활용하되 민감정보는 나가지 않는다"를 BNK 환경에서 수치로 입증하는 것이다. 인라인 경쟁 제품 대비 차별점(문맥 기반 판단, 낮은 오탐, 마스킹 후 전달, 망 구성 무영향)이 평가 항목에 그대로 반영되도록 기준을 설계한다.

| # | 평가 항목 | 목표치 | 측정 방법 |
|---|-----------|--------|-----------|
| 1 | 프롬프트 인젝션 차단율 | > 99.5% | 공격 시나리오 세트(200건 이상) 주입 후 차단 로그 대조 |
| 2 | DLP 탐지 정확도 (오탐율) | 오탐 < 0.1% | 금융 민감정보 세트 + 정상 업무 프롬프트 세트 병행 측정 |
| 3 | 응답 지연 (가드레일 오버헤드) | 검사 구간 < 200ms | 부하 도구로 p50/p95 측정, LLM 자체 지연과 분리 산출 |
| 4 | 감사로그 완전성 | 100% | 전송 요청 전수와 감사로그 건수 대조, SIEM 수신 확인 |
| 5 | 사용자 편의성 | 설문 4.0/5.0 이상 | 평가단 설문 + 우회 시도(개인 기기 등) 발생 건수 |

## 2. 일정 (착수일 D0 기준 4주)

| 주차 | 단계 | 주요 활동 | 완료 기준 |
|------|------|-----------|-----------|
| W0 (착수 전) | 사전 준비 | 방화벽 정책 오픈, 랙 2U·전원·내부 IP, LLM API 계정, 평가단·시나리오 확정 | 사전 준비 체크리스트 전 항목 완료 |
| W1 | 설치·연동 | 장비 반입·기동(1~2일), 내부망 HTTPS 접속 확인, 외부 LLM White-list 아웃바운드 개통, AD/SSO·SIEM 연동(옵션) | 파일럿 사용자 10명 챗봇 사용 가능 |
| W2 | 정책 튜닝 | 금융 PII 탐지 규칙(주민·계좌·카드·전화·이메일) 적용, 부서별 RBAC/ABAC 정책, 오탐 기준 협의·조정 | 시나리오 사전 리허설 통과 |
| W3 | 확대 평가 | 200~300명 확대 오픈, 공격·DLP·성능 시나리오 본 측정, 사용 현황 대시보드 공유 | KPI 1~4 측정치 확보 |
| W4 | 측정·보고 | 잔여 측정 보완, 사용자 설문, 결과 보고서 작성·발표, 장비 회수·데이터 완전 삭제 확인서 제출 | 결과 보고회 완료 |

주간 단위로 BNK 담당자와 정기 점검 회의를 갖고, 주차별 완료 기준 미달 시 당주 내 만회 계획을 공유한다.

## 3. 내부 준비 트랙 — 제품 보강 (착수 전 완료)

현재 구현(관리 콘솔, 채팅·문서, 인증·2FA·OAuth, 역할·정책, 감사로그 서비스, Postgres·Redis·Nginx 컨테이너 배포, e2e 테스트)을 기준으로, PoC 평가 항목을 통과하는 데 필요한 보강 범위를 우선순위로 관리한다.

| 우선순위 | 항목 | 내용 | 평가 항목 연계 |
|----------|------|------|----------------|
| P0 | LLM 게이트웨이 실연동 | mock 제거, OpenAI·Azure OpenAI·Anthropic 커넥터, 목적지 White-list·타임아웃·재시도 | 전 항목의 전제 |
| P0 | DLP 엔진 (금융 규칙) | 주민등록번호·계좌번호·카드번호·전화·이메일 정규식 + 검증(체크섬), 마스킹 후 전달, 컨텍스트 허용 목록 | KPI 2 |
| P0 | 프롬프트 인젝션 방어 L1 | Jailbreak·시스템 프롬프트 탈취·역할 전환 패턴 룰셋, 위험 스코어·차단 사유 기록 | KPI 1 |
| P0 | 프롬프트 단위 감사로그 | 요청·응답·판정(허용/마스킹/차단)·사유를 건 단위 기록, 해시 체인, Syslog 전송(SIEM) | KPI 4 |
| P1 | 성능 계측 | 검사 구간 타이밍 분리 로깅, k6 부하 스크립트(동시 50~100 세션), 대시보드 지연 패널 | KPI 3 |
| P1 | 폐쇄망 패키징 | 이미지 오프라인 번들, 설치·기동 스크립트, 사내 리허설(외부 네트워크 차단 상태 설치) | W1 일정 |
| P1 | 인젝션 방어 L2 | 분류 모델 기반 2차 판정 (L1 통과분 대상) — PoC 범위 협의에 따라 조정 | KPI 1 |
| P2 | SSO(SAML·OIDC) 연동 | BNK AD 연동 — 옵션, W1에 계정 정보 수령 시 진행 | 편의성 |
| P2 | 관리 대시보드 보강 | 차단·마스킹 건수, 부서별 사용량, 오탐 처리 현황 위젯 | 보고 |

P0 4건은 착수 2주 전까지 완료하고, 폐쇄망 설치 리허설로 검증한다.

## 4. 평가 시나리오

| 세트 | 구성 | 건수(안) |
|------|------|----------|
| 인젝션 공격 | Jailbreak, 시스템 프롬프트 탈취, 역할 전환, 인코딩 우회, 다국어 우회 | 200+ |
| 민감정보 유출 | 주민번호·계좌·카드·고객명부 포함 프롬프트 (원문·변형·표 붙여넣기) | 100+ |
| 정상 업무 (오탐 측정) | 여신 심사 요약, 상품 약관 질의, 코드 리뷰, 번역 등 실업무 프롬프트 | 300+ |
| 성능 부하 | 동시 50·100 세션, 장문 프롬프트·스트리밍 응답 혼합 | 30분 × 3회 |
| 감사·권한 | 전수 로그 대조, 부서별 정책 차등(재무팀 허용·타 부서 차단), 관리자 권한 분리 | 전수 |

시나리오 상세와 판정 기준은 W0에 BNK와 합의해 고정하고, 측정 중 변경하지 않는다.

## 5. 역할 분담

| 구분 | 씨커스 | BNK |
|------|--------|-----|
| 환경 | 장비 반입·설치·기동, 정책 튜닝, 성능 측정 | 랙 2U·전원·내부 IP, 방화벽 정책 오픈 |
