01 · Network Architecture
망분리 네트워크 구성 — 내부 업무망 · 인터넷망 분리
구성 원칙 — 외부 LLM으로 향하는 유일한 경로는 KYRA를 경유하는 아웃바운드 HTTPS(443) 단방향 세션이며, 목적지는 White-list로 제한됩니다. 대화 원문·감사로그는 전량 내부망에 보관되고, 트래픽 경로 변경이나 SSL 복호화 구간 추가 없이 도입됩니다.

통제 지점네트워크 구간에서 패킷을 가로채어 분석애플리케이션 계층 — 전용 챗봇 화면 · API
SSL 복호화필수 — 전 단말 인증서 배포, 성능 저하불필요 — 복호화 구간 없음
대화 문맥 인식불가 — 패턴 · 키워드 매칭 수준프롬프트 문맥 분석 (Pattern + ML + Behavioral)
AI API 정책도메인 허용/차단 수준의 제한적 정책 — 전면 차단 또는 전면 허용의 양자택일사용자 · 부서 · 문서등급별 프롬프트 단위 정책 (RBAC/ABAC)
민감정보 처리탐지 시 세션 차단 위주 — 업무 중단마스킹 후 전달 — 업무 연속성 유지
오탐 영향오탐 시 업무 차단 · 우회 접속 유발오탐율 < 0.1% (문맥 기반 판단)
장애 영향인라인 장비 장애 시 인터넷 구간 전체 영향기존 망과 독립 — 장애 시 기존 망 영향 없음
감사로그패킷 · URL 수준 기록프롬프트 · 응답 단위 100% 감사 (SHA-256 체인)
망 구성 영향트래픽 경로 변경 · 인라인 구간 삽입 필요아웃바운드 HTTPS 정책 1건 추가로 완료
AI API 통제의 구조적 차이 — LLM API 트래픽은 암호화된 JSON·SSE 스트리밍 형태여서, 패킷 기반 인라인 장비는 내용을 문맥 단위로 해석하지 못하고 도메인 수준의 허용/차단 정책에 머무르게 됩니다. KYRA는 애플리케이션 계층에서 프롬프트 자체를 이해하고 통제하므로, 차단이 아닌 마스킹 후 활용이 가능하며 임직원의 생성형 AI 업무 활용과 정보 보호를 동시에 달성합니다.
